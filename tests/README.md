## 1. Demo v0 最终必须证明的范围

- `/welcome` 六阶段真实操作、持久化和多设备恢复；
- `/admin` 共用账号、会话自提权、运行状态机、公共内容事后处置与确定性重置；
- `/screen` 匿名聚合、规则通过弹幕、实时更新、断线快照和减少动态效果；
- 服务端事务、幂等、唯一业务键、负余额保护、会话失效与 `resetEpoch` 隔离；
- 300 个固定合成参与者的协议级负载，目标事件传播延迟 p95 不超过 2 秒；
- vivo X300 默认浏览器、Windows Chrome、Windows Edge、1920×1080 和 `prefers-reduced-motion`。

实体 NFC、印刷、iPhone、微信、公网 HTTPS、真实场馆和主备硬件属于正式版延期测试，不是 Demo v0 的通过条件。

## 2. 目录结构

测试按证据类型组织，而不按人员组织：

```text
tests/
├─ unit/          # 数值、内容规则、状态机、聚合和错误映射
├─ integration/   # SQLite、迁移、事务、幂等、会话与重置
├─ api/           # HTTP 命令和 WebSocket 事件契约
├─ helpers/       # G1/G2 合成数据库与服务测试工具
├─ e2e/           # G3 三端真实浏览器关键闭环与恢复
│  └─ fixtures/   # G3 隔离临时数据库与真实服务编排
├─ load/          # G4 300 人真实 HTTP/WebSocket 协议负载、指标与固定测试夹具
└─ reports/       # 本地生成且默认忽略的机器可读结果
```

如果最终测试工具有不同约定，可以调整目录，但必须保留上述责任边界和可重复执行能力。

## 3. 自动化最低覆盖

### 单元测试

- 初始动力值 100；礼物扣减 5/10/20/50；余额永不为负；
- 星光值奖励 20/20/20/10/10/20，上限 100，同一业务键只奖励一次；
- 敏感词、链接、联系方式、长度、频率和来源屏蔽规则；
- `REHEARSAL` 可跳转、`LIVE` 只能前进的状态机；
- D-022 旧时光胶囊留言不进入公共 DTO、快照、事件或日志；
- 最终匿名聚合可从持久化事实重算。

### 集成与契约测试

- 激活、赠礼、弹幕、点亮和奖励在同一事务域内保持一致；
- 相同 `Idempotency-Key` 与相同请求体返回原结果；不同请求体返回 `IDEMPOTENCY_CONFLICT`；
- 过期 `stageRevision` 与 `resetEpoch` 被明确拒绝；
- 只在事务提交后广播事件；重连先取快照，再接收新序号；
- 刷新和服务重启后状态保持；旧会话在重置后失效；
- D-022 确定性重置恢复同一批合成身份、令牌、六位 Demo 码、节目和礼物。
- G5 已用单元、集成和浏览器用例覆盖合成学号摘要、公开星号、星色锁定、胶囊候选的人工选择/上屏/撤下、公共投影隔离与确定性重置；vivo X300 的本轮触控和软键盘体验仍须人工复验。
- G5-06 浏览器用例另覆盖 375×667、390×420 键盘剩余高度、667×375 横屏、125% 字号、44px 触控区域，以及礼物面板的焦点循环、Escape 关闭和焦点归还；这些证据不能替代 vivo X300 默认浏览器真机验收。

### G3 浏览器端到端测试

- `entry-device.spec.ts`：入口令牌清理、移动视口、键盘焦点、触控尺寸、刷新与双设备恢复；
- `participant-journey.spec.ts`：通用核验错误与私密写入丢响应安全重试，以及双参与者隔离、阶段锁、四档礼物、奖励和最终聚合；
- `admin-controls.spec.ts`：未登录边界、角色、自提权、过期版本、现场模式前进约束、确认与最近操作；
- `three-surfaces.spec.ts`：六阶段三端联动、隐私、弹幕拒绝/下屏/暂停/恢复/清屏/来源屏蔽、1920×1080 与减少动态效果；
- `recovery.spec.ts`：离线禁写、重连、服务重启、未知结果原键重试、重置、新 epoch 和旧会话失效；
- `session-races.spec.ts`：参与者退出后的晚到快照、后台快速重登与外部重置后的私密 DOM 清理。

上述 6 个文件包含 9 个场景，每个场景在三个浏览器项目执行一次，共 27 条。`recovery.spec.ts` 与 `three-surfaces.spec.ts` 记录静态失败检查点；最终浏览器报告的失败检查点为 0。

## 4. G4 负载脚本与报告

G4 负载脚本使用 300 个固定合成参与者，并记录：

- 版本、种子版本、开始时间和运行时长；
- 激活、阶段、赠礼、弹幕、协同点亮各自的样本数、成功率、p50、p95 和最大值；
- WebSocket 连接数、断线数和快照恢复数；
- 重复账本项、重复奖励、重复扣减、负余额和旧 epoch 污染数量；
- 不含姓名、完整令牌、六位 Demo 码、Cookie、时光胶囊或完整弹幕正文的失败摘要。

目标事件传播延迟的最终计时口径：从客户端命令开始，到大屏合并权威快照以及适用的参与者私有快照或已提交运行事件被观察为止；重放样本不计入。通过标准为 p95 ≤ 2 秒，且账本不变量错误为 0。

从仓库根目录运行独立 G4 专项，或在收口时运行包含 G3 全门的命令：

```bash
pnpm test:load
pnpm verify:g4
```

- 弹幕测试证据优先记录内部内容 ID、规则结果和状态，不保留完整正文。
- 测试生成物放在被忽略的本地目录；需要提交的基线只保留经过最小化的固定合成样例。
