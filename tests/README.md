# 测试目录说明

本目录用于管理迎新晚会互动系统的测试约定、测试用例和非敏感证据索引。当前项目处于初期阶段，本轮仅建立测试说明；端到端验收以 `docs/TEST_PLAN.md` 和 `docs/RUNBOOK.md` 中的人工测试、真实设备测试与场馆彩排为准。

## 1. 当前测试范围

- `/welcome`：手机端身份激活、寄语、星星、节目、应援、弹幕、互动与个人档案；
- `/screen`：舞台大屏集结、节目状态、热度、弹幕、星光、寄语和主备切换；
- `/admin`：权限、节目控制、审核、补发、监控、暂停、降级和恢复；
- NFC 与二维码指向同一 URL；
- 真实 iPhone、安卓和双端微信内置浏览器；
- 网站、网络和大屏三级降级；
- 上线前全流程彩排。

## 2. 本地启动基线

前端位于 `frontend/`。在仓库根目录进入该目录后，使用锁文件对应的 pnpm：

```powershell
Set-Location .\frontend
pnpm install --frozen-lockfile
pnpm run dev --host 0.0.0.0
```

构建检查：

```powershell
Set-Location .\frontend
pnpm run build
```

说明：当前是否已有三个完整路由和自动化测试，以实际代码及 `package.json` 为准。若路由或测试脚本尚未实现，应在测试记录中明确标为“未实现/阻断”，不得用静态页面能打开代替功能通过。

## 3. 测试地址

使用占位地址，禁止把生产密钥或私有参数写入文档：

```text
<BASE_URL>/welcome
<BASE_URL>/screen
<BASE_URL>/admin
```

- NFC、二维码和印刷短链接只允许进入同一个 `<BASE_URL>/welcome`；
- `/screen` 和 `/admin` 不印到公开物料；
- 如使用环境变量，真实值放在未提交的本地环境文件或受控密钥系统中；
- 测试输出不得打印令牌、Cookie、数据库连接串或管理员口令。

## 4. 测试数据规则

允许使用：

```text
姓名：测试新生001
测试编号：test-student-001
寄语：保持好奇，完成一次合成测试。
弹幕：测试弹幕-允许展示
```

禁止使用：

- 真实新生名单、姓名、学号、手机号或身份证信息；
- 真实管理员账号或长期有效凭据；
- 从生产环境复制的数据库、日志、截图或浏览器存储；
- 在 URL 中携带个人信息或可复用密钥；
- 为测试方便而关闭生产环境鉴权、审核或服务端积分校验。

需测试名单匹配时，应生成独立合成名单。需测试删除、补发或批量操作时，只能在隔离环境对合成数据执行。

## 5. 推荐目录结构

后续增加自动化测试时，建议按职责组织：

```text
tests/
  README.md
  unit/              # 纯函数、规则、校验和状态机
  integration/       # API、数据库、消息推送和幂等
  e2e/               # welcome、screen、admin 三端联动
  fixtures/          # 只含合成数据
  manual/            # NFC、真实设备、场馆和彩排清单
```

新增目录和工具前应先确认项目技术选型；本初版不假设已经安装某个测试框架。

## 6. 自动化优先级

### P0

- 三个路由的基础可达性和权限边界；
- 名单匹配成功、失败及重复提交；
- 动力值和星光值的服务端校验、上限及幂等；
- `/admin` 节目切换同步到 `/welcome` 和 `/screen`；
- 弹幕审核后才可上屏；
- 断线重连后状态一致；
- 降级开关和恢复不会重复处理请求。

### P1

- 不同节目和互动类型的数据驱动测试；
- 寄语长度、敏感词和审核状态；
- 大屏布局快照或关键组件视觉回归；
- 弱网、超时、限流和重试；
- 活动结束后的只读回顾和数据清理流程。

NFC 标签写入、二维码印刷质量、真实手机感应和舞台主备切换不能只依赖自动化，必须按人工清单实测。

## 7. 人工用例执行格式

每条用例至少记录：

```text
用例编号：
日期时间：
环境：本地 / 集成 / 场馆彩排
测试端：welcome / screen / admin / NFC / 二维码
设备与版本：
网络：有线 / Wi-Fi / 移动热点 / 断网
前置条件：
步骤：
预期结果：
实际结果：
结论：通过 / 失败 / 阻断
缺陷编号：
证据索引：
```

证据文件建议使用 `用例编号_端或设备_日期时间` 命名。证据中不得出现真实个人信息、令牌、Cookie 或密钥；需要截图时先使用合成数据，并检查浏览器地址栏和开发者工具内容。

## 8. NFC 成品记录

NFC 邀请函的每批记录应覆盖：

1. 写入统一的 NDEF HTTPS URL；
2. 读取并与二维码、短链接逐字符核对；
3. 确认后设置永久只读；
4. 完成夹芯、覆膜或装袋后复测；
5. 使用另一台设备抽样交叉验证；
6. iPhone、安卓及双端微信打开最终页面。

只记录批次号和卡片测试编号，不关联真实新生。错误、空白、未锁定或损坏标签必须隔离。

## 9. 提交前检查

- [ ] 仅提交合成测试数据；
- [ ] 未提交 `.env`、凭据、令牌、Cookie、数据库或真实名单；
- [ ] 新测试可重复执行，不依赖固定执行顺序；
- [ ] 写操作测试在隔离环境运行并可清理；
- [ ] `/welcome`、`/screen`、`/admin` 的失败信息清楚；
- [ ] NFC 与二维码同 URL 的检查仍在用例中；
- [ ] 真实设备、三级降级和场馆彩排未被自动化结果替代；
- [ ] 缺陷和证据已按严重度记录。
