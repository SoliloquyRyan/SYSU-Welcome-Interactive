# SYSU Welcome Interactive

中山大学智能工程学院迎新晚会创新互动网页项目。

正式产品采用 NFC 明信片邀请函作为主要体验入口，二维码和短网址作为设备兼容备用；三种方式进入同一 H5。Demo v0 只验证同一随机令牌的网页入口，实体制作后续确认。二维码不能解决网站或现场网络故障，相关情况由备用网络、轻量页面和离线流程处理。

- `packages/contracts/`：前后端共享的协议版本、错误、运行状态、健康检查、快照和实时事件契约。

- `tests/`：G1/G2 自动化测试、G3 浏览器端到端与恢复测试、G4 协议级负载、真实设备和最终验收说明。
- `.github/`：Issue、Pull Request 和自动构建模板。

## G0～G4 验收与复验

需要 Node.js 和 pnpm。

```bash
pnpm install --frozen-lockfile
pnpm dev
```

根命令会初始化或原子升级本地合成数据，依次启动后端和前端，确认代理链路就绪后输出手机入口、后台、大屏和二维码文件位置。手机与电脑需位于同一可信网络；启动器不会修改 Windows 防火墙。当前生成的合成入口、合成姓名与学号、后台口令和数据库只保存在 `backend/.data/`，不得提交或截图传播。升级会保留既有个性邀请令牌和身份 ID，不会把学号明文写入数据库。

先验证 G2 功能基线：

```bash
pnpm verify:g2
pnpm db:verify
```

G3 自动化从仓库根目录运行：

```bash
pnpm verify:g3
```

## 动画同学快捷入口

Windows 下可直接双击仓库根目录的 `打开手机端预览.cmd`。它会自动进入正确目录，优先使用系统或 Codex 自带的 `pnpm`，并在首次缺少依赖时完成准备。启动后会同时打开 390×844 手机端和已进入排练状态的动画阶段控制台；在控制台选择阶段 1～6 并点击“跳转”，即可观察手机端实时切换。

只调试 `/welcome` 手机端星色与入场动画时，在仓库根目录执行：

```bash
pnpm preview:mobile
```

命令会使用 OS 临时目录中的合成数据启动隔离服务，自动打开一个
`390×844` 手机窗口和一个动画阶段控制窗口。手机端通过个性令牌直接建立会话并停在
“欢迎进入智工星河”，控制端自动使用合成后台会话进入排练。点击“启动星程”并确认星色后，可在控制端跳转阶段 1～6；关闭手机端窗口
  或按 `Ctrl+C` 后，临时数据库、会话和端口都会被清理。命令不会打印邀请
令牌、合成姓名、合成学号或后台密码，也不会读取 `backend/.data/`。

## 维护方式

当前项目由负责人本人长期单人维护。产品、前端、后端、视觉和测试仍按职责拆分，以便规划、审查和验收，但不假设固定有五名成员，也不把 AI 产出视为人类验收。

Demo v0 的当前边界：

- 同一局域网内运行 `/welcome`、`/admin` 和 `/screen`；
- 六阶段使用合成数据形成真实持久化与实时联动；
- 不进行公网部署，不接真实名单，不写实体 NFC，不接 AI 审核服务；
- 正式活动、硬件、印刷、域名和真实数据方案后续单独确认。

实体物料采购、付款、供应商下单、样品测试和到货验收均属于正式版延期事项，不阻塞 Demo v0。

## 协作规则

- GitHub Issue、分支和文档是开发任务与验收的正式记录；即时通信仅作可选通知渠道。
- 原则上一个 Issue 对应一个功能分支和一个 Pull Request；Demo v0 的跨模块基线以 `docs/DECISIONS.md` 中的已确认例外为准。
- 不直接向 `main` 推送；AI 也只能在独立分支工作。
- AI 生成的代码由对应人类负责人审查，不能自行验收。
- 真实姓名、学号、手机号、名单、密钥、数据库和现场导出文件不得进入仓库。

详细规则见 [CONTRIBUTING.md](CONTRIBUTING.md)。
