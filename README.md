# SYSU Welcome Interactive

中山大学智能工程学院迎新晚会创新互动网页项目。

项目采用 NFC 明信片邀请函作为主要体验入口，二维码和短网址作为设备兼容备用；三种方式进入同一 H5。二维码不能解决网站或现场网络故障，相关情况由备用网络、轻量页面和离线流程处理。

## 当前状态

仓库目前是可运行的开发骨架，不包含正式业务逻辑、真实名单、生产密钥或正式活动数据。

- `frontend/`：Vue 3 + Vite；含 `/welcome`、`/screen`、`/admin` 三个占位页面。
- `backend/`：后端方案待团队确认，当前仅保留接口边界说明。
- `docs/`：需求、决策、隐私、测试和现场手册。
- `tests/`：真实设备和全流程验收说明。
- `.github/`：Issue、Pull Request 和自动构建模板。

## 快速开始

需要 Node.js 和 pnpm。

```bash
cd frontend
pnpm install
pnpm dev
```

打开终端显示的本地地址。连接同一网络的手机可使用电脑局域网地址测试，但不要在开发环境使用真实新生数据。

## 五人分工

1. 项目/产品：需求、优先级、Issue 与最终产品验收。
2. 手机端前端：登录、个人页面、动力值、星光值和寄语流程。
3. 后端/发布：数据库、接口、审核后台、仓库管理和部署回退。
4. 视觉/大屏：页面视觉、大屏动画、页面文案和内容流程。
5. 测试/NFC：NFC、二维码、真实设备、全流程和彩排验收。

采购、付款和供应商下单不在本组职责内；项目组只提供技术规格、样品测试和到货验收结论。

## 协作规则

- 微信用于通知、讨论和阻塞升级；GitHub Issue 是开发任务的唯一记录。
- 一个 Issue 对应一个功能分支和一个 Pull Request。
- 不直接向 `main` 推送；AI 也只能在独立分支工作。
- AI 生成的代码由对应人类负责人审查，不能自行验收。
- 真实姓名、学号、手机号、名单、密钥、数据库和现场导出文件不得进入仓库。

详细规则见 [CONTRIBUTING.md](CONTRIBUTING.md)。
