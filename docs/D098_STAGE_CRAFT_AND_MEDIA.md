## 建议的播放分工

建议本场继续采用 OBS 本地节目媒体 + 系统透明互动层。重型视频及伴奏放在现场电脑的固定素材目录，系统处理节目顺序、学院舞台、弹幕、礼物、抢答、抽人、投票、颁奖和谢幕。此建议不代表已经修改现场 OBS 或部署服务器。

| 场景 | OBS 下层 | 系统画面 |
|---|---|---|
| 集结、互动、主持、颁奖、谢幕 | 无独立节目视频 | 普通 `/screen`，显示完整学院舞台或对应场景 |
| 有节目视频 | 本地媒体源 | `/screen?media=overlay`，节目时透明，只叠加系统公共互动 |
| 只有伴奏 | 本地音频源 | 普通 `/screen`，使用学院舞台 |
| 有图片和伴奏 | 图片源 + 本地音频源 | `/screen?media=overlay` |

OBS 媒体源原生支持本次常见的 MP4、MP3 和 WAV，并可控制入场重播、循环及结束隐藏；浏览器源则负责网页叠加。参见 [OBS 媒体源](https://obsproject.com/kb/media-sources) 和 [OBS 浏览器源](https://obsproject.com/kb/browser-source)。

网页也能嵌入音视频，但需要专门补齐本地资产索引、编码校验、预载、音频解锁、播放进度和刷新恢复，以及现场手动重播/切换；有声自动播放还可能被浏览器策略拒绝。当前系统没有这些演出播放器控制，单纯把文件放上服务器不等于形成可靠的播出链路。参见 [MDN play()](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/play)。本轮不把数百 MB 节目素材发送给观众手机，也不增加公网视频请求。

使用建议：两类网页源按实际部署基址填写，生产路径带 `/welcomeparty/`。网页源保持连接，关闭“不可见时关闭源”和“场景激活时刷新浏览器源”，避免换场重载；独立节目媒体按节目决定是否入场重播，伴奏不循环，并确认一次只输出一份音频。视频自带伴奏时不要叠加同一首外部音轨。隐藏后关闭媒体文件会节约内存，也可能增加重新打开延迟，需在播出机实测；本轮未代签 OBS 音频路由和场馆稳定性。

大屏采用深黑中央、右侧银蓝弧光和底部层叠半透明光带。复用原学院标志，节目背景默认一处，颁奖/主持外层一处，手机沿用现有顶部标志不重复添加。颁奖结果文字背后加柔边深色承托，避免背景边线穿字。环境光使用 28/34 秒低幅变化，暂停冻结，减少动态静态。设置项同步改为「学院舞台底图」。
