# 数据与隐私工作基线

> 状态：协议 v2 现行（D-025～D-032）。本文的最小化、公开告知、合成数据、日志与公共内容处置原则对 v1/v2 同样有效；v1 实现的字段快照只作历史参考，v2 字段以 [`PROTOCOL_V2.md`](./PROTOCOL_V2.md) 与共享契约为准。本文不是法律意见，也不表示学院已完成正式审批；真实数据告知、责任人和流程属于正式版延期事项。

## 1. 基本原则

- **只用合成数据**：Demo v0 不导入真实姓名、学号、手机号、班级、真实邀请码或名单。
- **目的明确**：只为合成身份核验、星辰档案、现场互动、时光胶囊候选、公开内容处理和必要排障保存数据。
- **最少够用**：能用随机内部标识、状态或聚合数解决的问题，不向大屏或日志暴露身份字段。
- **胶囊明示候选**：时光胶囊提交前明确说明可能经人工筛选上屏；未确认不得提交，未选中正文不得进入大屏。
- **弹幕明示公开**：首次发送弹幕前告知公开范围；通过本地规则后立即匿名公开，之后可下屏、屏蔽来源或清屏。
- **服务端权威**：客户端不保存可脱离服务端提交的业务队列，离线时阻止写入。
- **已接受的权限风险**：后台采用共用账号且登录会话可自提权，无法提供具体个人归因；不得把会话记录包装成最小权限或个人审计。
- **正式版限期清理**：未来如处理真实或可识别数据，原则上在活动结束后 30 天内完成清理。

## 2. 数据清单

| 数据类别 | 目的 | 最小化要求 | 可访问角色 | 当前保留基线 |
|---|---|---|---|---|
| 合成邀请入口 | 进入 H5、恢复状态、作废和重置 | 固定随机令牌只保存安全摘要；不得含姓名、学号或班级 | 共用后台会话 | 随确定性重置保留同一测试令牌 |
| 合成身份与合成学号 | 备用核验并避免重复参与者 | 仅虚构姓名；完整合成学号只保存安全摘要，不明文写入日志 | 参与者本人；后台仅必要统计 | 随确定性重置恢复固定种子 |
| 动力值、星光值和互动事实 | 现场功能、本人档案和故障核对 | 不附加无关身份字段；使用内部 ID 与唯一业务键 | 参与者本人、后台；大屏仅聚合 | Demo 可通过确定性重置清除 |
| 公开星号与星色 | 星辰展示、本人档案和未来抽奖扩展 | 星号含姓氏首字母和学号后四位，属于可关联编号；不得附完整姓名或完整学号 | 参与者、后台、大屏 | 随种子恢复星号；星色随运行重置清除 |
| 时光胶囊候选 | 本人档案与人工选择上屏 | 提交前确认公开范围；后台默认只读取星号、星色和正文 | 本人、后台筛选；大屏仅人工选中项 | 可撤下、清屏或随重置清除 |
| 公开弹幕 | 实时公共互动和事后处置 | 首次明示公开；限长、限频、规则校验；公开版本不附身份 | 大屏、后台、参与者 | Demo 可通过删除、清屏或重置处理 |
| 会话与操作记录 | 登录、权限检查和排障 | 会话只保存安全摘要；操作只记会话短 ID、当时角色、动作和结果 | 对应会话；后台系统状态 | 旧会话在重置后失效，运行记录随重置清除 |
| 聚合数据 | 大屏与 Demo 复盘 | 不包含完整姓名、完整学号、未选中胶囊、令牌、Cookie 或身份映射 | 大屏、后台 | 随当前 Demo 数据集存在 |

Demo v0 不允许第三方服务或外部 AI 接收上述数据。正式版若引入第三方服务，必须在启用前记录服务名称、数据范围、用途、保存方式和退出方案，并由负责人确认。

## 3. 收集与告知

Demo v0 首次进入 H5 时，应以简短、易读的方式说明：

- 当前仅使用虚构测试身份和本地合成数据；
- 收集哪些 Demo 数据、为何需要、是否为必填；
- 时光胶囊可以跳过；如提交，正文会进入人工上屏候选池；
- 弹幕通过规则后会匿名实时出现在大屏，并可被后台下屏；
- 如何重试、修改弹幕或反馈问题。

首次提交时光胶囊和首次发送弹幕前分别提供明确、简短的公开范围告知。胶囊只有在主动确认后才能提交，提交即进入人工候选池；弹幕通过规则后即时公开。正式录像、直播、长期保存、撤回和删除文案后续单独审定。

## 4. 邀请函、身份与星号

- NFC 标签、二维码和短码不得写入姓名、学号、班级等明文信息。
- 个性化令牌应随机、难以猜测，可由后台作废；NFC 与二维码使用同一令牌，确定性重置后保持稳定。
- v2 仍以 NFC 个性入口为主，二维码/短网址承载同一随机令牌；仅在无法使用个性入口时允许人工协助的虚构姓名+合成学号备用核验，且必须映射到同一合成身份、同一星号、同一数值与同一档案，不能另建参与者。
- 入口 URL 初始可携带令牌；页面读取后应立即把地址栏和当前历史项替换为不含令牌的 `/welcome`，不得向第三方资源传递或在访问日志中明文保留。
- Demo v0 不建立真实邀请函发放清单。
- D-023 明确把姓氏拼音首字母和学号后四位组成的星号作为公开编号；该编号可能被熟人关联到本人，不能标为不可关联匿名 ID。
- Demo 只使用虚构姓名和合成学号；正式名单来源、授权、重试限制、访客模式和人工核验步骤后续确认。
- 随机令牌、完整学号、参与者会话、后台会话和后台密码不得明文入库；按各自用途使用安全摘要或密码哈希。
- 星号必须唯一；正式导入时若发生碰撞，应拒绝激活并交由后台处理。

## 5. 时光胶囊、弹幕与公共展示

- 时光胶囊可以跳过；提交前必须确认可能经筛选后以星号和星色公开展示。
- 已提交胶囊进入人工候选池；后台可选择、撤下和紧急清除，只有仍被选中的正文可进入大屏。
- 后台筛选默认只需星号、星色和正文，不需要完整学号；AI 不得自动决定公开。
- 弹幕通过敏感词、链接、联系方式、长度和频率等确定性规则后立即进入 `PUBLISHED`；失败进入 `REJECTED_BY_RULE`，不得广播或奖励。
- 大屏弹幕和胶囊不显示完整姓名、完整学号、联系方式或入口令牌；胶囊可显示已明确为公开编号的星号和星色。
- 后台可将单条弹幕改为 `REMOVED`、屏蔽匿名来源、暂停新弹幕或执行紧急清屏；重连后不得恢复已下屏内容。
- 规则通过后即时公开可能发生漏判，这是项目负责人已接受的风险；删除、屏蔽、限流和清屏必须始终可用。
- 如现场录像或直播会长期保留大屏内容，需在活动前明确告知和处理方式。
- “时光胶囊”当前只是叙事设定，不构成保存四年的授权；真正的四年保存方案不在本基线范围内。

## 6. 系统与权限

- 后台使用一个共用账号；任何已登录会话可自行取得审核处理、阶段控制、Demo 管理或全部角色。
- 服务端检查当前角色，但该方案不构成可靠的最小权限；操作记录只保存会话短 ID、当时角色、时间、动作和结果，不能识别真实操作者。
- 大屏只通过受限接口获取聚合数据、公开星号/星色、仍处于 `PUBLISHED` 的弹幕和人工选中的时光胶囊，不连接完整身份、完整学号、令牌或未选中正文。
- 正式数据不得复制到个人聊天、个人网盘、公开代码仓库或无关测试环境。
- 开发和 AI 协作统一使用合成或已匿名化数据；不得向外部 AI 提供真实姓名、真实学号、入口令牌、时光胶囊原文或弹幕。
- 导出文件必须受控、注明用途和清理日期；不需要时不导出。
- 可观测日志不得记录完整邀请令牌、完整学号、Cookie、后台密码、时光胶囊正文或完整弹幕正文；内容处置仅引用内部内容 ID。
- 本地 HTTP 只限可信局域网合成 Demo，不提供传输机密性；`HttpOnly`、`SameSite` 和严格 `Origin/Host` 检查只能降低部分风险。正式公网运行必须使用 HTTPS 和 `Secure` Cookie。

## 7. Demo 重置与正式版 30 天清理

当前 v1 确定性重置会清除激活、星色锁定、积分、时光胶囊候选、公共内容、互动、旧会话和当前运行记录，恢复相同合成身份、合成学号摘要、星号、节目和礼物，并保持邀请令牌稳定。运行数据库位于 Git 忽略目录，不得提交。v2 的日常合成重置与一次性协议切换必须是两个显式操作；发现真实、不可重建或有保留价值的数据时，一次性切换必须停止，不能借日常重置静默清空。

以下 30 天清理只适用于未来获准处理真实或可识别数据的正式版本：

以晚会实际结束时间为 T0，当前基线为最迟在 T+30 天完成：

1. 关闭个人档案及邀请函访问入口，或使其令牌不可逆失效。
2. 删除身份映射、原始互动明细、寄语、弹幕和公共内容处置索引副本。
3. 删除后台导出、操作电脑下载、U 盘、共享目录和临时排障文件。
4. 清理数据库备份、对象存储和第三方服务中的对应副本；无法立即删除的机制须提前确认。
5. 仅保留匿名化汇总、技术复盘和删除记录，并复查其不能合理识别个人。
6. 由未来确认的数据负责人执行，并按学院实际人员安排确定复核方式，记录范围、时间、结果和例外。

任何超过 30 天的可识别数据保留，包括四年寄语、长期个人档案或安全日志例外，都必须在收集前单独说明目的、期限、责任人和退出方式，并重新获得所需确认；不得事后默认延长。

## 8. 数据事件处理

发现错绑、越权访问、令牌泄露、不当内容上屏或数据外传时：

1. 立即暂停相关入口、公开展示、导出或后台会话。
2. 保护参与者，先清屏或作废令牌，再进行排查。
3. 只保存排障必需的记录，避免在沟通群反复转发原始数据。
4. Demo v0 通知项目负责人；正式版同时通知未来确认的数据负责人，并按学院确认的流程处理。
5. 记录原因、影响范围、处置和防复发措施。

具体报告对象、联系方式、响应时限和学院流程待确认。
