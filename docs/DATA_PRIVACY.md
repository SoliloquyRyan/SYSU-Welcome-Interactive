# 数据与隐私工作基线

> 状态：协议 v2 / D-054 / D-056 现行。项目负责人已确认名单使用授权并完成 220 人受保护导入；寄语/时光胶囊不采集或展示。D-056 已把服务器私有持久化、一致性备份/恢复和合成协作边界落实为工程门，但实际数据告知、责任人、保存/删除、加密传输和事件响应流程仍须学院正式确认。本文不是法律意见。

## 1. 基本原则

- **正式/测试隔离**：正式库只含获授权的 220 组姓名与 8 位学号摘要；合成测试库和 5 个便捷测试账号不得混入正式运行。
- **目的明确**：只为身份核验、星辰档案、现场互动、个人抽奖、公开内容处理和必要排障保存数据。
- **最少够用**：能用随机内部标识、状态或聚合数解决的问题，不向大屏或日志暴露身份字段。
- **抽奖最小公开**：后台可在当前目录已准入参与者中无放回抽取；后台中奖记录含目录姓名+公开星号（正式运行时姓名属于受保护字段），大屏和公共事件只含公开星号。
- **弹幕明示公开**：首次发送弹幕前告知公开范围；通过本地规则后立即匿名公开，之后可下屏、屏蔽来源或清屏。
- **服务端权威**：客户端不保存可脱离服务端提交的业务队列，离线时阻止写入。
- **已接受的权限风险**：后台采用共用账号且登录会话可自提权，无法提供具体个人归因；不得把会话记录包装成最小权限或个人审计。
- **正式版限期清理**：未来如处理真实或可识别数据，原则上在活动结束后 30 天内完成清理。
- **代码与数据分离**：GitHub/release 只含代码和合成资产；正式运行目录、备份与传输暂存位于代码目录之外，且不因发布或重新克隆被复制。

## 2. 数据清单

| 数据类别 | 目的 | 最小化要求 | 可访问角色 | 当前保留基线 |
|---|---|---|---|---|

| 正式身份与学号 | 备用核验并避免重复参与者 | 只导入姓名与 8 位学号；数据库仅存学号 HMAC 摘要，性别/班级不导入 | 参与者本人；后台为现场功能显示必要姓名 | 原名单、正式库及备份按 30 天基线清理 |
| 合成测试身份 | 开发、回归与现场预演 | 与正式库隔离；只导出 5 个便捷账号，仍属于固定 300 人合成目录 | 开发/验收人员 | 可确定性重置 |

| 公开弹幕 | 实时公共互动和事后处置 | 首次明示公开；限长、限频、规则校验；公开版本不附身份 | 大屏、后台、参与者 | Demo 可通过删除、清屏或重置处理 |

| 聚合数据 | 大屏与 Demo 复盘 | 不包含完整姓名、完整学号、令牌、Cookie 或中奖者内部身份映射 | 大屏、后台 | 随当前 Demo 数据集存在 |
| 正式备份包 | 故障恢复与发布前保护 | SQLite 一致性快照 + 同代运行凭据/NFC 映射 + checksum manifest；包外仍需加密 | 指定数据负责人/备份保管人 | 与正式数据同属 T+30 清理范围，具体副本数与恢复点待落名 |

第三方服务或外部 AI 不得接收真实名单、NFC 映射、学号、令牌或后台口令。若未来确需引入第三方服务，必须在启用前记录服务名称、数据范围、用途、保存方式和退出方案，并由负责人确认。

## 3. 收集与告知

正式 H5 首次进入时，应以简短、易读的方式说明：

- 收集姓名/学号核验、星色、互动与抽奖所需的哪些数据，为何需要、是否为必填；
- 公开星号可能在星系和个人抽奖结果中展示；大屏不显示姓名；
- 弹幕通过规则后会匿名实时出现在大屏，并可被后台下屏；
- 如何重试、修改弹幕或反馈问题。

首次发送弹幕前提供明确、简短的公开范围告知；弹幕通过规则后即时公开。入场说明应明确公开星号可能用于星系与现场抽奖。正式录像、直播、长期保存、撤回和删除文案后续单独审定。

## 4. 邀请函、身份与星号

- NFC 标签、二维码和短码不得写入姓名、学号、班级等明文信息。
- 个性化令牌应随机、难以猜测，可由后台作废；同一人的 NFC 与二维码使用同一令牌。
- v2 仍以 NFC 个性入口为主，二维码/短网址承载同一随机令牌；无法使用个性入口时可用姓名+8 位学号恢复同一正式身份、同一星号、同一数值与同一档案，不能另建参与者。合成 Demo 只在服务端兼容 8 位测试学号。
- 入口 URL 初始可携带令牌；页面读取后应立即把地址栏和当前历史项替换为不含令牌的 `/welcome`，不得向第三方资源传递或在访问日志中明文保留。
- `backend/.private/2026-nfc-map.csv` 是受控发放清单，包含姓名、学号与可用邀请令牌；必须最小权限保存，不得提交、截图或转发，正式 URL 定稿后按职责备份/销毁。
- D-023 的“姓氏首字母+学号后四位”只保留为旧合成 Demo 历史规则；D-054 正式星号改为与身份字段无关的随机公开编号。
- 正式名单来源与核验授权已确认；重试限制由现有限频承担，访客模式、补卡和人工核验责任人仍待确认。
- 随机令牌、完整学号、参与者会话、后台会话和后台密码不得明文入库；按各自用途使用安全摘要或密码哈希。
- 星号必须唯一；正式导入器从独立随机空间生成并由数据库唯一约束兜底，不得用学号后四位解决碰撞。

## 5. 抽奖、弹幕与公共展示

- 系统不再提供寄语/时光胶囊输入、候选、审核、上屏或终章展示；schema 中的旧列和空表只用于前向迁移兼容。
- 抽奖只在 `RUNNING + PROGRAM_SUPPORT` 由后台明确操作；服务端从已准入且本 epoch 未中奖者中无放回抽取，不读取星光权重。
- 后台中奖记录只显示目录姓名与公开星号；正式姓名只在受控后台会话内出现。大屏、Screen 快照和公共事件只显示公开星号。不得导出姓名—星号映射或把它写入日志/测试报告。
- 关闭、暂停、换场或完成只收起抽奖层并保留记录；只有排练模式的 Demo 管理员可清空，本 epoch 普通重置会清除全部抽奖记录。
- 弹幕通过敏感词、链接、联系方式、长度和频率等确定性规则后立即进入 `PUBLISHED`；失败进入 `REJECTED_BY_RULE`，不得广播或奖励。
- 大屏弹幕和抽奖不显示完整姓名、完整学号、联系方式、入口令牌或内部身份 ID；抽奖只显示已明确为公开编号的星号。
- 后台可将单条弹幕改为 `REMOVED`、屏蔽匿名来源、暂停新弹幕或执行紧急清屏；重连后不得恢复已下屏内容。
- 规则通过后即时公开可能发生漏判，这是项目负责人已接受的风险；删除、屏蔽、限流和清屏必须始终可用。
- 如现场录像或直播会长期保留大屏内容，需在活动前明确告知和处理方式。
- 旧“时光胶囊”叙事不构成任何保存授权；D-037 已停止采集，未来如重新提出长期寄语须作为新功能重新完成必要性、告知、期限和删除评审。

## 6. 系统与权限

- 后台使用一个共用账号；任何已登录会话可自行取得审核处理、阶段控制、Demo 管理或全部角色。
- 服务端检查当前角色，但该方案不构成可靠的最小权限；操作记录只保存会话短 ID、当时角色、时间、动作和结果，不能识别真实操作者。
- 大屏只通过受限接口获取聚合数据、公开星号/星色、仍处于 `PUBLISHED` 的弹幕和抽奖安全投影，不连接完整身份、中奖者姓名、完整学号或令牌。
- 正式数据不得复制到个人聊天、个人网盘、公开代码仓库或无关测试环境。
- 开发和 AI 协作统一使用 `pnpm dev:rehearsal` 的固定合成目录或已匿名化数据；不得为了协作复制正式 `.private`、备份包或 NFC 映射，不得向外部 AI 提供真实姓名、真实学号、入口令牌、抽奖身份映射或弹幕。
- 导出文件必须受控、注明用途和清理日期；不需要时不导出。
- 可观测日志不得记录完整邀请令牌、完整学号、Cookie、后台密码、抽奖身份映射或完整弹幕正文；内容处置仅引用内部内容 ID。
- 本地 HTTP 只限受控排练，不提供传输机密性；正式名单真机访问和实体 NFC 上线必须使用 HTTPS 与 `Secure` Cookie。`HttpOnly`、`SameSite` 和严格 `Origin/Host` 检查不能替代传输加密。
- 正式服务器后端只监听 loopback，只信任 loopback 反向代理；公网不得开放后端端口。运行目录建议 `0700`、文件建议 `0600`，systemd 使用专用非登录账号和 `UMask=0077`。
- 当前 SQLite 只允许一个后端写实例，不放 NFS/SMB/同步盘。多实例会扩大一致性、锁与泄漏风险，未经新的数据库架构评审不得启用。

## 7. 正式备份、传输与恢复

- 备份必须通过 `db:formal:backup` 的 SQLite 在线 backup 流程生成，不得直接热复制活动主库或临时收集 `-wal/-shm`。bundle 同时包含数据库、运行凭据和 NFC 映射，并以 manifest 记录逐文件 SHA-256/长度；创建、恢复和正式启动会逐行核对映射与数据库，生产时还必须匹配唯一 HTTPS origin。
- manifest 只能证明文件完整性，不能加密内容。备份目录在任何外传前必须用组织批准的加密方式封装，经批准通道传输，解密暂存和密钥分开保管。
- 备份与恢复目标必须是 Git 仓库外、尚不存在的新目录；恢复先核验 checksum、SQLite 完整性、协议/schema、人数和 `PROTECTED` 分类，复制后复验。禁止覆盖活动目录。
- 备份至少覆盖发布/迁移前、NFC 批量定稿后和活动前恢复点；每份记录创建时间、对应提交、保管人、位置、恢复演练、访问例外和删除日期，不在公开日志中记录路径内的敏感命名或内容。
- 真正切换恢复目录前停止服务并确认没有第二个数据库写者；恢复后检查三端、会话、NFC 映射和日志，再保留旧目录到负责人签核。
- 运行库、备份、加密包、解密暂存、运维下载和离机副本全部受本页 T+30 清理约束。完整命令与服务器清单见 [`SERVER_DEPLOYMENT.md`](./SERVER_DEPLOYMENT.md)。

## 8. Demo 重置与正式版 30 天清理

`RESET_DEMO` 只适用于验证通过的 `SYNTHETIC_DEMO`，会清除其激活、星色、账本、抽奖、公开内容、互动、旧会话与运行状态。正式 `PROTECTED` 库在数据库分类、服务端命令和正式 UI 三层禁用该入口；发现真实、不可重建或有保留价值的数据时必须停止，不能借合成维护入口静默清空。正式恢复必须配套保存同代 SQLite 与运行凭据，NFC 映射另行最小权限保管。

以下 30 天清理适用于当前受保护正式版本；执行责任人和复核人仍须在上线前落名：

以晚会实际结束时间为 T0，当前基线为最迟在 T+30 天完成：

1. 关闭个人档案及邀请函访问入口，或使其令牌不可逆失效。
2. 删除身份映射、原始互动明细、寄语、弹幕和公共内容处置索引副本。
3. 删除后台导出、操作电脑下载、U 盘、共享目录和临时排障文件。
4. 清理数据库备份、对象存储和第三方服务中的对应副本；无法立即删除的机制须提前确认。
5. 仅保留匿名化汇总、技术复盘和删除记录，并复查其不能合理识别个人。
6. 由未来确认的数据负责人执行，并按学院实际人员安排确定复核方式，记录范围、时间、结果和例外。

任何超过 30 天的可识别数据保留，包括四年寄语、长期个人档案或安全日志例外，都必须在收集前单独说明目的、期限、责任人和退出方式，并重新获得所需确认；不得事后默认延长。

## 9. 数据事件处理

发现错绑、越权访问、令牌泄露、不当内容上屏或数据外传时：

1. 立即暂停相关入口、公开展示、导出或后台会话。
2. 保护参与者，先清屏或作废令牌，再进行排查。
3. 只保存排障必需的记录，避免在沟通群反复转发原始数据。
4. Demo v0 通知项目负责人；正式版同时通知未来确认的数据负责人，并按学院确认的流程处理。
5. 记录原因、影响范围、处置和防复发措施。

具体报告对象、联系方式、响应时限和学院流程待确认。
