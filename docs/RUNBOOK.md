# 迎新晚会互动系统运行手册

> 状态：本文运行步骤对应 D-022 的 G0～G4 基线；D-023 的 G5 身份、星色、时光胶囊和手机布局尚未部署，不能按本文声称已可运行。
> 范围：可信本地局域网、固定合成数据、网页与本地服务
> 说明：D-022 已绑定并复验本地初始化、一键启动、六阶段三端联动、浏览器恢复和 300 人本机协议负载。D-023 是下一手机端目标；其预览、数据迁移和新测试未完成前，继续按本文运行旧基线。本文不得被当作正式活动、学院审批或生产部署手册。

## 1. 适用范围

本手册覆盖：

- 参与者端 `/welcome`；
- 共用后台 `/admin`；
- 展示端 `/screen`；
- 本地服务、SQLite 持久化、HTTP 命令与 WebSocket 事件；
- 排练/现场模式、断线恢复、公共内容处置和确定性重置。

实体 NFC、邀请函印刷、公网域名、真实名单、正式场馆、主备硬件、音视频、灯光和主持 Cue 属于正式版延期事项。

## 2. 维护者与运行职责

项目由负责人本人长期单人维护。以下是职责而不是固定人员数量；一次 Demo 可以由同一人依次承担，也可以临时由多人分担：

| 职责 | 主要动作 |
|---|---|
| Demo 管理 | 启动、停止、种子初始化、确定性重置、收集测试证据 |
| 阶段控制 | 选择排练/现场模式，开始、暂停、恢复、推进或完成流程 |
| 公共内容处理 | 查看已发布弹幕，删除内容、屏蔽来源、暂停发布或紧急清屏 |
| 大屏观察 | 保持 `/screen` 可见，确认连接、阶段和聚合状态 |
| 参与者测试 | 使用合成身份走完 `/welcome` 六阶段 |

后台采用一个共用 Demo 账号。任何已登录会话均可自行取得审核处理、阶段控制、Demo 管理或全部权限。该方案不能识别真实操作者，也不提供可靠的最小权限；日志只记录会话短 ID、当时角色、动作、时间和结果。

## 3. 安全边界

- 只在本人控制的可信本地网络运行 Demo；局域网 HTTP 不提供传输机密性。
- 当前 D-022 运行只使用固定合成身份、六位 Demo 码、随机邀请令牌和虚构节目；G5 迁移后改用合成学号。
- 不输入、导入或截图真实姓名、学号、班级、手机号、正式邀请码、生产口令或真实活动数据。
- 不把完整令牌、六位 Demo 码、Cookie、后台密码、私密寄语正文或数据库文件提交到 Git。
- 参与者和后台使用相互独立的 `HttpOnly`、`SameSite=Lax` Cookie；服务端对业务请求和 WebSocket 检查精确的 `Origin` 与完整 `Host` authority。正式公网运行前必须升级为 HTTPS 与 `Secure` Cookie。

## 4. 地址与启动输出契约

从仓库根目录执行 `pnpm dev`。根级一键启动器在初始化和代理链路均就绪后输出以下实际值，不要求用户手工拼接地址：

```text
WELCOME_URL=http://<局域网地址>:<端口>/welcome
ADMIN_URL=http://<局域网地址>:<端口>/admin
SCREEN_URL=http://<局域网地址>:<端口>/screen
WELCOME_QR=<指向带固定合成令牌入口的二维码；页面读取后地址栏回到不含令牌的 /welcome>
DEMO_ADMIN=<共用 Demo 账号提示，不含日志可见明文密码>
```

客户端只能使用相对 `/api` 和由当前页面 host 推导的同源 `/ws`，不得硬编码 `localhost`。启动器负责初始化固定种子、启动本地服务与三端页面并验证代理就绪；页面已接入 G2 功能，但仍不能描述为正式生产系统。

首次启动前安装与验证：

```bash
pnpm install --frozen-lockfile
pnpm verify:g4
pnpm dev
```

`pnpm verify:g3` 已接入并包含 G2 回归、共享契约/后端/前端构建、E2E 类型检查和三项目 Playwright。D-019 记录的历史独立 G3 结果为退出码 0、278.9 秒、Vitest 16 个文件/102 条及 Playwright 6 场景 × 3 项目 = 18/18。D-021 提交前工作树总验收中的根级 `pnpm verify:g4` 又以退出码 0、观察总耗时约 463.2 秒重跑扩展全门：Vitest 20 个文件/119 条、三项生产构建及 Playwright 9 场景 × 3 项目 = 27/27 全部通过，浏览器报告 `passed`、失败检查点 0、时间窗 295388 ms。环境为 Windows 10.0.26100、Node.js 24.16.0、pnpm 11.16.0、Playwright 1.62.1；Chromium/Chrome/Edge 版本分别为 151.0.7922.34、151.0.7922.76、151.0.4129.72。`tests/reports/g3-browser.json` 是被 Git 忽略的本地脱敏证据，不是提交产物；CI 仅已配置且尚无远端执行证据。项目负责人随后完成 vivo X300 默认浏览器人工核心旅程。

`pnpm test:load` 只执行 G4 专项所需的契约/后端构建、负载类型检查和 300 人真实本机 HTTP/WebSocket 混合旅程；`pnpm verify:g4` 则先完整执行 `pnpm verify:g3`，再执行 G4 负载。开发中可先用前者定位性能回归，阶段收口使用后者；D-021 记录的提交前工作树全门已经实际通过。

需要明确指定局域网地址时，在 PowerShell 中先设置 `$env:DEMO_HOST = '本机局域网 IPv4'`。启动器不会自动修改 Windows 防火墙。

## 5. 启动前检查

G3 每次验收运行按顺序确认：

1. 当前数据库是独立的合成数据实例，运行目录已被 Git 忽略。
2. 服务端迁移成功，固定种子版本与预期一致。
3. 启动器输出的手机、后台和大屏 URL 使用同一 host 与端口。
4. 执行 vivo X300 人工项时，确认手机与电脑在同一可信网络且可访问 `WELCOME_URL`；D-021 记录的 2026-08-10 人工旅程已通过，后续代码变化后的复验仍按此检查并重新记录设备与浏览器元数据。
5. `pnpm db:verify` 通过，`/api/ready` 返回四项 `ready` 和 300 个合成参与者。
6. `/api/screen/snapshot` 返回当前权威运行状态和匿名聚合，且没有姓名、寄语、令牌或六位 Demo 码。
7. 未登录后台不能读取管理快照；一个合成参与者可在 Stage 1 激活并保存私密寄语，三端能观察到相应匿名更新。

若任一检查失败，先停止服务并修复；不要用手工改数据库绕过未就绪状态，也不要继续执行现场阶段命令。

## 6. 运行状态

服务端权威运行状态由三部分组成：

- `mode`：`REHEARSAL`（排练）或 `LIVE`（现场）；
- `status`：`READY`、`RUNNING`、`PAUSED` 或 `COMPLETED`；
- `stage`：1–6。

排练模式允许跳转阶段，用于快速测试。现场模式只能开始、暂停、恢复、向前推进和完成，不能回退或任意跳转。每次阶段变更更新 `stageRevision`；重置更新 `resetEpoch`。过期命令必须被服务端拒绝，不能覆盖较新的状态。

## 7. 六阶段操作顺序

> 以下操作均由 G2 页面与本地服务支持；G3 使用真实浏览器和固定合成数据收集端到端证据，不新增业务规则。

### 7.1 身份激活

- 参与者通过固定随机令牌打开 `/welcome`，使用虚构姓名和六位 Demo 码核验。
- 成功后初始动力值为 100、星光值为 20。
- 同一参与者在多设备登录时恢复同一状态；重复提交不得重复建号或发分。

### 7.2 私密未来寄语

- 参与者进入主流程时填写限长未来寄语；首次有效保存增加星光值 20。
- 寄语只在本人最终档案中可读，永不进入大屏、公共事件或后台公共内容列表。
- 该步骤没有公开审核状态，也不能与弹幕的公开告知混为一谈。

### 7.3 星星启动

- 阶段开放后，每位参与者只能启动一次稳定的匿名个人星星并增加星光值 20。
- 大屏显示匿名节点与聚合状态。动画失败时保留静态节点和完成事实。

### 7.4 节目应援与弹幕

- 节目来自固定虚构种子，不在 Demo 现场编辑正式节目。
- 礼物为微光 5、信标 10、星轨 20、星舰 50；成功赠送在单事务中扣减动力值并增加热度，首次赠礼增加星光值 10。
- 首次发送弹幕前展示一次性公开告知。弹幕通过敏感词、链接、联系方式、长度和频率规则后立即匿名上屏；首次合规弹幕增加星光值 10。
- 规则拒绝的弹幕不上屏。后台可事后删除已发布弹幕、屏蔽来源、暂停新弹幕或紧急清屏。

### 7.5 协同点亮

- 每位参与者只能完成一次协同点亮并增加星光值 20。
- 大屏实时显示完成数、有效参与者分母和比例，不显示个人名单。

### 7.6 星际档案

- 参与者查看本人星号、动力值、星光值、互动记录、礼物记录和私密未来寄语。
- 大屏只显示匿名集体星图、激活数、星光总量、互动数和等级分布。
- 所有结果从持久化事实派生，不使用前端固定数字伪装实时数据。

## 8. 公共内容处置

> G2 弹幕采用本地确定性规则与事后处置，不调用外部 AI。

弹幕没有人工发布前队列；通过本地确定性规则后即为 `PUBLISHED`。发现不合适内容时按影响范围选择：

1. **删除单条**：将内容标记为 `REMOVED`，所有大屏在权威更新后消失。
2. **屏蔽来源**：阻止该参与者会话继续发布，并保留不含真实身份的处置记录。
3. **暂停新内容**：立即阻止新的弹幕写入，不影响已提交的礼物和阶段事实。
4. **紧急清屏**：需要普通确认；清除当前公共弹幕展示，不读取或删除私密未来寄语。

AI 审核只预留适配器接口。Demo v0 不调用外部模型，外部服务不可用也不得影响本地规则和事后处置。

## 9. 断线、失败与恢复

> G2 已实现表中的业务写入、登录和大屏事件恢复；G3 自动化已在真实浏览器中验证关键恢复路径，项目负责人也已在 vivo X300 默认浏览器完成人工断网恢复。后续代码或设备环境变化后仍须按下表重新验收。

| 状况 | 立即动作 | 恢复标准 |
|---|---|---|
| 手机断线 | 禁止业务写入，显示离线提示 | 重连后先拉权威快照，再允许操作；不自动补交 |
| 大屏断线 | 保留最后可信快照并显示断线状态 | 重连后用完整快照校正；装饰轨迹不补播 |
| 后台断线 | 停止发送控制命令 | 重新登录并读取当前运行状态后再操作 |
| 服务进程重启 | 不继续盲点按钮 | 数据库恢复成功，三端快照一致，`resetEpoch` 未意外变化 |
| 动效失败 | 关闭装饰层 | 静态标题、状态、数值和操作仍完整可读 |
| 内容失控 | 暂停新弹幕或紧急清屏 | 规则拒绝内容从未显示，已删除内容不在重连后恢复 |

断线期间不得在客户端排队业务写入。任何恢复都以服务端权威快照为准，不能以浏览器缓存或动画状态推断业务结果。

## 10. 确定性重置

可从仓库根目录执行 `pnpm db:reset`，或在取得 `DEMO_ADMIN`/`ALL` 角色后使用后台重置。后台重置必须经过普通确认，并回到可复现的完整 Demo 起点：

- `resetEpoch` 递增；
- 激活、数值账本、私密寄语、礼物、弹幕、协同点亮和当前运行记录被清除；
- 旧参与者与后台会话失效；发起重置且完整收到成功响应的后台页面会自动换成新 epoch 管理会话；
- 固定合成身份、虚构姓名、六位 Demo 码、节目、礼物和随机邀请令牌恢复为相同种子；
- 已打印或已生成的 Demo 二维码对应令牌仍有效；
- 三端收到 `demo.reset` 后丢弃旧 epoch 事件并重新取快照。

重置不是正式数据删除流程，也不证明真实数据保留政策已经完成。

## 11. 停止与证据

结束一次 Demo 时：

1. 记录当前提交或工作树标识、种子版本、操作系统、Node、pnpm、浏览器、设备、视口、网络和测试时间。
2. 按 P0 编号保存通过、失败、跳过、恢复方式和执行者；自动化最终数字只能来自实际命令输出，vivo X300 只能由项目负责人标记人工结果。
3. 保存不含凭据、令牌、六位 Demo 码、Cookie、后台密码、私密正文、数据库或完整公共内容的汇总测试结果。
4. 停止本地服务，确认端口和浏览器临时配置已清理，且没有误把数据库或运行凭据加入 Git。
5. 如需复跑，使用确定性重置；如需保留故障证据，只保留最小化、匿名化片段。
