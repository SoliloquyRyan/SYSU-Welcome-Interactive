# 迎新晚会互动系统现场运行手册（初版）

## 1. 使用范围

本手册供现场主控、内容审核、网络与备份人员、入口工作人员及技术负责人共同使用，覆盖：

- 新生端 `/welcome`；
- 舞台端 `/screen`；
- 管理端 `/admin`；
- NFC 明信片邀请函、二维码和短链接；
- 上线检查、正式执行、故障降级、恢复和活动后收尾。

任何真实名单、管理员口令、服务器密钥、令牌和网络密码均不得写入本手册或提交到仓库。现场凭据由指定负责人通过安全渠道分发。

## 2. 角色与单一责任人

每个岗位在正式活动前填写实际负责人和备用负责人，避免多人同时操作同一控制项。

| 岗位 | 主要职责 | 禁止事项 |
|---|---|---|
| 总指挥 | Go/No-Go、降级和恢复的最终决定 | 不直接修改生产数据 |
| 现场主控 | `/admin` 节目切换、集结、暂停和降级 | 未收到 Cue 不触发关键动作 |
| 大屏操作 | `/screen` 全屏、主备信号和预渲染素材 | 不登录管理端，不临场更改素材 |
| 内容审核 | 弹幕、寄语审核和下架 | 不补发积分、不切换节目 |
| 网络与备份 | 主备网络、主备电脑和状态监控 | 不在未确认时同时切换多项基础设施 |
| 入口工作人员 | NFC/二维码指引、人工核验和分流 | 不拍摄或复制完整名单 |
| 记录员 | 记录 Cue、故障、处置时间和结果 | 记录中不得粘贴密钥或真实个人数据 |

## 3. 现场物资

### 3.1 必需

- 已验收的 NFC 明信片邀请函及备用成品；
- 卡面二维码、可手动输入的短链接和活动纸面关键信息；
- 主控电脑、备用电脑、大屏及所需视频接口；
- 场馆有线网络或 Wi-Fi、两路不同运营商备用热点；
- 工作人员测试手机：支持 NFC 的 iPhone、支持 NFC 的安卓手机，以及双端微信；
- 电源排插、网线、视频转接头、充电器、移动电源和对讲设备；
- 预渲染的星星集结、节目热度、寄语结尾视频及静态兜底画面；
- 纸质或离线人工核验名单，仅由授权入口负责人保管；
- 本手册、Cue 表、测试验收表和故障记录表的离线副本。

### 3.2 建议

- USB NFC 读写设备及少量空白备用标签；
- 备用邀请函、二维码说明牌和 NFC 感应位置演示卡；
- 独立 U 盘保存预渲染素材和经过校验的部署包；
- 备用键鼠、视频线、胶带和标签纸。

## 4. 地址与配置管理

正式活动只使用经过审批的 HTTPS 基础地址。现场记录使用占位符，不在文档中写真实密钥：

```text
BASE_URL=<经审批的活动基础地址>
WELCOME_URL=<BASE_URL>/welcome
SCREEN_URL=<BASE_URL>/screen
ADMIN_URL=<BASE_URL>/admin
```

要求：

- NFC、二维码和印刷短链接必须进入同一个 `WELCOME_URL`；
- `/screen` 仅在舞台设备打开，不印到公开物料；
- `/admin` 不通过公开 NFC 或二维码分发；
- 管理员凭据、API 密钥和真实名单只存放在批准的安全位置；
- 不在聊天、截图、投屏画面、浏览器收藏名或日志中暴露凭据；
- 任何地址变更先在稳定入口层完成，再重新验证 NFC、二维码和短链接。

## 5. 时间线

### T-7 天至 T-3 天：技术联调

- 冻结活动基础地址、三个路由和 NFC/二维码入口；
- 完成邀请函小样的写入—读取—锁定—复测；
- 使用合成数据跑通 `/welcome`、`/admin`、`/screen` 三端链路；
- 完成 iPhone、安卓及双端微信浏览器验证；
- 校验正式大屏分辨率、视频接口和预渲染素材；
- 主备网络分别完成连接与切换测试；
- 将所有未关闭问题登记并分配责任人。

### T-2 天至 T-1 天：场馆全流程彩排

- 使用正式场地、正式设备、最终 Cue 表和邀请函成品；
- 入口、主持、主控、审核、大屏和网络岗位全部到位；
- 从 NFC/二维码进入开始，完整执行登录、寄语、集结、节目切换、应援、弹幕、星光和结尾档案；
- 主动模拟网站功能故障、主网络中断和大屏主机故障；
- 实际执行三级降级和恢复；
- 记录 Cue 时间差、页面延迟、人员协作问题和恢复时长；
- 彩排后清除合成数据，封存最终部署版本和素材。

### 活动当天 T-120 分钟

- 主备电脑、路由、热点、大屏、音视频接口和电源全部上电；
- 校准系统时间，确认所有设备时间一致；
- 主控电脑打开 `/admin`，大屏电脑打开 `/screen` 并进入全屏；
- 使用测试身份在 `/welcome` 完成一条全链路验证；
- 验证主控触发能同步到手机和大屏；
- 主备网络各切换一次并恢复主线路；
- 播放全部预渲染素材，确认无缺帧、无错误版本、无敏感数据；
- 将测试产生的合成内容清除。

### 活动当天 T-60 分钟

- 从成品邀请函抽取若干张，用真实 iPhone 和安卓复测 NFC 与二维码；
- 检查入口海报、座椅卡、主持人屏幕的二维码均进入同一 `/welcome`；
- 确认入口人工核验名单可离线访问并由授权人员保管；
- 确认内容审核队列、敏感词规则和一键暂停可用；
- 确认备用电脑停留在安全待命画面，备用视频源可立即切换；
- 所有岗位通过对讲完成一次口令回读。

### 活动当天 T-30 分钟：Go/No-Go

总指挥逐项确认：

- [ ] `/welcome`、`/screen`、`/admin` 可访问；
- [ ] NFC、二维码和短链接目标一致；
- [ ] 手机端、后台和大屏端状态一致；
- [ ] 主备网络、主备电脑和预渲染素材可用；
- [ ] 审核员、入口人员和记录员已就位；
- [ ] 三级降级的触发口令和责任人明确；
- [ ] 当前无阻断级或严重级未处置问题；
- [ ] 页面、屏幕和日志中无测试数据、真实名单或密钥泄露。

任一核心项不通过时，先修复或直接选择可控的降级模式，不得在状态不明时开放全部实时功能。

## 6. 正式执行流程

### 6.1 入场阶段

1. 入口人员提示新生点亮并解锁手机，将手机顶部或背面靠近邀请函 NFC 感应区。
2. 无反应时立即引导扫描同卡二维码；仍无法打开时尝试印刷短链接。
3. NFC、二维码和短链接均进入 `/welcome`，不得让参与者安装未知应用。
4. 身份匹配失败时，转人工核验或访客模式，不在入口公开讨论完整身份信息。
5. 记录员观察登录成功率和排队情况；拥堵时增开二维码指引和人工分流。

注意：若网站本身不可用，二维码也无法解决问题，应直接按一级或二级降级处置。

### 6.2 开场集结

1. 主控确认 `/admin` 在线人数、待启动人数和大屏连接状态。
2. 主持人口令前，大屏操作员回报 `/screen` 已全屏、备用视频源待命。
3. 主持人口令到达后，仅现场主控执行一次“开始集结”。
4. 记录员记录触发时间和大屏实际响应。
5. 实时动画异常时，主控停止重复触发，大屏操作员按口令切预渲染集结视频。

### 6.3 节目互动

- 每次切换节目由现场主控执行，并由大屏操作员口头确认；
- 审核员持续处理弹幕和寄语队列，必要时先暂停公开展示；
- 网络人员监控连接、延迟和错误率，不因少量客户端问题立即切换全场网络；
- 出现重复扣减、负余额或异常加分时，立即暂停相应功能，保留其他稳定功能；
- 禁止展示个人消费排行、完整姓名或完整学号。

### 6.4 结尾回响

1. 内容审核员确认待展示寄语已完成审核。
2. 主控按 Cue 触发寄语与关键词流程。
3. 实时关键词或动画异常时，大屏切换已验收的模板视频。
4. 手机端个人档案可在散场后继续开放，不为等待生成而阻塞出口。

## 7. 三级降级与恢复

### 7.1 一级：网站功能降级

**适用情况**：弹幕、复杂动画、关键词分析或部分接口异常，但 `/welcome` 核心页面和后台仍可访问。

**执行**：

1. 现场主控暂停故障模块，保留身份、节目状态和必要提交；
2. 大屏隐藏异常组件，切换静态背景或简化布局；
3. 手机端显示简短说明，避免用户反复提交；
4. 记录故障开始时间、影响范围和已暂停功能。

**恢复**：先在后台确认服务和数据状态，再由测试手机验证，最后恢复公开入口和大屏组件。不得一次同时恢复多个未知状态模块。

### 7.2 二级：网络受限

**适用情况**：场馆 Wi-Fi 拥堵、WebSocket 大面积断开、主线路故障或请求延迟明显。

**执行**：

1. 网络人员确认是局部终端、无线网络还是服务端问题；
2. 后台和大屏优先切换到有线或独立备用网络；
3. 降低弹幕和数据刷新频率，允许轮询或延迟汇总；
4. 暂停非核心互动，入口启用人工核验或访客模式；
5. 主持人口播说明核心舞台流程继续，不组织全场反复扫码。

**恢复**：确认主线路稳定后先恢复后台，再恢复大屏，最后分批恢复手机端非核心功能。检查故障期间的重试请求，防止重复扣分或加分。

### 7.3 三级：大屏故障或完全离线

**适用情况**：主备网页均不可用、场馆断网、大屏浏览器或主机故障，实时联动无法可靠继续。

**执行**：

1. 总指挥宣布进入三级降级；
2. 现场主控停止实时手机互动和自动触发；
3. 大屏操作员切换备用电脑、备用视频源、预渲染视频或静态画面；
4. 主持人按离线 Cue 继续星星集结、节目热度和寄语叙事；
5. 入口使用邀请函纸面信息和人工名单，不要求继续访问网站；
6. 记录故障期间，不承诺补记无法可靠确认的互动数据。

**恢复**：除非总指挥、技术负责人和大屏操作员共同确认稳定，否则晚会中不从三级模式强行恢复实时联动。若决定恢复，先在非投屏设备验证，再切备用大屏源，最后有限开放手机端。

## 8. 常见故障快速处理

| 现象 | 首查 | 处置 |
|---|---|---|
| NFC 无反应 | 手机是否亮屏解锁、NFC 是否开启、感应位置、手机壳 | 移动手机背面位置；仍失败则扫码，不在入口长时间排查单卡 |
| NFC 和二维码结果不同 | 两者目标 URL 和跳转环境 | 隔离该批邀请函，使用统一入口海报并复核全部同批成品 |
| `/welcome` 打不开 | HTTPS、域名、主站状态和网络 | 判断网站还是网络问题，进入一级或二级降级；二维码不会绕过站点故障 |
| 登录重复或积分异常 | 请求重试、幂等状态、后台日志 | 暂停相应写操作，保留证据，只处理合成或经授权的记录 |
| 弹幕失控 | 审核队列、频率限制 | 一键暂停公开弹幕，保留节目和大屏主画面 |
| `/screen` 卡住 | 浏览器、连接状态、主机和视频源 | 尝试安全刷新；失败则切备用电脑或预渲染素材 |
| `/admin` 无法控制 | 管理端网络、权限、服务状态 | 禁止多人重复点击；进入对应降级并按 Cue 人工继续 |
| 主网络故障 | 有线、Wi-Fi、服务端、热点状态 | 后台和大屏优先切备用线路，参与者侧降低实时功能 |

## 9. 恢复后的完整性检查

- 当前节目和舞台 Cue 一致；
- `/admin`、`/screen`、`/welcome` 显示同一活动状态；
- 重试队列没有造成重复身份、重复扣分或重复加分；
- 待审内容未绕过审核直接上屏；
- 大屏已连接当前数据源，不再播放旧缓存；
- 故障期间人工操作和后续补录有明确授权与记录；
- 恢复结果由主控、大屏操作和记录员三方口头确认。

## 10. 活动后收尾

1. 停止新的互动提交，保留只读回顾或结束提示。
2. 导出经批准的活动统计，不把真实名单复制到代码仓库或普通聊天工具。
3. 按要求处理寄语、弹幕、日志和个人数据；删除动作须由授权人员执行并留记录。
4. 注销管理端会话，回收现场临时凭据，不在共享电脑保留登录状态。
5. 保存非敏感故障时间线、Cue 执行结果和改进项。
6. 清点主备设备、邀请函余料、U 盘和离线名单，离线名单交回授权负责人。
7. 将统一入口调整为经审批的活动回顾或停止服务页面，并复核旧邀请函不会打开错误环境。
