# GitHub 公共发布边界

日期：2026-09-20

这份清单用于下一届整理仓库和制作 Release 时快速判断“能不能公开”。它描述的是公开 GitHub 的默认边界，不替代学院对正式数据、节目署名和媒体版权的确认。

## 可以放进仓库的内容

- 源码、共享契约、合成排练数据生成器和不含真实数据的测试；
- `docs/` 中的架构、操作、复盘和决策记录；
- 已确认可公开的节目单、演职员署名和视觉素材；
- 示例环境变量、部署模板和离线包生成脚本，但不能包含运行时数据或凭据；
- `docs/assets/invitation/` 中明确标注为示例的邀请函素材。

项目外的 `backups/`、`output/`、`outputs/`、`OBS-迎新晚会-*`、`_welcome_qa/` 和各类 Word/Excel 工作备份继续留在仓库外；它们可能含测试账号、真实现场资料、媒体或编辑历史，不能因为文件名看起来像“文档”就整体上传。

## 默认留在仓库外的内容

- 正式名单、姓名—学号/NFC 对应表、真实数据库和备份；
- 管理员、OBS、音频桥接、服务器、Cookie、邀请令牌和任何运行密钥；
- 含真实身份的 trace、录屏、聊天导出、现场日志和完整导入包；
- 带音乐、主持音频或其他第三方媒体的完整部署压缩包，除非已完成版权和隐私复核。

## 当前仍需人工确认的公开项

仓库中的节目单和演职员资料来自负责人提供的公开演出信息，当前按节目用途保留。下一届若继续复用，先确认姓名、节目、图片和音视频授权仍有效；若只是演示系统，应改用合成节目单，而不是把现场资料复制到新分支。

`output/` 下的断网 PPT/PDF、主持素材和部署包被 `.gitignore` 排除。它们可以作为下一届 Release 的候选资产，但在上传前必须检查文件内容、媒体版权、演职员信息和 SHA 清单；不要直接用完整现场压缩包替代源码发布。

D-030 的个人星光预演素材仍在项目外的本地目录 `motion-previsual-personal-star/`，仓库中的历史记录会引用它。由于当前没有在本次收口中确认其版权和公开范围，下一届接手时应先完成授权确认；确认前请把它当作外部交接材料，不要从本机目录直接复制进 Git。

## 发布前四步

1. 在干净 checkout 中运行 `pnpm docs:check`、`pnpm typecheck`、`pnpm test`、`pnpm build` 和 `pnpm test:e2e:current`。
2. 用 `git ls-files` 与 `git grep` 检查没有 `.env`、数据库、名单、令牌、密码、Cookie 或私有路径。
3. 对要上传的 Release 资产单独解压检查，不把本地 `output/` 目录整体加入 Git。
4. 在 Release notes 中写明版本、验证范围、已知限制和“真实场馆网络/手机/LED/OBS 尚需现场验收”。
