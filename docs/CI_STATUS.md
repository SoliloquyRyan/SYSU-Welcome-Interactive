# CI 状态与 E2E 口径

日期：2026-09-20

## 当前必需门

GitHub Actions 的必需工作流会验证：依赖安装、合约和后端类型检查、单元/集成测试、构建、部署静态检查、正式/排练 smoke、文档链接、E2E 类型检查，以及当前现场主流程 `tests/e2e/d119-final-live.spec.ts`。

本地等价入口（`test:e2e:current` 是兼容别名）：

```text
pnpm test:e2e
pnpm test:e2e:current
```

这条规格覆盖 D-119 当前现场路径：三端启动、游客入场、个人流星、节目后隐藏到场人数、档案页学生核验、弹幕、主持/节目切换、互动控台、颁奖隐私和刷新恢复。它使用合成名单，不访问正式数据。

## 为什么没有把全部历史 E2E 作为必需门

仓库仍保留 D-106、D-108、D-109 等阶段的浏览器规格，方便追溯当时的视觉和流程决策。其中一部分断言的是已经废弃的交互，例如游客入场后立即在聊天页显示“核验学生身份”；D-119 已将它移到手机“档案”页。2026-09-20 的 GitHub CI 记录显示，安装、类型检查、单元/集成测试、构建、部署 smoke、文档检查和 E2E 类型检查均通过，只有全量旧 E2E 矩阵失败或超时。

因此当前 CI 采用“现行现场规格必需、历史规格保留待迁移”的口径。完整矩阵仍可手动运行：

```text
pnpm test:e2e:all
```

如果需要重现旧的单浏览器基线，使用 `pnpm test:e2e:legacy`；它不属于当前 CI 门，可能因为历史交互断言而失败。

在历史规格全部按当前协议和现场流程迁移前，不把 `test:e2e:all` 的结果解释为当前部署已经失败，也不把当前 smoke 的通过扩大为真实手机、LED、调音台、OBS 长链路或场馆网络签核。
