# 产品与系统需求

> 状态：D-021 已记录 Demo v0 G0～G4 的 2026-08-10 提交前工作树验收；是否已形成可复现冻结版本，以 D-022 对被验收提交的完整 SHA、提交后复验结果与干净工作树状态的记录为准（G5 与正式环境不在该结论范围）。
> 说明：`MUST` 表示 `feature/demo-v0` 必须满足的产品基线，`G3-EXIT` 与 `G4-EXIT` 标明分阶段取证门槛，`FORMAL-PENDING` 表示只在正式上线前确认；本文不构成学院正式决策。若旧用例或文档与本文件冲突，以 `docs/DECISIONS.md` 的最新已确认项和本版本为准。

## 1. 角色

- **Demo 参与者**：通过固定合成邀请令牌进入 H5，以虚构姓名和六位 Demo 码完成六阶段。
- **共用后台操作会话**：登录后可自行取得 `REVIEWER`、`STAGE_CONTROLLER`、`DEMO_ADMIN` 或 `ALL`；不同角色只是能力分组。
- **大屏会话**：只读取匿名聚合和仍处于公开状态的弹幕。
- **项目负责人**：当前长期单人维护，并负责产品取舍、运行和最终验收。

## 2. 入口与身份

- **REQ-ENTRY-001 MUST**：Demo v0 使用同一随机令牌验证 NFC 与二维码的入口概念；NFC 作为正式产品主入口、二维码作为设备兼容备用的方向保持不变，但实体写卡和印刷为 `FORMAL-PENDING`。
- **REQ-ENTRY-002 MUST**：NFC 与二维码进入同一 H5，并恢复同一个参与者状态；不得重复发放动力值或生成两个档案。
- **REQ-ENTRY-003 MUST**：NFC、二维码和可见链接不得直接包含姓名、学号、班级等个人信息。
- **REQ-ENTRY-004 MUST**：页面应提供清晰的轻触、扫码和人工协助说明。
- **REQ-ENTRY-005 MUST**：后台应能识别有效、无效或已作废的合成入口；令牌操作需要 `DEMO_ADMIN` 或 `ALL` 当前角色和确认对话框。
- **REQ-ENTRY-006 MUST**：采用个性化“一人一卡一码”；同卡 NFC 与二维码编码同一不可猜测随机令牌，确定性重置后保持有效。
- **REQ-ENTRY-007 MUST**：入口 URL 可承载随机令牌；前端读取并发起激活后应立即将地址栏和当前历史项替换为不含令牌的 `/welcome`，且不得将令牌发送给第三方资源或写入日志。
- **REQ-ID-001 MUST**：Demo v0 使用随机令牌、虚构姓名和六位 Demo 码核验；失败信息不得分别泄露姓名或六位 Demo 码是否存在。
- **REQ-ID-002 MUST**：公开星号不得直接复用完整或部分学号，应由系统生成并校验唯一性。
- **REQ-ID-003 MUST**：同一参与者可在多个设备或浏览器同时保持会话；各端恢复同一服务端状态。
- **REQ-ID-004 FORMAL-PENDING**：正式真实名单、最少核验字段、人工核验和访客权限后续确认。

## 3. 六阶段功能

### 3.1 轻触/扫码与身份激活

- **REQ-FLOW-101 MUST**：参与者进入后看到简短的数据提示、操作说明和核验界面。
- **REQ-FLOW-102 MUST**：首次有效激活只创建一个参与者状态，发放一次 100 点初始动力值和 20 点星光值。
- **REQ-FLOW-103 MUST**：后台可查看登录成功率、无效入口数和当前在线人数，但大屏只显示匿名汇总。

### 3.2 未来寄语

- **REQ-FLOW-201 MUST**：参与者核验后优先看到未来寄语表单，可保存一条最多 80 个可见字符的私密短句。
- **REQ-FLOW-202 MUST**：未来寄语只进入本人档案，不建立人工审核或公开状态，永不进入大屏、公共快照或公共事件。
- **REQ-FLOW-203 MUST**：首次成功保存奖励 20 点星光；之后可修改正文，但不得重复得分。
- **REQ-FLOW-204 FORMAL-PENDING**：正式版本是否允许寄语公开、相应授权和撤回方式后续确认；Demo v0 不预留公开开关。

### 3.3 星星生成与全场集结

- **REQ-FLOW-301 MUST**：每个已激活参与者生成一个匿名个人星星和唯一星号。
- **REQ-FLOW-302 MUST**：后台推进到第 3 阶段后，参与者可将自己的星星启动一次；大屏按已创建和已启动数量生成集结效果。
- **REQ-FLOW-303 MUST**：装饰动画失败时保留静态星点、数量和完成状态，不得影响星星启动事实；正式预渲染视频为 `FORMAL-PENDING`。
- **REQ-FLOW-304 MUST**：个人星星外观由服务端保存的稳定种子派生，多设备显示一致；首次启动奖励 20 点星光。
- **REQ-FLOW-305 FORMAL-PENDING**：正式汇聚图形、主持口令、音乐和灯光 Cue 后续确认。

### 3.4 节目应援与弹幕

- **REQ-FLOW-401 MUST**：手机端显示当前节目、下一节目和节目状态；只有开放中的节目可接收动力值。
- **REQ-FLOW-402 MUST**：动力值由服务端校验并幂等扣减，余额不得为负，刷新或重试不得重复扣减。
- **REQ-FLOW-403 MUST**：首次提交公开弹幕前显示一次明确公开告知；弹幕通过敏感词、链接、联系方式、长度和频率等本地确定性规则后，立即以匿名形式上屏，不经过人工预审。
- **REQ-FLOW-404 MUST**：大屏不展示个人动力值消费排行，只展示节目或集体维度的聚合效果。
- **REQ-FLOW-405 MUST**：虚拟礼物档位为微光 5、信标 10、星轨 20、星舰 50；可重复赠送，不涉及金钱、支付、充值或兑换，参与者可将全部余额投入同一节目。
- **REQ-FLOW-406 MUST**：成功送礼在同一服务端事务中扣除动力值、写入礼物事实并增加节目热度；余额不得为负。同一动作重试只生效一次，新的明确点击可形成新礼物。
- **REQ-FLOW-407 MUST**：首次成功送礼奖励 10 点星光；首次规则通过弹幕奖励 10 点星光，后续下屏不追回已经确认的成长奖励。

### 3.5 协同点亮

- **REQ-FLOW-501 MUST**：第 5 阶段提供“全场协同点亮”；每位参与者最多成功一次，首次完成奖励 20 点星光。
- **REQ-FLOW-502 MUST**：星光值只记录参与成长，不兑换、不转赠，也不补充动力值。
- **REQ-FLOW-503 MUST**：大屏显示点亮人数、有效参与人数和百分比，不公开个人星光排名。
- **REQ-FLOW-504 MUST**：重复点击、刷新、并发和重试不得重复点亮或得分。

### 3.6 星际档案

- **REQ-FLOW-601 MUST**：结尾大屏只展示匿名集体星图、激活人数、星光总量、互动次数和等级分布，不展示未来寄语正文。
- **REQ-FLOW-602 MUST**：集体画面和聚合数据不得反向识别具体参与者。
- **REQ-FLOW-603 MUST**：个人档案只向对应参与者展示，可包含星号、互动次数、双值和本人寄语。
- **REQ-FLOW-604 MUST**：Demo v0 完成后已有参与者仍可重新核验查看档案；未激活令牌不得再创建新参与者。
- **REQ-FLOW-605 FORMAL-PENDING**：正式个人档案开放期限不得超过活动后 30 天，实际期限和下载/截图提示后续确认。

## 4. 双值规则

- **REQ-VALUE-001 MUST**：动力值当前工作基线为首次激活后获得 100 点，总量有限，用于节目应援，用完不自动恢复。
- **REQ-VALUE-002 MUST**：星光值当前工作基线上限为 100 点，通过有效互动累计，不作为可消费余额。
- **REQ-VALUE-003 MUST**：两套数值在界面上使用不同名称、图标、颜色和说明。
- **REQ-VALUE-004 MUST**：双值变更由服务端作为唯一可信来源，通过事实或账本记录时间、原因、唯一业务键和结果。
- **REQ-VALUE-005 MUST**：星光值固定上限 100，分配为激活 20、私密寄语 20、星星启动 20、首次送礼 10、首次合规弹幕 10、协同点亮 20。
- **REQ-VALUE-006 MUST**：所有扣减和奖励具备数据库唯一约束及幂等保护；任何重复请求不得造成重复账本记录。

## 5. 公共内容处理

- **REQ-MOD-001 MUST**：弹幕使用 `PUBLISHED`、`REJECTED_BY_RULE`、`REMOVED` 状态；不存在人工预审的 `PENDING/APPROVED` 发布门槛。
- **REQ-MOD-002 MUST**：本地规则拒绝包含敏感词、链接、联系方式、超长或超频内容；拒绝结果必须给出可修正原因且不得广播或奖励。
- **REQ-MOD-003 MUST**：后台支持查看已发布弹幕、单条下屏、屏蔽匿名来源、暂停新弹幕和紧急清屏；下屏内容重连后不得恢复。
- **REQ-MOD-004 MUST**：屏蔽来源后拒绝该匿名参与者的后续弹幕，并默认移除其当前可见内容；不影响其私密档案。
- **REQ-MOD-005 MUST**：未来寄语不是公共内容，不进入该后台模块。
- **REQ-MOD-006 MUST**：AI 审核只保留可替换接口，不调用外部模型、服务或账号。

## 6. 后台与大屏

- **REQ-ADMIN-001 MUST**：后台单页管理运行模式、六阶段、固定节目、已发布弹幕、参与者与入口统计、在线情况、异常状态和确定性重置。
- **REQ-ADMIN-002 MUST**：后台只有一个共用登录账号；所有模块和按钮可见，任何已登录会话可自行取得 `REVIEWER`、`STAGE_CONTROLLER`、`DEMO_ADMIN` 或 `ALL`，服务端仍校验命令需要的当前角色。
- **REQ-ADMIN-003 MUST**：共用账号方案不记录实际操作者姓名；操作记录只包含会话短 ID、当时角色、动作、时间和结果，不得声称提供个人审计。
- **REQ-ADMIN-004 MUST**：模式切换、现场推进、结束、令牌操作、确定性重置和紧急清屏使用普通确认对话框；暂停互动作为安全动作可立即生效。
- **REQ-ADMIN-005 MUST**：运行状态固定为 `mode=REHEARSAL|LIVE`、`status=READY|RUNNING|PAUSED|COMPLETED` 和 `stage=1..6`；排练可跳阶段，现场只能向前推进。`PAUSED` 时拒绝参与者业务写入，但允许读取、恢复和公共内容处置。
- **REQ-SCREEN-001 MUST**：大屏只消费聚合数据、匿名标识和仍处于 `PUBLISHED` 状态的弹幕，不直接读取身份名单、未来寄语、六位 Demo 码或入口令牌。
- **REQ-SCREEN-002 MUST**：大屏断线后自动重连并拉取最新快照，避免重复播放或显示过期节目。
- **REQ-SCREEN-003 MUST**：主控可以暂停实时互动并让大屏进入静态安全场景；备用电脑、预渲染视频与导播链路为 `FORMAL-PENDING`。
- **REQ-SCREEN-004 MUST**：Demo v0 以 1920×1080、浏览器缩放 100% 为大屏基线；正式场地比例、接口和导播链路为 `FORMAL-PENDING`。

## 7. 非功能与现场要求

- **REQ-NFR-001 MUST / G4-EXIT**：使用 300 个合成参与者进行协议级登录、送礼、弹幕、协同点亮和 WebSocket 负载测试；该 G4 专项负载结论不作为 G3 通过条件。D-021 记录的 2026-08-10 提交前 `pnpm verify:g4` 负载已以 300 个固定合成参与者、301 条 WebSocket 连接、300 次激活、1200 次礼物、300 次弹幕和 300 次协同点亮完成并报告 `passed`；G3 小规模 smoke 仍不得作为替代证据。
- **REQ-NFR-002 MUST**：对登录、扣减、得分和提交内容执行幂等、频率限制和服务端校验。
- **REQ-NFR-003 MUST / G3-EXIT**：G3 覆盖 Windows Chrome、Windows Edge、1920×1080 和 `prefers-reduced-motion`；D-021 对应的自动化环境以及项目负责人在 vivo X300 默认浏览器执行的人工核心旅程均已通过，D-021 验收未发现或复现未关闭 S0/S1，并在提交前工作树范围内记录 G3 退出条件通过。真机浏览器版本与实际 CSS 视口未单独采集，作为 D-021 证据限制接受；正式 iPhone、微信、实体 NFC 和场馆网络为 `FORMAL-PENDING`。
- **REQ-NFR-004 MUST / G4-EXIT**：G4 协议级基准中，阶段、礼物、弹幕和协同点亮更新从客户端命令开始到目标端观测权威版本的传播延迟 p95 不超过 2 秒；样本数、p50、p95、最大值、失败率和不变量结果由 G4 负载报告证明。D-021 对应的 Windows loopback 报告中，阶段 20 次为 41.98/46.12/68.07 ms，礼物 1200 次为 1259.31/1426.08/1496.09 ms，弹幕 300 次为 1297.62/1438.55/1447.43 ms，协同点亮 300 次为 850.09/939.64/943.57 ms（依次为 p50/p95/max），失败率均为 0，满足协议专项阈值。主要写入并发为 24，不表示 300 次写请求同一瞬间并发。真实分布式局域网和场馆网络会额外引入传输延迟，其实地测量与裕量为 `FORMAL-PENDING`，不得用 D-021 的 loopback 证据替代。
- **REQ-NFR-005 MUST**：系统日志不得记录真实姓名、学号、完整令牌、六位 Demo 码、Cookie、后台密码、私密未来寄语或完整弹幕正文。
- **REQ-NFR-006 MUST**：Demo v0 只使用固定合成数据，遵循 `DATA_PRIVACY.md`；不得导入真实名单或调用外部 AI/云服务。
- **REQ-NFR-007 MUST**：断线时阻止业务写入，不在客户端排队；重连后先拉权威快照。刷新和服务重启不得丢失已提交状态。
- **REQ-NFR-008 MUST**：确定性重置恢复相同合成身份、令牌、六位 Demo 码、节目和礼物；清除激活、积分、内容、互动、旧会话和运行记录，并增加 `resetEpoch`。
- **REQ-NFR-009 MUST**：正常动画使用 CSS、SVG 或 Canvas；不安装大型动画或 3D 库。减少动态效果时直接显示静态终态，信息不得依赖运动。
- **REQ-NFR-010 MUST**：提供一个根级命令启动本地服务与三端网页，并输出手机入口 URL、二维码、后台 URL、大屏 URL 和共用 Demo 账号提示。
- **REQ-NFR-011 MUST / G3-EXIT**：G3 必须保持 `pnpm --dir frontend build` 与根级 `pnpm verify:g2` 回归通过，并通过根级 `pnpm verify:g3`。D-019 记录的历史独立 G3 证据为退出码 0、278.9 秒、Vitest 16 个文件/102 条与 Playwright 6 场景 × 3 项目 = 18/18。D-021 提交前工作树总验收又以根级 `pnpm verify:g4` 退出码 0、观察总耗时约 463.2 秒重跑扩展全门：Vitest 20 个文件/119 条、Playwright 9 场景 × 3 项目 = 27/27、共享契约/后端/前端生产构建全部通过，浏览器报告 `passed` 且失败检查点 0；自动化部分已满足。CI 仅已配置，尚无远端执行证据。
- **REQ-NFR-012 MUST / G3-EXIT**：`docs/TEST_PLAN.md` 的 34 条三端 P0 必须逐条映射到已有 G2 自动化、G3 浏览器自动化或项目负责人手工证据。D-021 对应的自动化证据与 vivo X300 指定人工项均已通过，D-021 验收未发现或复现未关闭 S0/S1，G3 在 D-021 的提交前工作树范围内收口。
- **REQ-NFR-013 MUST / G3-EXIT**：G3 浏览器测试使用真实本地服务、相对 `/api`、同源 `/ws`、独立临时数据库和固定合成种子；不得用模拟接口替代核心六阶段、会话、幂等、实时恢复或重置事实。

G4 的 `tests/reports/g4-load.json` 还证明：协议错误为 0；服务重启时 301 条连接全部断开并恢复；参与者运行态扇出触发的额外快照请求为 0；重复账本、重复奖励、重复扣减、重复幂等记录、负余额和旧 epoch 污染均为 0；确定性重置、旧会话失效、旧 epoch 重同步和固定凭据再激活通过。该被忽略的脱敏本地报告只证明 Windows loopback 上约 123 秒的完整混合旅程，不是 30 分钟 soak、分布式局域网、场馆或正式上线验收。根级 `pnpm verify:g4` 在 D-021 提交前工作树全门中实际通过，但不绑定任何提交。G0～G4 冻结候选提交形成后，必须在该提交的干净工作树复验，并由 D-022 记录被验收提交的完整 SHA、命令结果与工作树状态；D-022 落地前只能称为冻结候选，不能称为可复现冻结版本，也不扩大上述环境或版本边界。

## 8. G3 最低验收场景

以下场景由 G2 自动化与 G3 浏览器/人工证据共同证明。300 人规模和 p95 指标由已通过的 G4 独立专项报告证明；G3 只证明真实浏览器流程与恢复正确，不能单独作为性能验收依据。

- 使用承载同一合成随机令牌的 NFC/二维码概念入口后，账号、动力值、星光值和个人档案一致；Demo v0 不要求实体写卡。
- 重复轻触、扫码、刷新、超时重试不会重复注册、发分或扣分。
- 私密未来寄语在任何情况下都不会出现在公共大屏；规则拒绝或已下屏弹幕不得显示或在重连后恢复。
- 大屏断线重连后恢复正确节目和聚合数据，不显示姓名、学号或入口令牌。
- 共用后台账号未登录时不能读取管理数据；登录后可自提权并执行相应命令，日志不得伪装为个人归因。
- 排练可跳阶段，现场只能向前推进；过期阶段命令被拒绝。
- 离线写入被阻止，重连、刷新和服务重启后状态一致。
- 确定性重置后旧二维码仍有效，但旧会话必须重新核验。

## 9. 待确认汇总

1. 正式到场规模、节目单、场地、时间和舞台 Cue。
2. 正式真实身份字段、名单来源、访客模式和人工核验。
3. 未来寄语是否在正式版公开，以及授权、录像/直播提示和个人档案期限。
4. 正式公网托管、HTTPS 域名、数据库、第三方服务、备份和数据负责人。
