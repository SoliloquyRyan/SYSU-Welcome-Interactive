# 产品与系统需求（v2 现行）

> 状态：协议 v2 现行。D-056 建立正式单机 HTTPS 部署、仓库外私有持久化、生产启动前验证、SQLite 一致性备份/全新目录恢复与固定合成排练要求。D-055 将 220 人设为正式大屏视觉满场参考，并启用低倾角盘状银河、420 颗无身份底星、未解析盘面光的有界密度补偿、环境层克制呼吸及逐人流星轨道捕获；300 人只保留为技术压力上限。D-054 已授权并导入 220 人受保护名单，正式库与合成测试库隔离，NFC 使用匿名随机令牌，人工恢复支持 8 位真实学号；D-037 的中场抽奖、D-051 的超新星接管、D-052 的通用实体手机门和 D-053 的 Orbital Signal 三端视觉体系继续有效。协议细节与验收口径以 [`PROTOCOL_V2.md`](./PROTOCOL_V2.md) 为权威；视觉细节以 [`VISUAL_GUIDE.md`](./VISUAL_GUIDE.md) 为准。v1 六阶段历史需求已归档。

## 1. 角色

- **Demo 参与者**：固定合成邀请令牌进入 H5；二维码/短链接携带同一令牌；人工协助使用虚构姓名 + 合成学号定位同一身份，不得建立第二账号。
- **共用后台操作会话**：登录后可自提 `REVIEWER`、`STAGE_CONTROLLER`、`DEMO_ADMIN` 或 `ALL`；角色只是能力分组（接受无个人归因风险，D-010）。
- **大屏会话**：只读聚合数据、公开星号/星色、公开弹幕与抽奖公开结果；不读取姓名。
- **项目负责人**：单人维护，负责产品取舍、运行与最终验收。

## 2. 入口与身份

- **REQ-ENTRY-001**：NFC 为主入口、同令牌二维码/短链接为兼容备用；私密写卡映射已生成，正式 HTTPS origin、实体写卡与印刷仍为 `FORMAL-PENDING`。
- **REQ-ENTRY-002**：所有入口进入同一 H5 并恢复同一参与者状态，不得重复发放或生成两个档案。
- **REQ-ENTRY-003**：入口 URL 与 NFC 数据不得包含姓名、学号等个人信息。
- **REQ-ENTRY-004**：页面提供轻触、扫码与人工协助说明。
- **REQ-ENTRY-005**：后台可识别有效/无效/已作废合成入口；令牌操作需 `DEMO_ADMIN`/`ALL` + 确认。
- **REQ-ENTRY-006**：一人一卡一码；同卡 NFC 与二维码编码同一不可猜测随机令牌。
- **REQ-ENTRY-007**：入口 URL 可承载令牌；读取后立即把地址栏与历史项替换为不含令牌的 `/welcome`，不得外传或写日志。
- **REQ-ID-001**：个性 NFC 令牌是主要核验方式；二维码/短链接携带同一 256 位随机令牌。人工协助使用姓名与 8 位学号恢复同一身份，不得生成第二账号；失败信息不得分别泄露姓名或学号是否存在。合成 Demo 通过服务端兼容层接受其 8 位测试学号，客户端不得再补写固定前缀。
- **REQ-ID-002**：正式公开星号必须由独立随机空间生成（现行 `A-0000` 形态）并由数据库唯一约束兜底，不得包含、截取或派生姓名/学号。姓氏首字母 + 学号后四位只属于旧合成 Demo 历史规则，不得用于正式导入。
- **REQ-ID-003**：同一参与者多设备登录共享同一服务端状态。
- **REQ-ID-004**：真实名单来源与核验授权已确认；本次正式目录共 220 人，只导入姓名与 8 位学号，性别/班级不得进入运行库。访客模式与现场碰撞/补卡应急仍为 `FORMAL-PENDING`。
- **REQ-ID-005**：正式库必须是独立 `PROTECTED` 数据库；测试账号只能来自独立合成库，不得进入正式星系、计数、抽奖或后台身份目录。
- **REQ-ID-006**：公开星号、NFC URL、日志、事件、快照与错误不得包含或派生明文学号；“学号→NFC URL”只允许存在于 Git 忽略、最小权限保存的私密映射。

## 3. 协议 v2 要求（V2-MUST，详见 PROTOCOL_V2 对应章节）

### 3.1 版本与权威状态（PROTOCOL_V2 §1/§4.2）

- **REQ-V2-PROTOCOL-001**：命令、快照、响应、事件携带 `protocolVersion=2` 与 `resetEpoch`；v1/v2 不得同实例混用。revision 家族：`runRevision`、`presentationRevision`、`participantRevision`、`aggregateRevision`、`starRevision`、`interactionRevision`；`public|admin|participant:<id>` 三流各自连续 `streamSeq`。
- **REQ-V2-PROTOCOL-002**：合法运行 tuple 只有 `READY+null`、`RUNNING/PAUSED+三场景之一`、`LIVE+COMPLETED+COOPERATIVE_LIGHT`。
- **REQ-V2-PROTOCOL-003**：LIVE 终章由最后场景一次确认、服务端原子写入 `COMPLETED`；REHEARSAL 只能显式预演结尾。
- **REQ-V2-PROTOCOL-004**：`PAUSED` 拒绝参与者写入、允许只读恢复；`COMPLETED` 硬关闭写入；安全处置不含数值调整。
- **REQ-V2-PROTOCOL-005**：管理命令迁移（`SET_MODE` 仅 READY、`START`、REHEARSAL 可跳场景、LIVE 只向前、`PAUSE`/`RESUME`、`COMPLETE`）非法组合稳定拒绝。
- **REQ-V2-PROTOCOL-006**：错误码为 PROTOCOL_V2 §9 的闭合集合，不继承 v1 码。
- **REQ-V2-PROTOCOL-007**：参与者快照含完整个人事实与服务端计算的 `allowedActions`；事件后先刷新快照再启用写入。

### 3.2 参与者入场与晚到者（PROTOCOL_V2 §2）

- **REQ-V2-ONBOARD-001**：激活先原子预留 300 slot 之一，再建会话并发 100 动力 + 20 星光一次；满员以 `STAR_CAPACITY_REACHED` 整笔拒绝。
- **REQ-V2-ONBOARD-002**：`READY`/`RUNNING` 接受新到与晚到者；晚到者完成后直接进入当前场景，不补播。
- **REQ-V2-ONBOARD-003**：锁色即把预留恒星以 `publicStarId` 原子加入公开星系、发 `star.node.upserted` 并直接准入；本人端突出标注，他人无标签。
- **REQ-V2-ONBOARD-004**：手机端、后台和大屏均不提供寄语/时光胶囊入口；旧字段只作迁移兼容，旧写命令稳定拒绝。
- **REQ-V2-ONBOARD-005**：重复、刷新、多设备、断线、并发不重复激活/锁色/入星系/奖励。
- **REQ-V2-ONBOARD-006**：`PAUSED` 不接受入场写入；`COMPLETED` 后本 epoch 已激活身份只读重认证，未完成者不能继续入场。

### 3.3 星系与三场景（PROTOCOL_V2 §3/§4）

- **REQ-V2-GALAXY-001**：协议与渲染技术上限继续为 300 颗真实恒星，正式受保护目录及正式视觉满场参考为 220 人；不得生成携带身份或参与者外观的假星补位，也不得静默截断真实星，slot 从确定性目录预留。无身份中性底星和未解析盘面光只属于装饰环境，不进入快照、计数、聚合或抽奖。
- **REQ-V2-GALAXY-002**：客户端先取权威快照再幂等消费事件；刷新/重连/乱序/重放不制造重复恒星或伪缺口。
- **REQ-V2-SCENE-001**：`ASSEMBLY` 仅一次 `START_STAR`（+40 星光）；`PROGRAM_SUPPORT` 允许礼物/弹幕/抽奖；`COOPERATIVE_LIGHT` 仅一次点亮（+20 星光）；晚到者不补旧场景奖励。
- **REQ-V2-SCENE-002**：presentation 为服务端权威互斥状态 `NONE|RAFFLE|FINALE_PREVIEW`，独立 `presentationRevision`；抽奖只在 `RUNNING + PROGRAM_SUPPORT` 合法。
- **REQ-V2-SCENE-003**：抽奖由服务端在已准入参与者中无放回随机抽取；后台显示姓名+星号，大屏只显示星号；场景变化/暂停/完成自动关闭投影并保留记录，排练模式可清空。
- **REQ-V2-SCENE-004**：大屏恒星含 `started`；聚合至少区分激活/公开恒星/已准入/已启动/点亮/星光总量；后台匿名漏斗不以在线数作分母。
- **REQ-V2-SCENE-005**：`ADVANCE`/`COMPLETE` 的就绪警告合并进一次确认，可明确 override 并审计；权限/旧 revision/非法 tuple 不可 override。
- **REQ-V2-SCENE-006**：抽奖结果持久化并随快照、刷新和重连恢复；同一轮同一身份不得重复中奖。

### 3.4 大屏、OBS 与公共互动（PROTOCOL_V2 §5.2）

- **REQ-V2-SCREEN-001**：大屏技术上最多 300 颗真实恒星，正式视觉以 220 人为满场参考；保持单 Canvas 与稳定槽位，真实星位置不得因当前人数变化而缩放或重排。已公开抵达的恒星在正常可见的 `ASSEMBLY` 从出现首帧起即以逆时针恒星物质流持续运行，且与较慢盘面密度波保持可见相对运动。集结稳态及其离场不得显示当前星数、目标数、`x / 220`、`x / 300`、满员率或到场进度，也不显示编号/星号/排行/头像/可点击节点。
- **REQ-V2-SCREEN-002**：`ASSEMBLY` 使用本地无点源暗星云与程序化尘埃密度纹理。公共真实星严格一人一星，以盘面离散星为主体的低倾角恒星盘呈现并逐颗保留服务端 `displayColor`；中央核球、短棒与两组宽而弱的密度波只作低权重层次，不得读作发光 S 形旋臂、粗线或霓虹轨道。D-055 允许 420 颗固定、确定性、更小更暗的中性色装饰底星及连续未解析盘面光，让 0 人首帧也有可见逆时针流动并增强场馆结构；它们无公开星号、身份、事件或业务语义，不得进入任何人数、快照或聚合。盘面光和底星可按当前真实星数量做最大有界、连续平滑的环境曝光补偿，220 人及以上回到基准，不得生成额外参与者外观；正常模式只允许环境层以多周期低振幅曝光和极小尺度变化形成非同步呼吸，真实星不得同相脉冲，reduced-motion、页面隐藏和静态恢复不保留呼吸。每个页面会话只在实时首次公开一颗此前不存在的真实星时播放一次画外流星，末段沿目标真实星位的逆时针轨道切线被盘面捕获并自然沉入稳定星流；已有星更新、快照、刷新、重连、隐藏恢复和 reduced-motion 不补播。真实星继续使用近白亚像素核心、极薄保色光晕、重尾尺寸/亮度与极少数短衍射芒，禁止统一漂白、硬边彩珠、同半径呼吸或奶油光球。D-048 要求正常等待星流使用稳定 30Hz；到场流星及正常可见的 `ASSEMBLY → PROGRAM_SUPPORT` 高速段以垂直同步 60Hz 为目标，不忙等。WebGL2 与最长边 1280px 的有界后处理缓冲须在首帧显示前预热，静态星云须一次性缓存；页面仍只有一个可见 Canvas。WebGL2 不可用或上下文丢失时回退 Canvas2D，reduced-motion 直接到透明静态终态。`PROGRAM_SUPPORT` 稳态为 OBS 完全透明源，默认不显示网页节目板、背景、标题、星点、礼物或常驻弹幕面板；网页不碰媒体。预渲染视频仅为尚未启用的备选，接入前必须另行通过素材权利、透明/遮罩编码、预载、浏览器/OBS 解码和恢复验收。
- **REQ-V2-SCREEN-002A**：`/welcome` 与 `/screen` 共用午夜蓝 `#01030a`、深空蓝 `#07101f`、信号蓝 `#427eee`、柔蓝 `#7eb0ff`、克制青 `#4adbe9`、星白 `#eef4ff`、暖白 `#ffd79a` 的 Orbital Signal 色谱；大屏只以低权重使用，禁止高饱和霓虹化，参与者逐星 `displayColor` 不得被覆盖。D-049 的黑洞尾段与出口白光具体实现已被 D-051 替换，不再作为当前验收对象。

- **REQ-V2-SCREEN-003**：弹幕 ≤40 字符、单人 3 条/10s、全场 12 条/s，规则拒绝敏感词/链接/联系方式/暂停/屏蔽；Screen 只把实时新的合规正文从右向左短时飘屏，正文不带底条、卡片或边框，节点数量有界且离场销毁，不从快照、刷新、重连或高优先级覆层期间补播；Screen 不含来源，Admin 只取匿名 `sourceId`。
- **REQ-V2-SCREEN-004**：后台可暂停、带原因撤下、屏蔽来源、紧急清屏；`COMPLETED` 后只允许减少公开内容。
- **REQ-V2-SCREEN-005**：礼物事件只含节目/礼物/时间且业务与账本继续生效；D-038 后大屏不渲染礼物视觉。

- **REQ-V2-SCREEN-007**：终章只在实时观察到权威完成时播 5～6 秒；快照已完成/刷新/重连/reduced-motion 直接静态终态。
- **REQ-V2-SCREEN-008**：`/screen` 可按需加载 GSAP core/timeline，只做少量覆层与有界实时弹幕节点的 `transform`/`opacity`；300 星点必须由单 Canvas 绘制；不新增插件、逐星 GSAP 或重型 3D，手机端不迁移 GSAP。隐藏/中断/刷新/重连/reduced-motion 直接进入透明静态终态，减少动态不执行弹幕位移。

### 3.6 三端视觉系统与上线文案（D-053，视觉细节见 VISUAL_GUIDE）

- **REQ-V2-UI-001**：`/welcome`、`/screen` 与 `/admin` 共用 Orbital Signal 基础色谱、语义表面、文字层级、边界、焦点、连接、成功、警告、危险和禁用状态令牌；参与者 `displayColor` 与页面专属 Canvas/WebGL 美术参数不得被共享主题覆盖。
- **REQ-V2-UI-002**：三端共用本机 CJK、display、signal 与 data 字体角色，不下载网络字体；现行共享圆角为 `2/4/8/12px`，手机操作坞与控件继续使用非对称微角。手机关键状态、标签与操作说明不得低于 12px；禁用控件必须有独立文字、边框和表面状态，不能只降低整体透明度。
- **REQ-V2-UI-003**：`/admin` 使用克制的深空运营控制台，首屏优先显示连接、运行 tuple 和主要控制；不得加入持续星流、粒子、强模糊或竞争操作判断的氛围动画。连接、权限、危险操作、抽奖和内容处置必须同时以文字和状态色表达；`NONE` 等内部枚举不得直接展示给操作者。
- **REQ-V2-UI-004**：开发导航只在开发模式出现；站点版本、数据范围和部署范围可由显式 Vite 构建变量覆盖。未配置变量或未完成正式上线门时必须继续显示安全的 Demo/合成数据/非公网默认文案，不得因生产构建自动伪称正式上线。

### 3.7 数值与重置（PROTOCOL_V2 §8/§10）

- **REQ-V2-VALUE-001**：星光 = 激活 20、首次启动星星 40、首次送礼 10、首次合规弹幕 10、协同点亮 20；上限 100。寄语/胶囊不再产生奖励。
- **REQ-V2-VALUE-002**：奖励规则服务端版本化（`rewardRuleVersion`），每行账本保存实际增量与版本。D-037 的 `0013` 合成库迁移删除旧胶囊奖励、把既有 `STAR_STARTED` 调整为 40 并校正累计值；此后不得在运行中热切换规则。
- **REQ-V2-VALUE-003**：后台无扣减/补发入口；安全处置仅删除、屏蔽、清屏或撤下。
- **REQ-V2-RESET-001**：`RESET_DEMO` 需 `DEMO_ADMIN`/`ALL` + 确认 + 合成数据硬门；永不在启动时自动执行。
- **REQ-V2-RESET-002**：普通重置原子进入新 epoch 的 `REHEARSAL+READY+null`；清参与者可变状态，保留固定合成身份、令牌映射、`publicStarId` 与 slot 目录。
- **REQ-V2-RESET-003**：v1→v2 只允许一次性合成数据切换（v2 基础迁移）；失败整体恢复 v1 备份，不混跑。
- **REQ-V2-RESET-004**：已激活的 schema 12 合成库升级至当前 schema 14 时必须停服、显式确认、先写入不覆盖的独立 SQLite 备份，并在单事务内依次应用 `0013`/`0014` 和完整复验；失败回滚并保留备份。启动器不得自动升级或退回 v1 初始化。
- **REQ-V2-RESET-005**：`RESET_DEMO` 与合成升级门只接受 `SYNTHETIC_DEMO`；任何 `PROTECTED` 正式名单库必须硬拒绝，且正式启动器缺库或凭据时不得自动造数。

### 3.8 正式部署、持久化与协作排练（D-056）

- **REQ-DEPLOY-001**：正式基线为单台支持 systemd 的 Linux 主机、单个 Node/Fastify 后端实例和 Caddy HTTPS/WSS 入口；后端只监听 loopback，只信任 loopback 代理，SQLite 不得由多实例、网络共享盘或两个 release 同时写入。
- **REQ-DEPLOY-002**：正式数据库、运行凭据和 NFC 映射必须在 Git/release 目录之外的持久化私有目录中，目录仅服务账号可访问（POSIX 建议 `0700`），文件仅服务账号可读写（建议 `0600`）。代码更新、release 切换或重新克隆不得覆盖该目录。
- **REQ-DEPLOY-003**：正式生产启动必须声明唯一无路径 HTTPS origin，强制 `Secure + HttpOnly + SameSite=Lax` 会话 Cookie，并在监听前验证构建、三项私密资产、`V2_ACTIVE + PROTECTED` 分类、当前 schema/迁移、人数/凭据一致性、仓库外路径和权限；任何失败均停止，不得自动生成、迁移、降级或放宽安全开关。
- **REQ-DEPLOY-004**：正式备份必须使用 SQLite 一致性 backup 机制生成独立快照，和同代运行凭据/NFC 映射组成全新仓库外 bundle，记录逐文件 SHA-256/长度并再次验证数据库。恢复必须先验 checksum 与协议，再物化到全新仓库外目录；禁止覆盖活动目录、直接热复制主库或手工拼接 WAL sidecar。
- **REQ-DEPLOY-005**：备份包仍是明文受保护数据，必须最小权限、使用获批准的加密传输与离机保存、记录保管/恢复/删除责任，并随 T+30 天数据治理范围清理；不得进入 GitHub、Issue、PR、聊天、普通协作盘或测试报告。
- **REQ-DEPLOY-006**：GitHub 只共享代码、迁移、模板与合成证据。协作者使用 `pnpm dev:rehearsal` 创建隔离固定 300 人 `SYNTHETIC_DEMO` 技术目录，界面明确标示合成排练且视觉仍以 220 人为正式参考；该入口不得读取/复制 `.private` 或伪称正式上线。
- **REQ-DEPLOY-007**：systemd 必须以专用非登录账号、`UMask=0077`、只读代码/仅状态目录可写和失败重启守护；上线前另行验证 Caddy 配置、证书、Host/Origin 拒绝、3000 端口不外露、服务重启恢复、正式 NFC、实体手机、OBS/大屏及数据责任。仓库 smoke 不代签实际服务器。
