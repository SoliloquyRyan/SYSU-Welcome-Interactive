## 1. 测试目标

协议 v2 必须重新证明以下事实，而不只是“页面能打开”：

1. 参与者入场时钟与现场运行时钟相互独立：NFC/备用核验成功即激活并进入选色，星色锁定后进入档案决策，提交或明确跳过后才进入服务端当前现场场景。
2. 全场只有 `ASSEMBLY`、`PROGRAM_SUPPORT`、`COOPERATIVE_LIGHT` 三个运行场景；`COMPLETED` 是终态，不存在第六阶段或归档场景。
3. `READY` 和 `RUNNING` 接受新到/晚到者，`PAUSED` 拒绝参与者写入但允许读取恢复，`COMPLETED` 拒绝参与者写入并允许既有参与者只读重认证。
4. 三端共享同一份服务端权威状态；重复点击、超时重试、多设备并发、重连和服务重启不会重复建号、重复星光、重复扣款、产生负余额或倒退终态。
5. 公共星系最多包含 300 颗真实恒星，使用权威快照和幂等 upsert 收敛；不以装饰假星补数量。时光胶囊仅由后台人工触发插入，不改变全局场景或状态。
6. v2 必须重新完成契约、迁移、API、浏览器、300 人协议负载、30 分钟渲染 soak、三端联动和 vivo X300 人工验收；任何 D-022 历史通过数字都不能替代。
7. D-027 正常首次寻星必须使用新鲜邀请、normal-motion 和生产 Vue 页面证明：页面稳定 `visible` 后才开始约 2.8 秒不可跳过镜头，开播后真正进入后台即静态且返回不重播；reduced-motion、刷新和恢复保持静态。D-028 还必须证明同一恒星节点和 `50% / 42vh` 轴贯穿四阶段，100% 帧到选色静态首帧无位置、尺寸、颜色或布局跳变，交接前控件不可用而交接后立即可用。

## 2. 测试原则

- 只使用固定种子中的虚构姓名、合成学号/人工协助备用核验字段、随机令牌、虚构节目和虚拟礼物；NFC 为主入口，二维码/短网址必须承载同一令牌，人工协助备用核验必须映射到同一合成身份。v1 历史用例可保留六位 Demo 码但不得混入 v2 通过结论。
- 不在仓库、截图、录屏、日志或缺陷单中记录真实姓名、学号、手机号、完整令牌、六位 Demo 码、Cookie、口令、私密寄语正文或数据库文件。邀请入口 URL 可按设计承载完整随机令牌，但不得原样进入测试证据；展示证据前必须脱敏。
- 所有业务写命令都必须验证幂等；现场敏感命令同时验证当前权威 revision 与 `resetEpoch`，协议握手必须拒绝 v1/v2 混用。
- 断线期间禁止业务写入，不在浏览器中排队补交；重连后先获取完整权威快照，再接收新事件。
- WebSocket 只广播已经提交的事实。装饰轨迹可丢弃，不得以重放动画代替状态恢复。
- 后台使用共用账号，登录会话可自行取得能力。测试应验证服务端检查当前角色，但不得把该机制描述为个人身份审计或可靠的最小权限。

| 环境 | 用途 | 当前要求 |

## 12. 隐私与安全检查

- D-022 基线：大屏快照、公共 WebSocket、服务端日志及非对应会话响应不得出现姓名、六位 Demo 码、完整令牌、Cookie、密码或旧私密寄语。
- v2 目标：完整学号、身份映射、未选中或已撤下的时光胶囊不得进入大屏、公共事件、日志或非对应会话；公开星号的可关联风险必须如实说明。
- 公共星系事件只包含公开星号/恒星标识、星色、稳定位置与允许公开的聚合字段；自己的高亮与“这是我”映射只能出现在对应参与者会话。
- `COMPLETED` 后只读重认证不得恢复任何未提交草稿，也不得开放参与者写命令；后台安全下屏/清除仍需经过权限、确认和审计边界。
- 参与者本人激活请求可以按入口模式携带令牌或备用核验字段，但这些信息不得进入公共页面、跨会话响应或测试证据。
- 后台与参与者会话使用 `HttpOnly`、`SameSite` Cookie；局域网 Demo 校验 `Origin` 与 `Host`。
- 局域网 HTTP 不提供传输机密性，只能在可信本地网络使用；不得宣称达到正式生产安全等级。
- 输入执行长度、格式、频率和常见注入防护；错误响应不回显敏感值。
- 数据库与本地凭据位于被忽略的运行目录，不进入版本控制。
