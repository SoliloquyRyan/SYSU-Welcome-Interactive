# 迎新晚会互动系统测试计划（初版）

## 1. 目的与范围

本计划用于验证迎新晚会互动系统从实体邀请函入口到手机端、舞台大屏端和后台管理端的完整链路，覆盖：

- `/welcome`：新生手机端 H5；
- `/screen`：舞台大屏展示端；
- `/admin`：现场后台管理端；
- NFC 邀请函、二维码和短链接的一致性；
- 真实 iPhone、安卓手机及微信内置浏览器；
- 网站、现场网络和舞台大屏故障时的三级降级；
- 上线前全流程彩排和恢复验证。

本轮为可执行初版，优先采用人工端到端测试。后续引入自动化测试时，不得降低真实设备、真实场地和彩排要求。

## 2. 测试原则

1. NFC、二维码和印刷短链接必须进入同一个受控 HTTPS URL；允许服务器端统一跳转，但最终路径、环境和页面行为必须一致。
2. NFC 和二维码只是访问入口，身份核验仍由 `/welcome` 的名单匹配完成；普通 NFC 标签不作为防复制门票。
3. 二维码只解决 NFC 不支持、未开启或感应失败，不能解决网站宕机或现场断网。
4. 所有功能测试使用合成数据，例如 `测试新生001`、`test-student-001`；不得导入真实名单，不得在截图、日志或缺陷单中出现真实姓名、学号、手机号或密钥。
5. 管理端写操作、积分补发、内容删除和降级切换只在隔离测试环境或经批准的彩排环境执行。
6. 每个关键场景均需记录测试人、时间、环境、设备、步骤、结果和证据；“页面能打开”不等于端到端通过。

## 3. 通过标准

上线前必须同时满足：

- `/welcome`、`/screen`、`/admin` 的 P0 用例全部通过，且无未关闭的阻断级或严重级缺陷；
- NFC、二维码和短链接的目标 URL 一致，成品邀请函完成“写入—读取—锁定—复测”；
- iPhone Safari、安卓主流浏览器、iOS 微信内置浏览器和安卓微信内置浏览器完成真实设备验证；
- 手机端操作可正确驱动后台状态与大屏展示，重复请求不会重复扣减或重复加分；
- 网站、网络、大屏三级降级均在彩排中实际触发并成功恢复；
- 正式场馆完成至少一次带主持口令、音视频、灯光和主备设备的全流程彩排；
- 测试环境、证据和仓库中不存在真实名单、生产密钥或可复用的管理员凭据。

## 4. 环境与角色

### 4.1 环境

| 环境 | 用途 | 数据要求 |
|---|---|---|
| 本地开发环境 | 页面和基础交互检查 | 仅合成数据 |
| 集成测试环境 | 三端联动、并发和故障注入 | 独立数据库，仅合成数据 |
| 场馆彩排环境 | 大屏、网络、主备机和主持流程 | 专用彩排批次，不得复用真实名单 |
| 生产环境 | 上线前只读检查及正式执行 | 按批准流程导入，禁止把数据复制到测试证据 |

### 4.2 测试角色

- 普通参与者：完成身份激活、寄语、应援、弹幕和互动；
- 临时访客：验证名单不匹配后的降级入口；
- 内容审核员：审核、下架弹幕和寄语；
- 现场主控：切换节目、触发集结、暂停互动和执行降级；
- 观察员：只读查看状态和记录证据；
- 网络与备份人员：切换网络、主备电脑和预渲染素材。

测试账号只使用占位名称和临时凭据。实际凭据由现场负责人通过安全渠道发放，不写入本文件或测试记录。

## 5. 设备与浏览器矩阵

真实设备测试至少覆盖下表。每次执行记录实际型号、系统版本、浏览器或微信版本、网络类型及手机壳情况。

| 类型 | 访问方式 | 必测内容 |
|---|---|---|
| 支持后台 NFC 的 iPhone | NFC、二维码、Safari | 亮屏解锁读取、通知打开、二维码备用、页面返回与重进 |
| 支持 NFC 的安卓手机 | NFC、二维码、系统浏览器或 Chrome | NFC 开关、不同天线位置、浏览器选择、重复贴卡 |
| iPhone 微信 | 二维码、微信内置浏览器 | 登录、表单、动画、WebSocket/轮询、截图保存 |
| 安卓微信 | 二维码、微信内置浏览器 | 登录、表单、动画、WebSocket/轮询、截图保存 |
| NFC 不可用场景 | NFC 关闭、无 NFC 设备或厚手机壳 | 指引是否清楚，能否立即改用二维码和短链接 |
| 舞台大屏电脑 | `/screen`、全屏浏览器 | 目标分辨率、缩放、自动重连、主备源切换 |
| 后台电脑 | `/admin` | 权限、节目控制、审核、监控、降级和恢复 |

网络至少覆盖场馆有线网络、场馆 Wi-Fi、两路不同运营商热点和断网状态。

## 6. NFC 与二维码专项测试

### 6.1 制作前检查

- 使用最终确认的受控 HTTPS 入口，不把临时地址直接写入批量标签；
- NFC 采用标准 NDEF URI，只写入 URL，不写姓名、学号、手机号或密钥；
- 二维码与短链接来自同一个入口地址；
- NFC 感应区避开折痕、裁切线、金属油墨、烫金烫银和磁吸结构；
- 使用最终卡纸、覆膜和装配工艺制作小样，不能只测试裸标签。

### 6.2 成品流程：写入—读取—锁定—复测

每张成品按以下顺序执行并在批次表勾选：

1. **写入**：将统一 HTTPS URL 以 NDEF URI 写入 NFC 标签。
2. **读取**：写入人员用设备读取，核对协议、域名、路径和参数；再扫描同卡二维码，确认 URL 完全一致。
3. **锁定**：确认无误后将标签设置为永久只读；锁定不可逆，错误标签必须隔离，不得混入成品。
4. **复测**：邀请函完成夹芯、覆膜或装袋后，再用另一台设备读取 NFC，并扫描二维码。
5. **抽样交叉测试**：每批抽取成品，在真实 iPhone、安卓和微信浏览器分别打开；发现同类问题时扩大到整批复核。

验收记录至少包含批次号、卡片编号、写入 URL 的非敏感摘要、写入结果、锁定结果、成品复测结果、测试人和时间。不得记录真实个人身份。

### 6.3 异常场景

- NFC 未开启、手机无 NFC、手机壳或磁吸配件干扰；
- 标签空白、写错地址、未锁定、锁定后损坏；
- 二维码反光、低对比、裁切、变形或距离过远；
- NFC 与二维码进入不同环境或不同活动批次；
- URL 多次跳转、证书异常、被浏览器提示风险；
- 页面已下线但实体邀请函仍在流通。

预期：用户始终能看到清楚的备用指引；错误或失效卡片被隔离；活动结束后统一入口可安全转为活动回顾或停止服务提示页。

|---|---|---|---|

| WEL-010 | 弹幕 | 提交正常、超频和测试违规内容 | 频率限制与审核规则生效；未经批准内容不进入公开大屏 |

### 7.2 易用性与安全检查

- NFC 指引、二维码备用入口和加载状态清楚；
- 表单只收集必要字段，错误信息不暴露完整名单；
- 公开页面、浏览器地址和前端日志不出现完整个人信息；
- 关键数值由服务端校验，不信任前端余额或积分；
- 页面在弱网时优先保证身份、节目状态和关键提交，非核心动画可降级；
- 不强制下载 App，不依赖自动播放音频才能完成流程。

## 9. `/admin` 后台测试

| 编号 | 场景 | 操作 | 预期结果 |
|---|---|---|---|
| ADM-001 | 未授权访问 | 未登录或低权限访问 `/admin` | 被拒绝或跳转登录，不返回管理数据 |
| ADM-002 | 权限边界 | 分别以审核员、主控和观察员操作 | 只能执行各自授权动作 |
| ADM-003 | 名单导入 | 导入合成名单，含重复和非法行 | 给出校验结果，不产生静默重复数据 |
| ADM-004 | 节目控制 | 切换节目并重复点击 | 状态只变更一次，手机端和大屏端一致 |
| ADM-005 | 集结控制 | 触发、暂停和切换预渲染 | 操作有确认和当前状态，防止误触发 |
| ADM-006 | 内容审核 | 通过、驳回、下架测试内容 | 队列和大屏同步，保留必要审计记录 |
| ADM-007 | 积分补发 | 对合成用户执行一次补发 | 权限、原因和结果可追踪，不可无限重复 |
| ADM-008 | 监控看板 | 制造在线、失败和断线事件 | 在线人数、失败率、队列和连接状态可见 |
| ADM-009 | 一键暂停 | 暂停弹幕或全部互动 | 手机端收到明确提示，大屏切到安全状态 |
| ADM-010 | 降级与恢复 | 依次切入并退出三级降级 | 当前级别清晰，恢复后数据不重放、不重复计分 |

后台不得在页面、导出文件或日志中显示密钥；管理员会话不得通过公开二维码或 NFC 入口进入。

## 10. 三端联动测试

1. 用多个合成用户从 NFC 和二维码进入 `/welcome`。
2. 完成身份激活和寄语，核对 `/admin` 统计及 `/screen` 激活人数。
3. 由 `/admin` 触发星星集结，核对手机和大屏同步。
4. 切换节目，完成应援、弹幕和互动，核对余额、星光值、审核队列和大屏聚合。
5. 在提交过程中制造重复点击、短时断网和页面刷新，确认操作幂等。
6. 触发结尾寄语和个人档案，确认公共大屏不泄露身份。
7. 分别执行三级降级并恢复，核对系统最终状态。

## 11. 网站、网络、大屏三级降级测试

| 级别 | 触发示例 | 验证动作 | 通过标准 |
|---|---|---|---|
| 一级：网站功能降级 | 动画、弹幕或关键词模块异常，核心站点仍可访问 | 后台暂停非核心功能，切换轻量页面或静态内容 | 登录、节目状态及必要提交仍可用；用户收到明确提示 |
| 二级：网络受限 | Wi-Fi 拥堵、WebSocket 断开或主线路故障 | 切换备用网络，降低刷新频率，改轮询或延迟汇总 | 核心状态最终一致；不重复计分；入口人员可人工核验 |
| 三级：大屏或完全离线 | 主备网页均不可用、视频源故障或场馆断网 | 停止实时互动，切预渲染视频/静态画面，按主持 Cue 继续 | 舞台不断档；纸面信息和人工流程可用；故障期间数据不被错误补记 |

每一级都必须测试“进入降级、保持运行、恢复正常”三个阶段。恢复前先确认服务端状态，再恢复用户入口，最后恢复大屏动态效果。

## 12. 非功能测试

### 12.1 性能与稳定性

- 按预计到场并发的至少 1.5 倍进行压测；测试数据必须为合成数据；
- 重点观察登录、节目切换、应援、弹幕、互动发分、WebSocket 连接和大屏聚合；
- 验证限流、排队、超时、重试和幂等；
- 大屏按整场时长持续运行，并监控 CPU、内存、网络和浏览器状态；
- 性能目标由技术负责人结合场馆网络和服务器配置在上线评审前填写，不在缺少基线时编造数值。

### 12.2 隐私与安全

- 测试仓库、截图、浏览器地址、日志和缺陷单不得出现真实名单或密钥；
- 所有入口使用 HTTPS，不接受证书告警；
- URL 不携带姓名、学号、手机号或可猜测的个人标识；
- 输入、弹幕和寄语验证长度、字符、频率及常见注入风险；
- `/admin` 验证鉴权、最小权限、会话失效和危险操作确认；
- 活动后验证数据导出、留存和删除流程，但删除测试只针对隔离的合成数据。

## 13. 上线前彩排

正式上线前至少完成一次桌面联调和一次场馆全流程彩排。场馆彩排必须包括：

1. 使用正式版邀请函小样，从 NFC 和二维码进入；
2. 多台真实手机同时登录、提交寄语、应援、发弹幕和完成互动；
3. 主持人按正式 Cue 触发星星集结、节目切换和结尾寄语；
4. 大屏使用正式分辨率、接口、主控电脑和备用电脑；
5. 现场主动模拟网站模块异常、主网络断开和大屏主机故障；
6. 执行三级降级并恢复；
7. 记录每个 Cue 的责任人、口令、预计动作和实际结果；
8. 清除彩排合成数据，再进行上线前只读复核。

彩排结束召开 Go/No-Go 评审。未通过 P0 链路、无法降级或无法恢复时，不得以“现场再处理”作为上线结论。

## 14. 缺陷与证据

### 14.1 严重度

- **S0 阻断**：无法登录、错误扣分/加分、后台失控、敏感数据泄露、无法执行降级；
- **S1 严重**：核心流程大面积失败、三端状态明显不一致、主备切换失败；
- **S2 一般**：存在可接受绕行方式的功能或兼容问题；
- **S3 轻微**：不影响流程的文案、视觉或低频问题。

### 14.2 证据要求

- 用例编号、环境、时间、设备和版本；
- 复现步骤、预期、实际结果及恢复方式；
- 必要的截图、录屏或非敏感日志；
- 截图与日志不得包含真实个人信息、令牌、Cookie 或密钥；
- 建议文件名：`用例编号_设备或端_日期时间`，不使用人员姓名。
