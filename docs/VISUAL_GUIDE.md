# 三端视觉与邀请函指南

> 状态：D-037 现行视觉规范。D-030 的约 5.4s/1.0s/4.2s 视觉语言与 D-031/D-032 样式继续作为基线，但寄语停留已移除，锁色确认后直接衔接入轨；节目中场新增个人抽奖层。协议与状态以 [PROTOCOL_V2.md](./PROTOCOL_V2.md) 为单一权威；D-036 及更早证据只覆盖变更前版本。
> 适用范围：`/welcome` 手机端、`/screen` 舞台大屏端、`/admin` 管理端，以及 A6 横版邀请函首轮预览。

## 1. 目标与边界

Issue #5 的旧令牌和组件继续作为基础设施；D-037 将手机端收敛为“身份激活与选色 → 锁色直接准入 → 流动星系中的当前现场场景”，并在 `/admin`/`/screen` 增加中场个人抽奖。D-030 的同一恒星镜头、D-031 的稳定流动星系和学院入口、D-032 的本机字体回退、唯一顶部逐字标题、非对称微角操作坞与本人私有档案交互继续生效。视觉必须服务于进入简单、状态一致、公共内容可处置、故障可恢复和数据最小化。D-032/D-036 的既有自动与人工结果不代签 D-037；vivo X300 当前入场、三端抽奖和 OBS 仍须按实际结果另行记录。

本 Issue 只建立视觉基础设施和占位示例：

- 建立颜色、字体、间距、圆角、组件和动效令牌；
- 提供 `BaseButton`、`BaseCard`、`StatusPill` 的共享表现规则；
- 允许三页做最小公共组件接入，用于证明组件可复用；
- 实现一个纯装饰、低成本、可关闭的环境动效；
- 复杂大屏动画只预留状态和事件接口，不实现完整粒子系统或节目 Cue；
- 不新增登录、身份核验、积分、审核、节目切换、实时连接或数据写入逻辑；
- 不引入大型动画库，不复制去年项目或授权不明的字体、图片、代码和素材。

入口、公开展示和隐私边界以 [PROJECT_CONTEXT.md](./PROJECT_CONTEXT.md)、[REQUIREMENTS.md](./REQUIREMENTS.md)、[DATA_PRIVACY.md](./DATA_PRIVACY.md) 和 [RUNBOOK.md](./RUNBOOK.md) 为准。视觉方向只有在负责人确认并记录到 [DECISIONS.md](./DECISIONS.md) 后，才可视为当前开发基线。

## 2. 设计原则

### 2.1 三端同源、密度有别

- **同源**：三端使用同一套语义颜色、字号阶梯、间距、圆角、焦点样式和状态词。
- **手机端清楚**：单列优先，触控目标足够大，说明简短，不出现横向滚动。
- **大屏端远距可读**：核心数字和状态优先，避免细线、过小文字、滚动区域和高频闪动。
- **管理端可判断**：状态、权限和危险操作必须明确；不能用氛围效果弱化异常信息。
- **降级仍完整**：关闭动画、断开实时链路或切换静态背景后，标题、状态和操作仍可理解。

### 2.2 语义优先于装饰

- 颜色必须表达语义，而不是仅用于“更炫”；同一状态在三端保持同一色义。
- 所有状态都必须有可见文字；图标和颜色只能辅助，不能单独承担信息。
- 动力值与星光值必须使用不同名称、图标、颜色和说明，不得只靠数值区分。
- 大屏只表现聚合、礼物事件、规则通过的已发布弹幕，以及抽奖中奖公开星号；不为姓名、完整学号、内部身份映射、联系方式或入口令牌预留展示位。

### 2.3 原创且可追溯

- 第一版优先使用 CSS、SVG 基础图形和系统字体，不下载来历不明的视觉资源。
- 未取得书面授权前，不使用学院标志图形、去年项目资产、商业字体、图库图片或第三方角色形象。
- 如后续引入外部素材，必须记录名称、来源链接、作者、许可证、允许用途和修改情况。
- D-031 是一项窄范围例外：项目负责人提供并授权白色透明学院 PNG 仅用于 Demo `/welcome` 左上入口；原图保持本地打包、不修改，来源为项目负责人于 2026-08-14 提供，SHA-256 为 `5E665D84994508A6A5BF106EF87A22E0CC443EA63634B5384A310EF3A498C008`，点击目标为学院官方站点 `https://ise.sysu.edu.cn/`。该例外不扩张到其他页面、正式矢量母版、品牌色或线下物料。

### 2.4 D-025 / D-030 / D-031 / D-032 手机端构图

- 目标视口约 390×844，页面外壳不产生纵向滚动；安全区、短视口和软键盘必须纳入布局计算。
- NFC 或备用核验成功即完成身份激活并进入选色；星色锁定事务直接准入并进入服务端当前现场场景。
- 主页面中央是流动星系，不再显示六阶段直线进度。最多 300 颗真实恒星使用服务端稳定位置；自己的恒星突出并在下方显示公开编号，其他恒星不显示标签。
- 每个新视图只保留一个页面级顶部大标题；大标题逐字显现并保留可见光标，下方操作坞只写当前任务的上下文标签，不重复同名标题，也不添加无信息量英文。
- 页面下半部只允许一个克制的高透玻璃操作坞，承载当前场景的主要操作并明显透出星系背景；面板、控件和弹层使用接近直角的非对称微角。禁止玻璃卡片墙、层叠透明面板、通用大圆角和持续动画模糊/滤镜；不支持透明效果时退化为高对比不透明面板。
- 本人档案可以显示私有 `displayName` 和预分配 `personalStarCode`；锁色前的星号不等于公共恒星已存在。姓名不得进入大屏、后台或公共事件，星号只有在锁色后才按既有 `publicStarId` 规则成为公共主键。
- 色温控件必须显示 Kelvin 数值、当前位置和清晰焦点，并向辅助技术暴露完整名称和值；用户选色不设倒计时。
- 正常首次核验成功、服务端明确返回新建身份与 `NEEDS_COLOR` 后，先等待页面稳定 `visible`，再参考 D-030 播放约 5.4 秒沉入、接近与捕获；权威锁色并返回 `ADMITTED` 后，参考约 1.0 秒完成同一恒星色温闪烁并直接衔接约 4.2 秒拉远入轨。中间不显示寄语/胶囊页；正常首次流程不提供动画跳过按钮，手机端不迁移 GSAP。
- 寻星、选色、锁色确认和入轨共用同一颗持久恒星与同一坐标系。正式页与认可预演使用同一生产渲染器，可组合经压缩验收的本地原创星云纹理、前/中/后 Canvas 合成层、局部颗粒和确定性本机轨道尘；不得让 DOM 星消失后再以 Canvas 圆环或另一颗星冒充连续交接。
- 选色和主场景控件可以提前渲染，但在对应权威状态到达前保持 `inert`、不可聚焦和不可操作；视觉时间线只能消费权威事实，不得触发或延迟锁色、准入或实时连接。
- 开播前暂不可见时等待；开播后进入后台或被中断则立即收束到权威静态终态且返回不重播。返回、刷新、断线恢复、失败、超时和 `prefers-reduced-motion: reduce` 也直接显示静态终态。
- 普通成功提示约 3.5 秒后收回并由页面持久状态接替；错误、离线、暂停和已结束提示持续显示。退出每次确认，草稿只存当前内存并按完成、退出、会话重置及场景离开规则清理。
- 正常状态不显示“实时同步”、裸露的 `RUNNING`、六阶段编号或常驻身份/数值行；异常状态保留清楚文字。
- 怀士堂线稿、旧 1.8/0.6 秒可跳过转场和 D-024 的约 0.9 秒首帧可跳过均为历史方向，不进入 v2。

令牌定义在 `frontend/src/styles/tokens.css`。新代码使用语义名称；旧页面继续通过兼容别名工作。颜色不得在组件中重复散落为无说明的十六进制值。

- 协议 v2 的 `/welcome` 只在底部操作坞使用半透明表面；其余主体不堆叠玻璃卡片，并必须提供不透明降级色。

### 3.2 字体与字号

第一版不加载网络字体，也不把设备是否安装任一指定字体当作交付条件。D-032 采用四组仅由本机/系统字体组成的渐进回退栈：

```css
:root {
  --font-stack-cjk: "HarmonyOS Sans SC", "OPPO Sans", MiSans, "vivo Sans",
    "Noto Sans SC", "Source Han Sans SC", "PingFang SC", "Microsoft YaHei UI",
    system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif;
  --font-stack-display: "Cascadia Code", "Cascadia Mono", "Microsoft YaHei UI",
    ui-monospace, monospace;
  --font-stack-signal: Bahnschrift, "Aptos Display", "Segoe UI Variable Display",
    Inter, system-ui, sans-serif;
  --font-stack-data: Bahnschrift, "Cascadia Mono", "SFMono-Regular", Consolas,
    ui-monospace, monospace;
}
```

`--font-stack-display` 只用于页面级大标题和极少量星际信号文字，以等宽骨架表达中文代码终端气质；本轮不采用像素游戏字体，也不使用难以辨认的装饰位图字。中文正文、按钮和表单使用 `--font-stack-cjk`，关键短标签可使用 `--font-stack-signal`，编号和数值使用 `--font-stack-data`。任一前置字体缺失时必须无闪断地落入后续系统字体；不得联网下载、从去年项目复制或捆绑未获准的中文字库或其他字体文件。

| 层级 | 建议令牌 | 大小 / 行高 | 用途 |
|---|---|---|---|
| 辅助 | `--font-size-xs` | `0.75rem / 1.5` | 标签、时间、次要元信息 |
| 小号 | `--font-size-sm` | `0.875rem / 1.55` | 状态、按钮辅助文字 |
| 正文 | `--font-size-md` | `1rem / 1.7` | 正文和表单说明 |
| 强调 | `--font-size-lg` | `1.125rem / 1.55` | 面板上下文、重要说明 |
| 小标题 | `--font-size-xl` | `1.5rem / 1.3` | 分区标题 |
| 页面标题 | `--font-size-2xl` | `clamp(2rem, 6vw, 4.7rem) / 1.06` | 三端首要标题 |

正文默认字重 400–500，标签和按钮 600–700，超大数字不超过 700。中文正文不使用强制大写或过宽字距；英文只在具有真实语义时保留，短标签可使用有限字距。

`/welcome` 进入新视图时，只让唯一的页面级顶部标题按字符依次显现，并在末尾保留可见光标；“找到属于你的星”也遵守该规则。操作坞、档案和弹层不得再重复同一句大标题，只能使用较低层级的上下文标签。字符动画是纯表现：辅助技术直接获得完整标题，页面隐藏、刷新、重连、失败恢复和 `prefers-reduced-motion: reduce` 直接显示完整静态文本；静态路径的光标不得持续闪烁，标题完成也不能触发、延迟或伪造业务状态。

## 5. 公共组件

### 5.1 `BaseButton`

第一版用于原生按钮，不承担路由链接多态和业务权限判断。

- 变体：`primary`、`secondary`、`ghost`、`danger`。
- 尺寸：`sm`、`md`、`lg`；默认 `md`。
- 默认触控尺寸不小于 44 × 44px；手机端主操作可占满容器宽度。
- 必须透传原生 `type`、`disabled`、`aria-*` 和事件。
- `disabled` 不可点击且保留可读标签；不能只用降低透明度模拟禁用。
- 加载状态保留原标签并增加忙碌标记，设置 `aria-busy`；本 Issue 仅做视觉能力，不发起请求。
- 键盘 `:focus-visible` 使用 3px 暖金色轮廓和 3px 外偏移，不得移除。
- 危险按钮必须写明动作，例如“清屏”，不能只显示无语义图标。

### 5.2 `BaseCard`

- 默认是普通信息容器，可通过 `as` 保留 `div`、`article`、`section` 或 `ul` 等正确语义。
- 变体：`glass`、`solid`、`outline`；不得把所有卡片都做成强光和重阴影。
- `/welcome` 的 v2 主场景不得用 `glass` 变体搭建卡片墙；液态玻璃只属于单一底部操作坞。
- 大屏与管理端默认使用弱边框、面板色和 `--radius-lg`，大屏指标卡可使用 `--radius-xl`；`/welcome` 的操作坞和档案项按 D-032 使用 `--shape-*` 微角令牌。
- 交互卡片必须使用真正可聚焦的按钮或链接，不能仅给 `div` 添加点击事件。
- 标题、正文、状态和操作区应有稳定顺序；装饰层设置 `pointer-events: none`。

### 5.3 `StatusPill`

状态胶囊必须始终显示文字；图标与颜色只作辅助。

| 状态 | 建议色调 | 说明 |
|---|---|---|
| 演示数据、信息 | `info` | 说明当前为占位或模拟状态 |
| 待开发、已下屏 | `neutral` | 非错误、当前不活动 |
| 暂停、重连中、已降级 | `warning` | 需要注意或等待处理 |
| 通过、在线、已完成 | `success` | 成功或正常可用 |
| 拒绝、离线、失败 | `danger` | 错误、停止或危险状态 |

静态说明不默认设置 `role="status"`。只有未来真实动态状态变化时，才按业务场景决定是否使用 live region，避免屏幕阅读器重复播报。

## 6. 三端差异

### 6.1 `/welcome` 手机端

- 以 320px 为最小支持宽度，主要检查宽度为 390px；单列优先。
- 页面必须可读、按钮可点、无横向溢出；约 390×844 下页面外壳不得纵向滚动，节目单内部滚动除外。
- 每个新视图只突出一个主要任务和一个顶部逐字标题；标题完成后保留可见光标，下方操作坞不得重复同名标题。减少动态、页面隐藏和恢复路径直接显示完整静态标题。
- NFC 个性入口为主，二维码/短网址承载同一随机令牌。退出确认会撤销当前会话并回到人工重新认证界面；该界面只收“学生姓名 + 恰好 8 位学号后缀”，当前合成 Demo 由客户端补固定前缀 `2026` 后调用既有人工协助激活接口。格式错误不发送请求，核验失败使用通用提示；成功必须恢复同一合成身份与档案，不能生成第二个参与者，也不能声称接入了真实学生名册。
- 入场视图以“找到属于你的星”为唯一顶部标题，并配合本人私有姓名、预分配星号和迎新晚会欢迎语；`displayName` 和预锁色阶段的 `personalStarCode` 只可出现在本人已认证页面。锁色前不得把该星号表现为公共恒星已建立；姓名和完整学号不得进入 `/screen`、`/admin`、公共事件、埋点或错误文案。
- 选色锁定后直接进入当前现场场景；晚到者不绕过核验与选色顺序。
- 主场景保留星系与一个底部操作坞；只有自己的恒星显示公开编号，其他恒星不显示标签。
- 星际档案按“档案者姓名 → 星星编号 → 星色 → 动力 → 星光”的信息顺序展示，不增加“已完成入场”等可由页面状态推断的冗余行，也不保留寄语/胶囊空位。动力解释为赠送虚拟礼物的可消费额度；星光解释为由服务端权威奖励累积、不可消费或兑换的个人成长记录。两项使用可点击、可聚焦的解释触发器和单一临时浮层，不使用 hover-only 交互。
- 下半部只有一个高透、非对称微角操作坞，背景星系仍可见；退出采用无普通边框的科技括角提示。高透、括角和微角不能牺牲文字对比、焦点或触控面积。
- 不依赖自动播放音频或环境动效完成流程。
- 使用 `100dvh` 时保留 `100vh` 回退，并考虑刘海屏安全区。
- 非核心动画在弱网或减少动态效果模式下直接关闭。
- 成功提示可自动收回，异常提示不可自动消失；退出始终确认，内存草稿按 D-025 的清理点清除。

### 6.2 `/screen` 舞台大屏端

- 第一版以 1920 × 1080、16:9 全屏作为视觉检查基线；这不是正式场馆规格。
- 背景可铺满视口，关键信息保持安全边距；不得出现浏览器控件、滚动条、裁切、黑边或文字溢出。
- 以最多 300 颗真实恒星组成的流动星系为主视觉，使用服务端稳定位置和幂等 upsert；不生成假恒星填充画面。常规星系不显示参与者编号/星号，也不允许点击单星；只有活动抽奖层可以显示中奖公开星号。
- 远距阅读优先：当前场景、连接与降级状态使用更高字号和明确标签；全场只运行 `ASSEMBLY`、`PROGRAM_SUPPORT`、`COOPERATIVE_LIGHT` 三个场景。
- 不展示个人排行、完整身份、中奖者姓名、内部身份映射、规则拒绝或已下屏内容。
- 抽奖只能由后台在 `RUNNING + PROGRAM_SUPPORT` 开启，不改变全局场景或运行状态；`COMPLETED` 后不再新抽取。
- 实时效果异常时必须能隐藏动效层并切换静态背景、简化布局或预渲染素材。
- LIVE 结束画面只投影服务端已确认的终态；REHEARSAL 的 finale 只允许显示持续可见的“排练预览”标记，不写 live `COMPLETED`。动画完成不得反向触发业务结束。
- `PROGRAM_SUPPORT` 作为 OBS 透明浏览器源：中心留给导播节目视频，网页只在左右边缘约 15%～20% 保留弱星点，并叠加匿名弹幕与有限礼物效果。网页不拥有媒体、不输出音频，不渲染节目占位黑底。
- 礼物采用“一个主礼物 + 一个次礼物”的稳定上限；1.5 秒同类事件只合并视觉计数，星舰可突出但不可形成持续挡屏。弹幕最多保留 8 条快照摘要；实时飞行层不显示作者、头像、编号或来源。
- 抽奖层独占舞台画面；隐藏期间到达的弹幕/礼物不补播。视觉优先级为终态、排练终章、抽奖、故障、场景、互动，越高层必须清理越低层的临时动画。normal-motion 可为新中奖结果提供一次克制揭晓；reduced-motion 与重连直接显示持久结果。

### 6.3 `/admin` 管理端

- 信息密度可高于手机端，但沿用同一颜色、间距、圆角和状态语义。
- 已发布、规则拒绝、已下屏、来源屏蔽及连接/降级状态必须清晰可扫读。
- 危险操作、暂停、清屏、抽奖清空等控件必须有文字、确认和权限边界；抽奖开启/抽取/关闭与排练清空的状态差异必须可扫读。
- 窄屏时列表内容允许自然换行，中间内容设置 `min-width: 0`，不得因状态胶囊造成横向溢出。
- 管理员凭据、令牌和真实名单不得出现在页面、截图或演示数据中。

## 7. 动效系统

动效数值令牌定义在 `frontend/src/styles/tokens.css`，关键帧、动效工具类与降级规则定义在 `frontend/src/styles/motion.css`。只动画 `transform` 和 `opacity` 等低成本属性，避免循环改变布局、滤镜或大面积阴影。D-026 允许 V2-07 `/screen` 动态加载 GSAP core 编排少量 DOM 覆层；恒星仍由单 Canvas 绘制，禁止逐星 GSAP 和任何插件。

| 令牌 | 第一版值 | 用途 |
|---|---:|---|
| `--motion-duration-fast` | `140ms` | 按压、悬停、焦点反馈 |
| `--motion-duration-base` | `220ms` | 普通状态变化 |
| `--motion-duration-slow` | `420ms` | 卡片或区域进入 |
| `--motion-duration-ambient` | `24s` | 环境层低速漂移 |
| `--motion-ease-standard` | `cubic-bezier(0.2, 0, 0, 1)` | 常规过渡 |
| `--motion-ease-emphasized` | `cubic-bezier(0.2, 0.8, 0.2, 1)` | 单次强调，不用于无限循环 |

### 7.1 四层方案

1. **组件反馈层**：按钮、链接和焦点的 140–220ms 反馈。状态变化后立即结束，不阻塞输入。
2. **页面状态层**：卡片出现、区域切换和数据刷新，220–420ms。进入、暂停、完成、失败必须有文字状态。
3. **环境氛围层**：低透明度星点或光晕以 18–30 秒周期缓慢漂移。纯装饰、`aria-hidden="true"`、`pointer-events: none`，三端只挂载一份。
4. **舞台场景层**：星星集结、节目互动和协同点亮分别映射 `ASSEMBLY`、`PROGRAM_SUPPORT`、`COOPERATIVE_LIGHT`；`COMPLETED` 是终态而非第四个场景。抽奖是节目支持阶段的 presentation，动画不得决定中奖者、推进状态机或触发结束。

### 7.2 减少动态效果

必须支持 `prefers-reduced-motion: reduce`：

- 环境层停止循环动画和位移，但可保留静态、低透明度背景；
- 页面进入和组件过渡立即完成，不使用闪烁、缩放或视差；
- 状态变化继续通过文字、颜色和布局即时呈现；
- 不把无限动画简单压缩到 `0.01ms`，以免形成高频循环；应明确设置 `animation: none`；
- 所有核心流程在完全无动画时仍可使用。

### 7.3 v2 手机端动效与反馈

- 正常首次流程采用 D-037 的受控个人旅程：新身份核验后、页面稳定可见才开始约 5.4 秒寻星，权威锁色并直接准入后参考约 1.0 秒闪烁并衔接约 4.2 秒拉远入轨，不出现寄语停留。
- 开播后真正进入后台或被中断时立即收束且返回不重播；返回、刷新、重连、失败、超时和减少动态效果路径不播放叙事时间线，直接渲染同一权威静态终态。
- 本机装饰星云、颗粒和轨道尘只负责氛围，不代表参与者数量；真实恒星事实只来自服务端。动画实现应优先使用合成友好的变换、透明度与单 Canvas 绘制，不得靠持续动画模糊、滤镜或大阴影制造液态玻璃。
- 普通成功提示的 3.5 秒收回是展示行为，不删除服务端事实；异常提示持续显示，直到权威状态恢复。

### 7.4 D-030 个人恒星连续镜头

- **视觉基线**：`motion-previsual-personal-star/personal-star-journey-animatic.webm`、同目录预演和十张关键帧保留沉入、接近、捕获、闪烁与拉远入轨的镜头语言；其中寄语停留已被 D-037 删除，不能照搬旧时间线。
- **持久主体**：从寻星首帧到选色、锁色确认及入轨只追踪同一颗本人恒星；表现载体可以跨 DOM/Canvas 层合成，但必须共享坐标、尺寸、颜色和运动轨迹，任何交接帧都不能闪断或跳位。
- **连续镜头**：速度、景深、星云层与轨道层在阶段边界互相覆盖，镜头由向前接近自然转为向后拉远；不得用互不相关的淡出/淡入、突然缩放或选中圆环替代真实连续运动。
- **无障碍交接**：后续文案与控件可预渲染，交接前 `inert`、不可聚焦和不可操作，权威状态与安全表现门都满足后立即可用。实时连接、快照和服务端允许动作不等待动画。
- **静态同构**：隐藏、中断、刷新、恢复、失败与 reduced-motion 都直接使用相应权威阶段的同构静态结构，不闪播、不补播，也不依赖视觉层取得业务结果。

### 8.2 正面信息层级

1. 活动/学院文字标识；未授权前只用文字，不描摹官方标志。

5. 不显示学号、班级、邀请码、入口令牌或可反推个人身份的编号。

### 8.3 背面入口层级

按兼容优先级展示三种进入方式：

1. **轻触 NFC**：主入口；
2. **扫描二维码**：NFC 不支持、未开启或识别失败时使用；
3. **输入短网址**：无法轻触或扫码时手动进入。

三者必须指向同一个占位 `/welcome`。第一版使用保留的无效域名 `https://welcome.example.invalid/welcome`，并在图面标注“示例入口 / 不可用于正式活动”。二维码不能被描述为网站宕机或现场断网的备用方案。

### 8.4 NFC 与二维码制作规则

- NFC 视觉触点避开折痕、裁切线、金属油墨、烫金烫银和磁吸结构。
- 视觉标记不等于最终标签位置；实际位置需结合标签、纸张、覆膜和装配小样测试。
- 本轮预览使用明确标注“二维码占位｜不可扫描”的非标准方块纹理，且不绘制标准定位图形，避免被误当作正式入口；正式二维码另行生成后须保持正方形、高对比、无拉伸并保留完整静区。
- 正式二维码、短网址和 NFC NDEF URI 必须来自同一受控 HTTPS 入口，并按“写入—读取—锁定—成品复测”验收。
- 普通 NFC 标签只是访问入口，不得在邀请函上宣称其本身完成身份认证或防复制。

### 8.5 占位数据与素材授权

- 第一版背景、轨道、星点和 NFC 图标使用原创 SVG 基础图形或 CSS 绘制。

## 9. 可访问性基线

- 普通正文与背景对比度目标不低于 4.5:1；大号文字及关键图形目标不低于 3:1。
- 所有交互元素具有可见 `:focus-visible` 样式，键盘顺序与视觉顺序一致。
- 手机端触控目标不小于 44 × 44px，相邻危险与普通操作保持足够间距。
- 状态、错误、成功和连接情况必须有文字，不得仅以颜色、闪烁或位置表达。
- 装饰组件使用 `aria-hidden="true"`，不能拦截鼠标、触摸或键盘操作。
- 使用原生按钮、链接和标题层级；禁止用不可聚焦的普通容器模拟控件。
- 禁用状态必须使用原生 `disabled`；动态忙碌状态需提供可理解的文本。
- 逐字标题必须向辅助技术暴露一次完整标题，不得逐字触发 live region；减少动态和恢复路径直接呈现完整标题，静态光标不循环闪烁。
- 动力与星光解释触发器使用原生按钮并提供 `aria-expanded`、`aria-controls` 和可关联说明；浮层打开时使用单一 `role="tooltip"`，按 `Escape`、切换到另一项或移出相关焦点范围均可关闭，焦点留在触发按钮上。
- 320px 宽度不得横向溢出；200% 缩放后主要内容和操作仍可访问。
- 不使用高频闪烁、快速视差、自动播放音频或必须依赖动画才能理解的提示。
