> 状态：共享组件与邀请函历史基线；协议 v2 的三端视觉方向由 D-025、D-027、D-028、D-029 与 `PROTOCOL_V2.md` 覆盖

## 1. 目标与边界

Issue #5 的旧令牌和组件继续作为基础设施；D-025 将手机端收敛为“身份激活与选色 → 档案决策 → 流动星系中的当前现场场景”，D-027 将首次寻星修订为稳定可见后约 2.8 秒的 Vue+CSS 穿越镜头，D-028 在项目负责人真机否决首版视觉连续性后冻结同一恒星、统一视觉轴与四阶段径向穿越系统，并将大屏收敛为最多 300 颗真实恒星组成的公共星系。视觉必须服务于进入简单、状态一致、公共内容可处置、故障可恢复和数据最小化，不能遮盖状态、降低可读性或暗示尚不存在的业务能力。V2-08 已把 `/welcome` 与 `preview:mobile` 检查器迁移到真实临时 v2 栈并形成桌面 Chrome 手机视口证据；D-028 自动连续性子门已通过，vivo X300 当前版本的新鲜邀请视觉签核、三端局域网与 OBS 复验仍为 `PENDING`。

本 Issue 只建立视觉基础设施和占位示例：

- 建立颜色、字体、间距、圆角、组件和动效令牌；
- 提供 `BaseButton`、`BaseCard`、`StatusPill` 的共享表现规则；
- 允许三页做最小公共组件接入，用于证明组件可复用；
- 实现一个纯装饰、低成本、可关闭的环境动效；
- 复杂大屏动画只预留状态和事件接口，不实现完整粒子系统或节目 Cue；
- 不新增登录、身份核验、积分、审核、节目切换、实时连接或数据写入逻辑；
- 不引入大型动画库，不复制去年项目或授权不明的字体、图片、代码和素材。

入口、公开展示和隐私边界以 [PROJECT_CONTEXT.md](./PROJECT_CONTEXT.md)、[REQUIREMENTS.md](./REQUIREMENTS.md)、[DATA_PRIVACY.md](./DATA_PRIVACY.md) 和 [RUNBOOK.md](./RUNBOOK.md) 为准。视觉方向只有在负责人确认并记录到 [DECISIONS.md](./DECISIONS.md) 后，才可视为当前开发基线。

## 2. 设计原则

### 2.1 三端同源、密度有别

- **同源**：三端使用同一套语义颜色、字号阶梯、间距、圆角、焦点样式和状态词。
- **手机端清楚**：单列优先，触控目标足够大，说明简短，不出现横向滚动。
- **大屏端远距可读**：核心数字和状态优先，避免细线、过小文字、滚动区域和高频闪动。
- **管理端可判断**：状态、权限和危险操作必须明确；不能用氛围效果弱化异常信息。
- **降级仍完整**：关闭动画、断开实时链路或切换静态背景后，标题、状态和操作仍可理解。

### 2.2 语义优先于装饰

- 颜色必须表达语义，而不是仅用于“更炫”；同一状态在三端保持同一色义。
- 所有状态都必须有可见文字；图标和颜色只能辅助，不能单独承担信息。
- 动力值与星光值必须使用不同名称、图标、颜色和说明，不得只靠数值区分。
- 大屏只表现聚合、礼物事件、规则通过的已发布弹幕，以及后台人工选中的时光胶囊；不为完整姓名、完整学号、未选中正文、联系方式或入口令牌预留展示位。

### 2.3 原创且可追溯

- 第一版优先使用 CSS、SVG 基础图形和系统字体，不下载来历不明的视觉资源。
- 未取得书面授权前，不使用学院标志图形、去年项目资产、商业字体、图库图片或第三方角色形象。
- 如后续引入外部素材，必须记录名称、来源链接、作者、许可证、允许用途和修改情况。
- D-031 是一项窄范围例外：项目负责人提供并授权白色透明学院 PNG 仅用于 Demo `/welcome` 左上入口；原图保持本地打包、不修改，来源为项目负责人于 2026-08-14 提供，SHA-256 为 `5E665D84994508A6A5BF106EF87A22E0CC443EA63634B5384A310EF3A498C008`，点击目标为学院官方站点 `https://ise.sysu.edu.cn/`。该例外不扩张到其他页面、正式矢量母版、品牌色或线下物料。

### 2.4 D-025 / D-027 / D-028 手机端构图

- 目标视口约 390×844，页面外壳不产生纵向滚动；安全区、短视口和软键盘必须纳入布局计算。
- NFC 或备用核验成功即完成身份激活并进入选色；星色锁定后进入档案提交/跳过决策，完成决策才进入服务端当前现场场景。
- 主页面中央是流动星系，不再显示六阶段直线进度。最多 300 颗真实恒星使用服务端稳定位置；自己的恒星突出并在下方显示公开编号，其他恒星不显示标签。
- 页面下半部只允许一个克制的液态玻璃操作坞，承载当前场景的主要操作；禁止玻璃卡片墙、层叠透明面板和持续动画模糊/滤镜。不支持时退化为高对比不透明面板。
- 色温控件必须显示 Kelvin 数值、当前位置和清晰焦点，并向辅助技术暴露完整名称和值；用户选色不设倒计时。
- 正常首次核验成功、服务端明确返回新建身份与 `NEEDS_COLOR` 后，先等待页面稳定 `visible`，再以约 2.8 秒 Vue+CSS+低 DOM SVG 的 `transform`/`opacity` 穿过星云、聚焦并找到中性恒星；权威星色锁定且快照到达后，以约 1.2 秒点亮个人恒星并拉远到星系。正常首次流程不提供跳过按钮，手机端不迁移 GSAP。
- 寻星电影与选色静态态共用一颗持久恒星，横向轴为 `50%`、纵向轴为 `42vh`。镜头覆盖完整可用舞台，不使用圆形裁切“徽章”；背景只用少量 SVG 径向速度线表达同一前进方向，恒星由同心白核、中性光晕与默认 `5800K` 色温光晕构成。
- 四阶段依次为 0%～18% 建立/加速、18%～62% 连续穿越、62%～82% 减速/捕获、82%～100% 锁定/交接。选色文案和控件提前渲染但保持 `inert`、不可聚焦；100% 帧与选色静态首帧必须视觉相同，只解除交互隔离，不替换节点或改变恒星几何与颜色。
- 开播前暂不可见时等待；开播后进入后台或被中断则立即收束到权威静态终态且返回不重播。返回、刷新、断线恢复、失败、超时和 `prefers-reduced-motion: reduce` 也直接显示静态终态。
- 普通成功提示约 3.5 秒后收回并由页面持久状态接替；错误、离线、暂停和已结束提示持续显示。退出每次确认，草稿只存当前内存并按完成、退出、会话重置及场景离开规则清理。
- 正常状态不显示“实时同步”、裸露的 `RUNNING`、六阶段编号或常驻身份/数值行；异常状态保留清楚文字。
- 怀士堂线稿、旧 1.8/0.6 秒可跳过转场和 D-024 的约 0.9 秒首帧可跳过均为历史方向，不进入 v2。

## 3. 设计令牌

令牌定义在 `frontend/src/styles/tokens.css`。新代码使用语义名称；旧页面继续通过兼容别名工作。颜色不得在组件中重复散落为无说明的十六进制值。

### 3.1 颜色

| 语义令牌 | 第一版值 | 用途 |
|---|---:|---|
| `--color-bg-canvas` | `#071225` | 页面主背景 |
| `--color-bg-deep` | `#06101e` | 深色渐变端、沉浸背景 |
| `--color-surface-panel` | `rgba(11, 28, 55, 0.78)` | 通用半透明卡片 |
| `--color-surface-raised` | `rgba(18, 42, 76, 0.92)` | 强调面板、悬浮层 |
| `--color-text-primary` | `#eaf2ff` | 主标题、正文重点 |
| `--color-text-secondary` | `#9fb0cc` | 辅助说明、元信息 |
| `--color-border-subtle` | `rgba(149, 178, 225, 0.20)` | 卡片边框、分隔线 |
| `--color-brand-primary` | `#5c89ff` | 主行动、品牌蓝 |
| `--color-brand-cyan` | `#61d9ff` | 信标、信息和星光高亮 |
| `--color-accent-warm` | `#ffd071` | 焦点、提醒和暖色强调 |
| `--color-success` | `#71e6b1` | 成功、通过、在线 |
| `--color-warning` | `#ffd071` | 注意、暂停、重连中 |
| `--color-danger` | `#ff8e9f` | 拒绝、离线、危险操作 |
| `--color-neutral` | `#9fb0cc` | 待开发、已下屏、中性状态 |

使用规则：

- 正文默认使用 `--color-text-primary`，长段说明使用 `--color-text-secondary`。
- 主操作使用品牌蓝；危险操作只能使用危险色，不以品牌色伪装。
- 暖金色同时承担键盘焦点和注意状态时，必须配合文字或图标避免歧义。
- 动力值首轮使用暖金方向，星光值首轮使用青色方向；最终图标和色值待产品负责人确认。
- 邀请函可使用同一冷暖关系，但印刷前必须根据纸张和打样结果重新校色。
- 协议 v2 的 `/welcome` 只在底部操作坞使用半透明表面；其余主体不堆叠玻璃卡片，并必须提供不透明降级色。

### 3.2 字体与字号

第一版不加载网络字体，也不把本机是否安装 `Inter` 当作交付条件。沿用当前回退栈：

```css
font-family: Inter, "Noto Sans SC", "PingFang SC", "Microsoft YaHei",
  ui-sans-serif, system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif;
```

`Inter` 仅在设备已安装时使用；中文正文必须能稳定回退到系统无衬线字体。不得从去年项目复制字体文件。

| 层级 | 建议令牌 | 大小 / 行高 | 用途 |
|---|---|---|---|
| 辅助 | `--font-size-xs` | `0.75rem / 1.5` | 标签、时间、次要元信息 |
| 小号 | `--font-size-sm` | `0.875rem / 1.55` | 状态、按钮辅助文字 |
| 正文 | `--font-size-md` | `1rem / 1.7` | 正文和表单说明 |
| 强调 | `--font-size-lg` | `1.125rem / 1.55` | 卡片标题、重要说明 |
| 小标题 | `--font-size-xl` | `1.5rem / 1.3` | 分区标题 |
| 页面标题 | `--font-size-2xl` | `clamp(2rem, 6vw, 4.7rem) / 1.06` | 三端首要标题 |

正文默认字重 400–500，标签和按钮 600–700，超大数字不超过 700。中文正文不使用强制大写或过宽字距；英文短标签可使用有限字距。

### 3.3 间距

采用 4px 基准阶梯：

| 令牌 | 值 | 常见用途 |
|---|---:|---|
| `--space-1` | `4px` | 图标内部微调 |
| `--space-2` | `8px` | 紧凑元素间隔 |
| `--space-3` | `12px` | 标签与正文、紧凑列表 |
| `--space-4` | `16px` | 默认组件内间距 |
| `--space-5` | `20px` | 按钮横向、普通卡片 |
| `--space-6` | `24px` | 内容组间距 |
| `--space-8` | `32px` | 卡片组、区块间距 |
| `--space-10` | `40px` | 大区块间距 |
| `--space-12` | `48px` | 大屏安全区、页面段落 |
| `--space-16` | `64px` | 桌面页面主留白 |

手机端页面左右安全间距首轮为 18px；桌面和大屏内容区首轮为 28px 以上。组件内部只使用上述阶梯，特殊视觉定位须在代码旁说明原因。

### 3.4 圆角、边框与阴影

| 令牌 | 值 | 用途 |
|---|---:|---|
| `--radius-sm` | `10px` | 小按钮、紧凑控件 |
| `--radius-md` | `14px` | 默认按钮 |
| `--radius-lg` | `18px` | 普通卡片 |
| `--radius-xl` | `24px` | 大屏数据卡片 |
| `--radius-pill` | `999px` | 状态胶囊，不用于大面积容器 |
| `--border-subtle` | `1px solid var(--color-border-subtle)` | 默认边界 |

圆角用于建立共享语言，不用于掩盖层级。管理端危险确认、错误框和数据表必须保持清晰边界。阴影只用于区分层级，不制造高亮文字周围的大面积光晕。

## 4. 旧 CSS 变量兼容

现有页面仍使用以下变量。第一版不得删除或改变其语义；`tokens.css` 应将旧名设为新语义令牌的别名。

| 旧变量 | 新语义令牌 | 兼容要求 |
|---|---|---|
| `--ink` | `--color-text-primary` | 保留，继续表示主文字色 |

| `--gold` | `--color-accent-warm` | 保留，继续表示暖色强调与焦点 |

实现形式示例：

```css

  --color-brand-cyan: #61d9ff;

  --ink: var(--color-text-primary);
  --muted: var(--color-text-secondary);
  --line: var(--color-border-subtle);
  --panel: var(--color-surface-panel);
  --blue: var(--color-brand-primary);
  --cyan: var(--color-brand-cyan);
  --gold: var(--color-accent-warm);

```

加载顺序应为 `tokens.css` → `motion.css` → 原有 `style.css`。新组件只使用新语义令牌；旧选择器可以继续使用旧变量。只有在后续单独 Issue 完成全量迁移和回归检查后，才可考虑移除旧别名。

## 5. 公共组件

### 5.1 `BaseButton`

第一版用于原生按钮，不承担路由链接多态和业务权限判断。

- 变体：`primary`、`secondary`、`ghost`、`danger`。
- 尺寸：`sm`、`md`、`lg`；默认 `md`。
- 默认触控尺寸不小于 44 × 44px；手机端主操作可占满容器宽度。
- 必须透传原生 `type`、`disabled`、`aria-*` 和事件。
- `disabled` 不可点击且保留可读标签；不能只用降低透明度模拟禁用。
- 加载状态保留原标签并增加忙碌标记，设置 `aria-busy`；本 Issue 仅做视觉能力，不发起请求。
- 键盘 `:focus-visible` 使用 3px 暖金色轮廓和 3px 外偏移，不得移除。
- 危险按钮必须写明动作，例如“清屏”，不能只显示无语义图标。

### 5.2 `BaseCard`

- 默认是普通信息容器，可通过 `as` 保留 `div`、`article`、`section` 或 `ul` 等正确语义。
- 变体：`glass`、`solid`、`outline`；不得把所有卡片都做成强光和重阴影。
- `/welcome` 的 v2 主场景不得用 `glass` 变体搭建卡片墙；液态玻璃只属于单一底部操作坞。
- 默认使用弱边框、面板色和 `--radius-lg`；大屏指标卡可使用 `--radius-xl`。
- 交互卡片必须使用真正可聚焦的按钮或链接，不能仅给 `div` 添加点击事件。
- 标题、正文、状态和操作区应有稳定顺序；装饰层设置 `pointer-events: none`。

### 5.3 `StatusPill`

状态胶囊必须始终显示文字；图标与颜色只作辅助。

| 状态 | 建议色调 | 说明 |
|---|---|---|
| 演示数据、信息 | `info` | 说明当前为占位或模拟状态 |
| 待开发、已下屏 | `neutral` | 非错误、当前不活动 |
| 暂停、重连中、已降级 | `warning` | 需要注意或等待处理 |
| 通过、在线、已完成 | `success` | 成功或正常可用 |
| 拒绝、离线、失败 | `danger` | 错误、停止或危险状态 |

静态说明不默认设置 `role="status"`。只有未来真实动态状态变化时，才按业务场景决定是否使用 live region，避免屏幕阅读器重复播报。

## 6. 三端差异

### 6.1 `/welcome` 手机端

- 以 320px 为最小支持宽度，主要检查宽度为 390px；单列优先。
- 页面必须可读、按钮可点、无横向溢出；约 390×844 下页面外壳不得纵向滚动，节目单内部滚动除外。
- 每个状态只突出一个主要任务；NFC 个性入口为主，二维码/短网址承载同一随机令牌。无法使用个性入口时，可进入人工协助的虚构姓名+合成学号备用核验，但必须映射到同一合成身份与档案，不能生成第二个参与者。任一路径核验成功即激活，不能再出现第二次“身份激活”步骤。
- 选色锁定后先完成档案提交或明确跳过，再进入当前现场场景；晚到者不绕过该入场顺序。
- 主场景保留星系与一个底部操作坞；只有自己的恒星显示公开编号，其他恒星不显示标签。
- 不依赖自动播放音频或环境动效完成流程。
- 使用 `100dvh` 时保留 `100vh` 回退，并考虑刘海屏安全区。
- 非核心动画在弱网或减少动态效果模式下直接关闭。
- 成功提示可自动收回，异常提示不可自动消失；退出始终确认，内存草稿按 D-025 的清理点清除。

### 6.2 `/screen` 舞台大屏端

- 第一版以 1920 × 1080、16:9 全屏作为视觉检查基线；这不是正式场馆规格。
- 背景可铺满视口，关键信息保持安全边距；不得出现浏览器控件、滚动条、裁切、黑边或文字溢出。
- 以最多 300 颗真实恒星组成的流动星系为主视觉，使用服务端稳定位置和幂等 upsert；不生成假恒星填充画面。大屏暂不显示任何参与者编号/星号，也不允许点击单星；可检查的公开星号只保留在网络主键层。
- 远距阅读优先：当前场景、连接与降级状态使用更高字号和明确标签；全场只运行 `ASSEMBLY`、`PROGRAM_SUPPORT`、`COOPERATIVE_LIGHT` 三个场景。
- 不展示个人排行、完整身份、未选中/已撤下时光胶囊、规则拒绝或已下屏内容。
- 时光胶囊只能由后台人工触发为插入子场景，不改变全局场景或运行状态；`COMPLETED` 后不再新上屏。
- 实时效果异常时必须能隐藏动效层并切换静态背景、简化布局或预渲染素材。
- LIVE 结束画面只投影服务端已确认的终态；REHEARSAL 的 finale 只允许显示持续可见的“排练预览”标记，不写 live `COMPLETED`。动画完成不得反向触发业务结束。
- `PROGRAM_SUPPORT` 作为 OBS 透明浏览器源：中心留给导播节目视频，网页只在左右边缘约 15%～20% 保留弱星点，并叠加匿名弹幕与有限礼物效果。网页不拥有媒体、不输出音频，不渲染节目占位黑底。
- 礼物采用“一个主礼物 + 一个次礼物”的稳定上限；1.5 秒同类事件只合并视觉计数，星舰可突出但不可形成持续挡屏。弹幕最多保留 8 条快照摘要；实时飞行层不显示作者、头像、编号或来源。
- 胶囊插入独占舞台画面；隐藏期间到达的弹幕/礼物不补播。视觉优先级为终态、排练终章、胶囊、故障、场景、互动，越高层必须清理越低层的临时动画。

### 6.3 `/admin` 管理端

- 信息密度可高于手机端，但沿用同一颜色、间距、圆角和状态语义。
- 已发布、规则拒绝、已下屏、来源屏蔽及连接/降级状态必须清晰可扫读。
- 危险操作、暂停、清屏、恢复等控件必须有文字、确认和权限边界；第一版仅展示样式，不实现操作。
- 窄屏时列表内容允许自然换行，中间内容设置 `min-width: 0`，不得因状态胶囊造成横向溢出。
- 管理员凭据、令牌和真实名单不得出现在页面、截图或演示数据中。

## 7. 动效系统

动效数值令牌定义在 `frontend/src/styles/tokens.css`，关键帧、动效工具类与降级规则定义在 `frontend/src/styles/motion.css`。只动画 `transform` 和 `opacity` 等低成本属性，避免循环改变布局、滤镜或大面积阴影。D-026 允许 V2-07 `/screen` 动态加载 GSAP core 编排少量 DOM 覆层；恒星仍由单 Canvas 绘制，禁止逐星 GSAP 和任何插件。

| 令牌 | 第一版值 | 用途 |
|---|---:|---|
| `--motion-duration-fast` | `140ms` | 按压、悬停、焦点反馈 |
| `--motion-duration-base` | `220ms` | 普通状态变化 |
| `--motion-duration-slow` | `420ms` | 卡片或区域进入 |
| `--motion-duration-ambient` | `24s` | 环境层低速漂移 |
| `--motion-ease-standard` | `cubic-bezier(0.2, 0, 0, 1)` | 常规过渡 |
| `--motion-ease-emphasized` | `cubic-bezier(0.2, 0.8, 0.2, 1)` | 单次强调，不用于无限循环 |

### 7.1 四层方案

1. **组件反馈层**：按钮、链接和焦点的 140–220ms 反馈。状态变化后立即结束，不阻塞输入。
2. **页面状态层**：卡片出现、区域切换和数据刷新，220–420ms。进入、暂停、完成、失败必须有文字状态。
3. **环境氛围层**：低透明度星点或光晕以 18–30 秒周期缓慢漂移。纯装饰、`aria-hidden="true"`、`pointer-events: none`，三端只挂载一份。
4. **舞台场景层**：星星集结、节目互动和协同点亮分别映射 `ASSEMBLY`、`PROGRAM_SUPPORT`、`COOPERATIVE_LIGHT`；`COMPLETED` 是终态而非第四个场景。时光胶囊是人工插入子场景，动画不得推进状态机或触发结束。

### 7.2 减少动态效果

必须支持 `prefers-reduced-motion: reduce`：

- 环境层停止循环动画和位移，但可保留静态、低透明度背景；
- 页面进入和组件过渡立即完成，不使用闪烁、缩放或视差；
- 状态变化继续通过文字、颜色和布局即时呈现；
- 不把无限动画简单压缩到 `0.01ms`，以免形成高频循环；应明确设置 `animation: none`；
- 所有核心流程在完全无动画时仍可使用。

### 7.3 v2 手机端动效与反馈

- 正常首次流程只有两段受控叙事动效：新身份核验后、页面稳定可见才开始的约 2.8 秒 Vue+CSS+低 DOM SVG 穿越式星云寻星，以及星色权威锁定后的约 1.2 秒点亮并拉远。
- 开播后真正进入后台或被中断时立即收束且返回不重播；返回、刷新、重连、失败、超时和减少动态效果路径不播放叙事时间线，直接渲染同一权威静态终态。
- 星系环境运动只插值服务端恒星位置；DOM 叙事动效只使用 `transform` 与 `opacity`。不得靠持续动画模糊、滤镜或大阴影制造液态玻璃。
- 普通成功提示的 3.5 秒收回是展示行为，不删除服务端事实；异常提示持续显示，直到权威状态恢复。

### 7.4 D-028 寻星连续性系统

- **持久主体**：从镜头首帧到选色静态态只保留一个恒星 DOM 节点，统一在 `50% / 42vh` 轴上单调放大，不做反弹；电影层退出后它的中心、尺寸和颜色均不变。
- **连续镜头**：全屏径向速度线以同一前进方向贯穿四阶段，远近层时间范围互相覆盖，不能分别使用互不相关的旋转、缩放或缓动，也不能在交接前提前淡空。
- **颜色交接**：白核和中性光晕始终存在，默认 `5800K` 色温光晕只在锁定/交接阶段连续显现；不得在电影结束时硬切另一颗暖色星。
- **无障碍交接**：最终文案与控件预渲染，交接前 `inert`、不可聚焦和不可操作，交接后立即可用；正常收束监听主动画 `animationend`，超时只作兜底。实时连接、快照和服务端允许动作不等待动画。
- **静态同构**：隐藏、中断、刷新、恢复、失败与 reduced-motion 都直接使用正常 100% 帧的同构静态结构，不闪播、不补播，也不依赖视觉层取得业务结果。

## 8. A6 横版邀请函第一版

### 8.1 文件与尺寸状态

- 暂按 A6 横版比例 `148mm × 105mm` 制作正反面 SVG 和 PNG 预览。
- SVG 建议使用等比例画布，例如 `viewBox="0 0 1480 1050"`；PNG 预览保持同一比例。
- 本轮文件是视觉方向样稿，不是可直接下单的印刷生产文件。
- 正式尺寸、出血、裁切安全区、圆角、纸张、覆膜、印刷色彩和 NFC 标签规格必须在打样前确认。

### 8.2 正面信息层级

1. 活动/学院文字标识；未授权前只用文字，不描摹官方标志。
2. “星际信标 / 星际成长”主视觉和简短邀请语。
3. 明确标注为示例的虚构姓名，例如“示例姓名 · 林星遥”。
4. 清晰的 NFC 轻触区及短指引，例如“手机解锁后轻触此处”。
5. 不显示学号、班级、邀请码、入口令牌或可反推个人身份的编号。

### 8.3 背面入口层级

按兼容优先级展示三种进入方式：

1. **轻触 NFC**：主入口；
2. **扫描二维码**：NFC 不支持、未开启或识别失败时使用；
3. **输入短网址**：无法轻触或扫码时手动进入。

三者必须指向同一个占位 `/welcome`。第一版使用保留的无效域名 `https://welcome.example.invalid/welcome`，并在图面标注“示例入口 / 不可用于正式活动”。二维码不能被描述为网站宕机或现场断网的备用方案。

### 8.4 NFC 与二维码制作规则

- NFC 视觉触点避开折痕、裁切线、金属油墨、烫金烫银和磁吸结构。
- 视觉标记不等于最终标签位置；实际位置需结合标签、纸张、覆膜和装配小样测试。
- 本轮预览使用明确标注“二维码占位｜不可扫描”的非标准方块纹理，且不绘制标准定位图形，避免被误当作正式入口；正式二维码另行生成后须保持正方形、高对比、无拉伸并保留完整静区。
- 正式二维码、短网址和 NFC NDEF URI 必须来自同一受控 HTTPS 入口，并按“写入—读取—锁定—成品复测”验收。
- 普通 NFC 标签只是访问入口，不得在邀请函上宣称其本身完成身份认证或防复制。

### 8.5 占位数据与素材授权

- 姓名必须虚构并明确标注“示例”；不使用任何真实姓名、学号、手机号或邀请码。
- URL 使用保留示例域名，不使用真实活动令牌、私有链接或临时开发地址。
- 第一版背景、轨道、星点和 NFC 图标使用原创 SVG 基础图形或 CSS 绘制。
- 不复制去年项目的字体、图片、代码、装饰纹样或其他授权不明资产。
- 后续若使用官方标志、商业字体、摄影或插画，必须先取得许可并登记来源。
- D-031 已登记的 `/welcome` 白色透明学院 PNG 是当前唯一已获项目负责人明确授权的学院图形资产；前端文件为 `frontend/src/assets/brand/sysu-intelligent-engineering-white.png`，不得从 `C:\Windows\TEMP` 或学院网站运行时加载。

## 9. 可访问性基线

- 普通正文与背景对比度目标不低于 4.5:1；大号文字及关键图形目标不低于 3:1。
- 所有交互元素具有可见 `:focus-visible` 样式，键盘顺序与视觉顺序一致。
- 手机端触控目标不小于 44 × 44px，相邻危险与普通操作保持足够间距。
- 状态、错误、成功和连接情况必须有文字，不得仅以颜色、闪烁或位置表达。
- 装饰组件使用 `aria-hidden="true"`，不能拦截鼠标、触摸或键盘操作。
- 使用原生按钮、链接和标题层级；禁止用不可聚焦的普通容器模拟控件。
- 禁用状态必须使用原生 `disabled`；动态忙碌状态需提供可理解的文本。
- 320px 宽度不得横向溢出；200% 缩放后主要内容和操作仍可访问。
- 不使用高频闪烁、快速视差、自动播放音频或必须依赖动画才能理解的提示。
