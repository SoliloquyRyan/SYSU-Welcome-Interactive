# G5 手机端产品与视觉基线

> 状态：D-023 需求已确认；D-024 批准深色星海视觉根基，G5-01～G5-05 已实现
> 适用范围：`/welcome` 手机端及其身份、星辰、时光胶囊接口边界
> 历史边界：D-022 继续冻结 G0～G4 已验收实现；本文描述 D-023 的下一目标，不改写历史验收事实

## 1. 目标

手机端应在约 390×844 的常见竖屏视口内完成主要操作，不依赖整页上下滑动。首次 NFC 进入形成一条连续叙事：

`NFC 进入 → 编号星群浮现 → 选择恒星色温 → 确认星色 → 星辰进入中央 → 轨道信号稳定 → 时光胶囊 → 星程主界面`

返回且会话有效的参与者跳过首次入场流程，直接恢复服务端权威状态。

## 2. 页面结构

- 顶部导航固定为 `星程 / 节目单 / 档案`。
- 导航下使用一条六阶段直线，只显示节点和 `02 / 06` 等进度，当前阶段名称单独展示。
- 中央区域承载星海、发光星点和“感知—决策—控制—协同”轨道信号动画；不再使用怀士堂线稿。
- 当前阶段的主要任务放在中央下方；主要操作在无需整页滚动时可触达。
- 节目单允许在中央内容区内部纵向滚动，但页面外壳和底部互动栏保持固定。
- 节目开始后，`星程` 页底部常驻一条直播式弹幕输入栏；发送按钮位于输入栏内，礼物入口紧邻发送按钮。`节目单` 只展示节目顺序和当前状态，不承载互动控件。
- 礼物入口打开半屏 2×2 面板，保留微光 5、信标 10、星轨 20、星舰 50 四档。
- 键盘弹出时压缩中央视觉区域，不把当前输入和提交按钮推离可视区。
- 状态与错误使用顶部浮动提示，不通过新增文档高度挤动布局。

## 3. 入口与星辰

- NFC 个性令牌是主要入口；二维码和短网址仍是兼容备用。
- 姓名与学号是无法使用个性入口时的备用核验方式；Demo 只能使用虚构姓名和合成学号。
- 入口 URL 不得包含姓名或学号，令牌读取后仍须立即从地址栏和当前历史项清除。
- 公开星号格式为姓氏拼音首字母加学号后四位，例如 `L-4821`。
- 该星号不是不可关联的匿名 ID；项目负责人已接受熟人可能通过其关联参与者的风险。
- 项目负责人确认预期名单不会重复；导入和数据库仍必须校验唯一性。若碰撞，激活失败并由后台处理，不得让两个参与者共享星号。
- 星号以后可作为抽奖展示编号，但 G5 不实现抽奖、兑奖、领奖核销或概率规则。

## 4. 恒星色温

- 调色条在红、橙、黄、白、蓝白五个恒星色域之间连续变化，不插入绿色或紫色等非目标主色。
- 视觉界面不显示颜色名称，显示 Kelvin 数值；屏幕阅读器仍需获得控件名称、当前数值和范围。
- 拖动时只实时预览；用户点击“确认星色 · 进入星辰”后才写入服务端。
- 星色确认后本场活动不可修改；刷新、重连和多设备必须显示同一色温。
- 既有稳定外观种子可以继续决定位置、尺寸和微弱闪烁，不能再代替用户选择的色温。

## 5. 时光胶囊

- 第二阶段名称由“未来寄语”改为“时光胶囊”。
- 当前默认继续采用最多 80 个可见字符的限制。
- 页面不得再声称正文“私密”或“永不上屏”。
- 填写区上方必须明确显示：`你写下的内容可能经筛选后，以星号和星色在现场大屏展示。`
- 保存前必须主动确认已知晓该公开范围；未确认不得提交。
- 用户可以跳过填写并继续主流程；一旦提交，正文即进入人工筛选候选池，不能选择“已填写但不进入候选池”。
- 候选内容不保证上屏，也不能由规则或 AI 自动公开；后台人工确认后才可进入大屏展示集合。
- 后台筛选默认只需要星号、星色和正文，不需要完整学号。
- “时光胶囊”是体验叙事，不构成四年保存承诺；长期保留、撤回和删除规则在正式数据接入前另行确认。

## 6. 动效与素材

- 第一版普通入场时长约 0.9 秒，并从首帧提供“跳过过场”。
- 选中的编号星辰移动到屏幕中央，发出感知波并稳定在轨道中心；不生成建筑线稿。
- 主界面中的同一星辰响应当前阶段和本人操作；暂不接入手机端全场高频聚合动画。
- `prefers-reduced-motion: reduce` 直接显示静态终态和可操作控件，不执行路径绘制、位移或缩放。
- 怀士堂照片和带署名线稿不进入当前手机端动画；不得嵌入、描摹或修改现成线稿。
- 不使用未经授权的校徽、院徽、字体、图片、去年项目资产或大型动画库。

## 7. 字段处置

| 当前字段或语义 | D-023 处置 | 原因与迁移要求 |
|---|---|---|
| `demoCode` / `demo_code_digest` | **删除并替换** | 改为备用核验的 `studentNumber` / `student_number_digest`；必须在同一迁移中更新种子、契约、接口、日志脱敏和测试，不能先删列再修消费者 |
| `futureMessage*` / `future_message*` | **删除并替换** | 改为 `capsuleMessage*` / `capsule_message*`，并增加公开范围确认与人工候选状态；历史验收中的旧名称不改写 |
| “私密寄语”“永不上屏”当前产品断言 | **删除** | 与 D-023 的上屏候选机制冲突；只有 D-022 历史验收记录可继续保留该表述 |
| `publicStarId` / `public_star_id` | **保留，改变生成规则** | 继续作为稳定公开编号，值改为姓氏首字母加学号后四位，并保持唯一约束 |
| `visualSeed` / `visual_seed` | **保留** | 继续支持稳定位置、尺寸和非颜色外观，不再决定用户选择的星色 |
| `displayName` / `display_name` | **保留** | 备用姓名核验和本人界面仍需要；不得进入公共大屏 |
| 邀请 `token` / 摘要 | **保留** | NFC、二维码和短网址同入口仍依赖不可猜测令牌 |
| 新 `starTemperatureKelvin` | **新增** | 服务端权威保存用户选择，并记录锁定时间；多设备必须一致 |
| 新胶囊候选状态 | **新增** | 至少区分已提交候选、人工选中、已展示/已撤下；精确状态机在接口实现前冻结 |

字段迁移必须原子完成。当前代码已完成星色、时光胶囊和身份三段迁移；`0007_student_identity.sql`、种子清单升级、严格接口契约、失败限频、隐私断言和浏览器用例共同证明旧六位码已由合成学号替换，邀请令牌与身份 ID 保持稳定。

## 8. 当前实现与后续边界

项目负责人已经批准深色星海、发光圆点恒星和轨道信号方向。当前第一版已经实现：

1. NFC 星群浮现与编号星辰状态；
2. 恒星温度连续调色条与确认状态；
3. 轨道信号转场后的时光胶囊；
4. 星程主界面与直线流程；
5. 减少动态效果静态状态。

已经实现：个性令牌直接建立会话、合成学号备用核验、`L-4821` 格式唯一星号，以及胶囊的提交、人工选中、上屏和撤下。大屏投影最多同时展示 6 条，只包含公开星号、恒星色温和已确认正文。`星程` 页固定弹幕与礼物底栏、节目单内部滚动和输入聚焦压缩已接入；375×667、390×420 键盘剩余高度、667×375 横屏和 125% 字号自动化已通过。礼物半屏面板支持初始焦点、Tab 循环、Escape 关闭和焦点归还；仍待项目负责人在 vivo X300 上确认真实软键盘和触控体验。动画协作者只修改表现层，边界见 [`ANIMATION_HANDOFF.md`](./ANIMATION_HANDOFF.md)。
