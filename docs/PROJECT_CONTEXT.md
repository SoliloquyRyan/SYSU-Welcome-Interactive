# 迎新晚会互动系统：项目上下文

> 状态：D-022 已冻结并复验 G0～G4 提交基线；D-023/D-024 已冻结 G5 手机端目标与批准视觉根基，G5-01～G5-05 已实现，手机端真机体验与文档收口仍待完成。
> 适用对象：项目负责人及参与协作的 AI
> 说明：本文记录 `feature/demo-v0` 的当前开发基线和正式版延期事项，不代表学院已正式审批。`docs/DECISIONS.md` 的已确认项优先于旧文档；标为“正式版待确认”的事项不得当作 Demo v0 的阻塞项或学院定案。

## 1. 项目目标

为智能工程学院迎新晚会建设一套手机 H5、后台控制台与舞台大屏联动的互动系统。实体明信片式邀请函既是迎新纪念物，也是进入“星际成长”体验的入口；新生完成六阶段互动后，可形成个人星际档案和匿名化的集体星图。

项目优先保证：进入简单、服务端状态可信、三端实时一致、现场可控、公开内容可快速处置、故障可恢复、数据最小化。

- D-019 历史独立 G3 基线中，Windows Chrome 与 Edge 的可重复浏览器证据于 2026-08-10 以 `pnpm verify:g3` 退出码 0、总时长 278.9 秒收口；Vitest 16 个文件/102 条、Playwright 6 场景 × 3 项目 = 18/18 以及共享契约、后端、前端构建均通过，退出后 E2E 临时目录为 0。该条中的 vivo `PENDING` 是当时状态，已由 D-021 的人工验收取代。
- D-021 提交前工作树总验收中，根级 `pnpm verify:g4` 退出码 0、观察总耗时约 463.2 秒；Vitest 20 个文件/119 条、三项生产构建、Playwright 9 场景 × 3 项目 = 27/27 全部通过，浏览器报告 `passed`、失败检查点 0、时间窗 295388 ms。环境为 Windows 10.0.26100、Node.js 24.16.0、pnpm 11.16.0、Playwright 1.62.1；Chromium/Chrome/Edge 版本分别为 151.0.7922.34、151.0.7922.76、151.0.4129.72。vivo X300 默认浏览器人工核心旅程也通过；其浏览器版本与实际 CSS 视口未单独采集，作为本次证据限制保留。
- D-021 对应的 G4 报告在 Windows 单机 loopback 上用 300 个固定合成参与者和 301 条 WebSocket 连接完成 123452.51 ms 的真实 HTTP/WebSocket 混合旅程。阶段、礼物、弹幕、协同点亮传播 p95 分别为 46.12、1426.08、1438.55、939.64 ms，四档礼物各自 p95 均小于 2 秒；业务与协议失败、重复账本/奖励/扣减/幂等记录、负余额和旧 epoch 污染均为 0，301 条连接在重启后全部恢复，重置与会话/epoch 隔离通过。主要 HTTP 写入并发为 24；该专项不是 300 次写请求同一瞬间并发、30 分钟 soak、分布式局域网或场馆验收。脱敏报告仅保存在被忽略的 `tests/reports/g4-load.json`。

- NFC 明信片为正式产品的主要触达方式，二维码为 NFC 不可用时的兼容备用；Demo v0 只验证同一随机令牌的网页入口，不制作实体卡片。
- NFC 与二维码进入同一个 H5，不得形成两套账号、积分或互动记录。
- 二维码只解决 NFC 兼容问题，不能解决网站、服务器或网络故障；Demo v0 只实现断线阻止写入、权威快照恢复和静态视觉降级，正式备用网络与预渲染素材后续确认。
- 邀请函采用一人一卡一码的随机个性令牌；同卡 NFC 与二维码编码同一令牌。
- G5 六阶段主线为：身份激活与星色、时光胶囊、星星集结、节目应援与弹幕、协同点亮、星际档案。
- 动力值用于节目应援，星光值用于记录参与成长；两者互不兑换。
- 时光胶囊可以跳过；提交前必须确认内容可能经筛选上屏，提交后进入人工候选池。后台可人工选择、上屏和撤下；大屏最多显示 6 条，只接收星号、星色和正文。
- 弹幕在首次公开告知后，经本地确定性规则校验即匿名实时上屏；后台提供事后删除、屏蔽来源、暂停和紧急清屏。AI 审核只预留接口。
- Demo v0 只处理固定合成数据；正式版如处理真实数据，继续遵守最小化、审批和活动结束后 30 天清理基线。
- 运行模式分为排练和现场：排练可跳阶段，现场只能向前推进；所有写操作、计分和阶段状态以本地服务端为唯一权威。
- 同一参与者可在多台设备登录；重复、刷新、重试和并发不得重复激活、奖励、扣分或点亮。

## 3. 六阶段体验

| 阶段 | 参与者体验 | 现场输出 |
|---|---|---|
| 1. 轻触/扫码、身份与星色 | NFC 令牌进入或姓名+学号备用核验，显示编号星辰并确认恒星色温 | 进入进度、星号和星色安全投影 |
| 2. 时光胶囊 | 可跳过；提交前确认正文可能经人工筛选后上屏 | 候选数量；仅人工选中内容可进入后续公共展示 |
| 3. 星星集结 | 生成稳定个人星星，在阶段开放后启动 | 星点汇聚与已启动数量 |
| 4. 节目应援与弹幕 | 查看固定虚构节目、投入虚拟礼物、提交实时弹幕 | 节目热度、匿名礼物轨迹和规则通过的实时弹幕 |
| 5. 协同点亮 | 每位参与者完成一次全场协同点亮 | 点亮人数、有效参与人数和百分比 |
| 6. 星际档案 | 查看本人星号、星色、时光胶囊、双值与互动档案 | 集体星图、激活数、星光总量、互动次数和等级分布 |

## 4. 交付范围

- **Demo 邀请入口**：个性令牌、网页入口二维码和 NFC/二维码同令牌规则；实体写卡、印刷和发放延期。
- **手机 H5**：进入、核验、寄语、个人星星、节目单、动力值、弹幕、互动任务与个人档案。
- **后台控制台**：共用账号登录、自提权、阶段与节目状态、实时弹幕事后处理、数据监控、应急暂停和确定性重置。
- **舞台大屏**：星星集结、节目热度、合规匿名弹幕、协同点亮进度和结尾匿名聚合。
- **本地运行**：一条命令启动本地持久化服务和三端网页，输出局域网 URL、二维码和 Demo 凭据；正式现场运行后续补充。

默认不包含支付、抽奖、兑奖与领奖核销、公开个人排行榜、人脸识别、四年或永久保存个人档案、真实名单、实体 NFC 写入、邀请函印刷、公网部署、真实 AI 审核或重型 3D 动画。星号只保留未来抽奖扩展方向，不代表抽奖已经进入 G5。

## 5. 单人维护与 AI 协作

项目负责人长期单人维护。以下是职责边界，不代表固定有五名成员；同一人可以承担多项职责：

| 职责 | 主要内容 |
|---|---|
| 产品与验收 | 需求、优先级、Issue、取舍和最终人类验收 |
| 前端 | 手机、后台、大屏页面、可访问性和浏览器兼容 |
| 后端与运行 | 数据库、接口、实时同步、迁移、重置和故障恢复 |
| 视觉与动效 | 轨道信号场、组件、动画分层和 reduced-motion |
| 测试 | 自动化、负载、真机和三端全流程证据 |

AI 可协助梳理需求、生成原型或代码、编写测试和维护文档，但必须遵守：

- 产品取舍、公开内容、数据导出和上线操作由人类负责人批准。
- AI 只使用合成或已匿名化数据，不接收真实姓名、真实学号、真实入口令牌、原始时光胶囊或弹幕。
- AI 产出必须由项目负责人复核，不得把建议写成学院正式决定。
- 影响实现或验收的决定先写入 `DECISIONS.md`，再同步本文与 `REQUIREMENTS.md`，最后修改实现与测试。

正式活动当天仍需明确现场主控、公开内容处置、人工协助和数据删除复核责任；具体人数和人选延期到彩排前确认。

## 6. 已知约束

- NFC 和二维码必须落到同一个稳定入口，且手机端状态一致。
- 现场大屏只能接收聚合数据、公开星号/星色、规则通过且仍公开的弹幕，以及后台人工选中的时光胶囊；不得读取完整姓名、完整学号、令牌或未选中的胶囊正文。
- 六阶段中的关键切换由后台触发；Demo v0 保证无动效时的静态信息降级，正式可播放兜底素材后续确认。
- 后台采用共用账号，任何登录会话可自行提权；该方案不能提供真实个人归因，是项目负责人明确接受的风险。未登录访问仍必须拒绝。
- Demo v0 使用本地局域网和合成数据；离线时阻止业务写入，重连后拉取服务端快照，不在客户端排队补写。
- 实体明信片、NFC、采购、样品测试、写入和到货验收均为正式版延期事项，不阻塞 Demo v0。
- “时光胶囊”目前是叙事表达，不等于获准保存数据四年。
