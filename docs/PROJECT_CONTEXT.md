> 状态：协议 v2 现行；最新决策 D-056（2026-09-05）已建立正式单机部署、仓库外私有持久化、生产启动前验证、HTTPS/Secure Cookie、systemd 守护、SQLite 一致性备份/恢复和可共享合成排练基线。D-055 把 220 人设为正式大屏视觉满场基准，300 人仅保留为技术压力上限，并将集结态收束为低倾角盘状银河、420 颗无身份中性底星、未解析盘面光的有界人数补偿与多周期低振幅呼吸；逐人画外流星继续沿逆时针切线进入稳定轨道。D-054 已建立 220 人受保护名单通道：真实名单只取姓名与 8 位学号，NFC/二维码 URL 使用随机匿名令牌，公开星号不再派生学号，5 个测试账号只从独立合成 Demo 导出。实际服务器、HTTPS 域名/DNS、私密数据传输、实体写卡、数据责任/删除流程和受影响现场复验尚未完成。本页是“项目现状”的唯一来源；历史内容见 [`archive/`](./archive/README.md)。

## 1. 目标

为智能工程学院迎新晚会建设手机 H5（`/welcome`）、后台控制台（`/admin`）与舞台大屏（`/screen`）三端联动的互动系统。实体明信片式邀请函（NFC/二维码）是进入“星际成长”体验的入口；新生完成身份激活与星色锁定后直接进入全场当前场景，形成个人星际档案与匿名集体星图；节目支持阶段可由后台开启个人抽奖。

优先级：进入简单 > 服务端状态可信 > 三端实时一致 > 现场可控 > 公开内容可快速处置 > 故障可恢复 > 数据最小化。

## 3. 协议 v2 主线（详见 PROTOCOL_V2）

1. 有效入口（NFC / 同令牌二维码 / 人工协助）先原子预留 300 个稳定 slot 之一，再完成激活并只发放一次 100 动力 + 20 星光；满员整笔拒绝。
2. 锁色事务把个人恒星加入公开星系并直接写入 `ADMITTED`；寄语/时光胶囊不再采集或展示。
3. 准入后立即进入当前全场状态；晚到者不重放历史阶段。
4. 全场只有 `ASSEMBLY → PROGRAM_SUPPORT → COOPERATIVE_LIGHT` 三场景；`COMPLETED` 是终态，不是第六场景。
5. `PAUSED` 冻结参与者写入但允许只读恢复；`COMPLETED` 关闭写入、允许本 epoch 已激活身份只读重认证。
6. 安全处置只指删除、屏蔽、清屏或撤下公开内容，不调整数值。

## 4. 三端体验

| 端 | 体验 |
|---|---|
| 手机 `/welcome` | 入场（寻星 → 选色 → 锁色确认后直接入轨）→ 沉浸式流动星系 + 单一高透微角操作坞；D-050 以轻量本地星云的亮度结构叠加低饱和 Orbital Signal 气氛，本人星保留 `displayColor` 并突出显示星号 |
| 大屏 `/screen` | 唯一可见 Canvas 技术上最多 300 颗真实恒星、正式以 220 人为视觉满场参考；低倾角恒星盘以盘面离散星与连续未解析星光为主体，核球、短棒及宽而弱的密度波只作层次，另有 420 颗无身份中性底星和有界人数补偿。星从公开抵达首帧起逆时针持续流动，环境层以非同步低振幅变化形成呼吸；摄影式点扩散材质逐星保留服务端 `displayColor`，且集结/离场不显示人数进度。新人只在实时首次公开时以一次画外流星沿切线进入稳定轨道。等待态 30Hz；到场流星和集结→节目以 60Hz 为目标并预热有界 WebGL2 后处理。D-051 让当前星海错峰螺旋汇聚为高温核心，经过一次非对称超新星与连续白场曝光后把 Canvas 平滑变为透明；Canvas2D 保留回退；`PROGRAM_SUPPORT` 稳态为无网页节目板/常驻层的 OBS 透明源，新弹幕仅实时飘屏；个人抽奖/终章按固定视觉优先级 |
| 后台 `/admin` | 共用账号登录 + 自提权；三场景控制、节目选择、无放回个人抽奖、弹幕处置、匿名漏斗、确定性重置；D-053 使用静态午夜蓝画布、分层深空面板和清晰状态色构成克制的高密度运营控制台，不加入持续星流或粒子动画，内部枚举转换为可读文案 |

## 5. 边界与延期事项

- Demo v0：本地局域网、固定合成数据、一条命令启动三端并输出 URL/二维码/凭据。
- 明确不做：支付、抽奖概率加权/兑奖/核销、公开个人排行榜、人脸识别、四年保存、真实 AI 审核、重型 3D。
- 已确认但必须受保护：真实名单来源与核验授权；只使用 220 组姓名/学号，不导入性别和班级。
- 正式版待确认：活动日期/节目单、场地大屏参数、实际 Linux 主机与 H5 HTTPS 域名/DNS、实体 NFC 写卡/补卡、物料预算、数据负责人与删除流程、学院 Logo 矢量母版授权。单机部署代码与手册已具备，不等于目标服务器已上线。

## 6. 协作与安全边界

- 项目负责人维护正式数据；协作者可通过 GitHub 共享代码并用固定合成排练环境开发，AI 可协助需求、原型、代码、测试与文档。
- AI 只使用合成或匿名化数据；不接收真实姓名、学号、令牌、抽奖身份映射或弹幕正文。
- AI 产出须由负责人复核；影响实现或验收的决定先写入 [`DECISIONS.md`](./DECISIONS.md)。
- 未授权不提交、不推送（见 DECISIONS D-014）。
