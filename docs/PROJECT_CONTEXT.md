# 迎新晚会互动系统：项目上下文

> 状态：D-025/D-026 已冻结协议 v2 与大屏表现口径，D-027 手机首次寻星约 2.8 秒、可见性门及 normal-motion 自动浏览器断言已落地并通过；V2-00～V2-09 已完成协议、数据库、入场、三场景运行时、快照/实时、v2 三端页面、三浏览器自动回归和 300 人协议负载。V2-10 的 30 分钟 Chrome 渲染门已通过并建立局域网临时预览入口；D-027 自动子门为 `PASS`，vivo X300 复验、OBS 实际合成与三端局域网人工签核仍待完成。仓库实际 `.data` 未执行 v1→v2 切换，当前日常运行时仍为 v1，不能表述为 v2 已现场上线。D-022 冻结的 G0～G4 与 D-023/D-024 对应实现只作为 v1 历史证据。
> 适用对象：项目负责人及参与协作的 AI
> 说明：本文记录仓库当前开发基线和正式版延期事项，不绑定历史分支名称，也不代表学院已正式审批。`docs/DECISIONS.md` 的已确认项优先于旧文档；标为“正式版待确认”的事项不得当作 Demo v0 的阻塞项或学院定案。

## 1. 项目目标

为智能工程学院迎新晚会建设一套手机 H5、后台控制台与舞台大屏联动的互动系统。实体明信片式邀请函既是迎新纪念物，也是进入“星际成长”体验的入口；新生通过 NFC/二维码激活身份、完成星色与档案决定后进入当前全场场景，并逐步形成个人星际档案和匿名化的集体星图。

项目优先保证：进入简单、服务端状态可信、三端实时一致、现场可控、公开内容可快速处置、故障可恢复、数据最小化。

## 2. 当前工作基线

D-025、D-026、D-027 与 [`PROTOCOL_V2.md`](./PROTOCOL_V2.md) 是当前产品和协议权威。V2-01～V2-05 已完成共享契约、维护门、参与者入场、三场景运行时与分流实时层；V2-06/V2-07 已完成 v2 后台与大屏；V2-08 已让 `/welcome` 按能力发现进入独立入场、真实星系和三场景操作坞，并将节目选择同步为服务端权威事件。V2-09 已用隔离临时 `V2_ACTIVE` 合成栈完成三浏览器三端闭环、全量自动回归和 300 人协议负载。V2-10 自动渲染门已在 1920×1080 Chrome 中持续测量 1,800,056.8ms 并通过，局域网临时合成入口也已就绪。D-027 的手机约 2.8 秒实现、可见性门和 normal-motion 自动断言已落地并通过；实际 `.data` 仍为 v1，v1 数据库继续使用旧三端，OBS、局域网与 vivo X300 仍须人工签核。

协议 v2 的当前主线是：

1. 有效 NFC、同令牌二维码/短链接或映射同一合成身份的人工协助核验，先原子预留 300 个稳定 slot 之一，再完成首次身份激活并只发放一次 100 动力值与 20 星光；容量满则整笔拒绝；
2. 参与者选择并锁定星色后，个人恒星立即加入公开星系，再对时光胶囊作“提交或跳过”的持久决定；
3. 胶囊提交者首次实际提交获得 20 星光；跳过者当时获得 0，之后可在 `READY` 或 `RUNNING` 补填并只奖励一次；
4. 完成或跳过胶囊后即进入当前全场状态；晚到者不从历史阶段重放，而是完成入场后直接进入当前场景；
5. 全场运行只保留 `ASSEMBLY`、`PROGRAM_SUPPORT`、`COOPERATIVE_LIGHT` 三个场景，`COMPLETED` 是终止状态，不是第六场景；
6. `PAUSED` 冻结参与者写入但允许已激活身份只读恢复；`COMPLETED` 关闭参与者写入，当前 epoch 任何已激活身份都可只读重认证，但未完成者不能继续入场。安全处置只指删除、屏蔽、清屏或撤下公开内容，不调整动力或星光。

- NFC 明信片为正式产品的主要触达方式，二维码/短链接为 NFC 不可用时的同令牌兼容备用；Demo v0 不制作实体卡片。
- NFC、同令牌二维码/短链接和用合成姓名/学号定位身份的人工协助进入同一个 H5、恢复同一参与者状态，不得形成两套账号、积分或互动记录。
- 二维码只解决 NFC 兼容问题，不能解决网站、服务器或网络故障；Demo v0 只实现断线阻止写入、权威快照恢复和静态视觉降级，正式备用网络与预渲染素材后续确认。
- 邀请函采用一人一卡一码的随机个性令牌；同卡 NFC 与二维码编码同一令牌。
- D-025/D-027 当前主线为“身份激活与星色 → 档案/时光胶囊决定 → 进入当前全场场景”；旧六阶段主线仅保留为 v1 历史。
- 动力值用于节目应援，星光值用于记录参与成长；两者互不兑换。
- 时光胶囊可以跳过；提交正文最多 80 个可见字符，必须确认内容可能经筛选上屏，提交后进入人工候选池，不支持“提交但不入池”。后台每次最多人工选择并插入 6 条，只向大屏发送星号、星色和正文。
- 弹幕在首次公开告知后，经本地确定性规则校验即匿名实时上屏；后台提供事后删除、屏蔽来源、暂停和紧急清屏。AI 审核只预留接口。
- Demo v0 只处理固定合成数据；正式版如处理真实数据，继续遵守最小化、审批和活动结束后 30 天清理基线。
- 合法运行组合只有任一 mode 的 `READY+null`、任一 mode 的 `RUNNING/PAUSED+三个场景之一`，以及唯一 `LIVE+COMPLETED+COOPERATIVE_LIGHT`。现场只向前推进；排练结尾是服务端权威、可清除且持续标记的 presentation，不得写 LIVE 的 `COMPLETED`。
- 运行、活动投影、参与者、匿名聚合和恒星分别使用 `runRevision`、`presentationRevision`、`participantRevision`、`aggregateRevision` 和 `starRevision`；公开、后台和本人三类逻辑流各用独立连续的 `streamSeq`，受限事件不会制造其他流的伪缺口。稳定事件名与闭合错误码以 [`PROTOCOL_V2.md`](./PROTOCOL_V2.md) 为准。
- 参与者快照由服务端统一给出个人事实与 `allowedActions`；大屏恒星包含公开 `started` 状态，`START_STAR` 在原位更新恒星并发 upsert。后台只显示激活→锁色入星系→准入的匿名漏斗及胶囊提交/跳过计数，不展示逐人身份；阶段推进与完成的就绪提醒可由有权限操作者明确覆盖，但安全硬门不可覆盖。
- V2-02 的 `pnpm exec tsx backend/src/cli/v2-switch.ts` 与 `pnpm exec tsx backend/src/cli/v2-reset.ts` 是仅供维护窗口使用的数据库门，验证入口为 `pnpm exec tsx backend/src/cli/v2-verify.ts`；本卡未增加 package 脚本别名。两项破坏性命令均要求精确确认 `SYNTHETIC_DEMO_DATA_IS_DISPOSABLE`，一次性切换还必须创建未存在的完整 SQLite 备份，并验证最新服务 generation 已真实监听且由同代服务在所有 HTTP/WebSocket 结束后干净关闭。任何真实、有价值、结构漂移或无法证明为固定合成基线的数据都会硬停止；操作员仍须人工确认所有 pre-0008 旧进程已退出。后台 `RESET_DEMO` 仍属于 V2-06，不能用维护 CLI 冒充现场控制。
- 同一参与者可在多台设备登录；重复、刷新、重试和并发不得重复激活、奖励、扣分或点亮。

## 3. 协议 v2 体验

### 3.1 参与者入场

| 状态 | 参与者体验 | 权威结果 |
|---|---|---|
| 身份激活 | NFC/同令牌备用入口或同身份人工协助核验后穿过星云，看到一颗中性恒星并选择色温 | 先预留稳定 slot；容量可用才建立会话、首次奖励并进入待选色 |
| 星色锁定 | 权威写入色温后点亮本星并拉远到流动星系 | 本星立即加入公开星系，使用稳定槽位；本人端突出并显示星号 |
| 档案决定 | 确认候选范围后提交最多 80 个可见字符，或明确跳过 | 两种决定均持久化；提交首次奖励，跳过不奖励；不提供私密但不入池的提交 |
| 已接入 | 自动落到当前 `READY`、运行场景、暂停或完成态 | 不重放已错过场景；完成态仅可只读恢复 |

正常首次入场不提供跳过动画按钮：服务端明确返回首次新建身份与 `NEEDS_COLOR` 后，页面先等稳定 `visible`，再用 Vue+CSS 播放约 2.8 秒更具穿越感的星云寻星；用户选色不计时，服务端确认色温并取得星系快照后再用约 1.2 秒点亮并拉远。开始前暂不可见时等待，真正开播后进入后台或被中断则立即静态且返回不重播；减少动态效果、返回用户、刷新、断线恢复、失败和超时也直接呈现可操作静态状态。手机端不迁移 GSAP。

### 3.2 三个全场场景

| 场景 | 参与者体验 | 现场输出 |
|---|---|---|
| `ASSEMBLY` | 已接入者可执行一次 `START_STAR`，查看本人恒星随星系流动，并可补填档案 | 启动写本人事实并把公共恒星原位更新为 `started=true`、发布 upsert、奖励一次；不创建或移动恒星，最多 300 颗真实恒星 |
| `PROGRAM_SUPPORT` | 查看节目、送出虚拟礼物、提交公开弹幕 | 节目热度、匿名礼物轨迹与规则通过的实时弹幕 |
| `COOPERATIVE_LIGHT` | 每位参与者最多完成一次协同点亮 | 点亮人数、有效参与人数与百分比 |
| `COMPLETED`（终止状态） | 只读查看本人档案与结束祝福 | 冻结后的集体星图与安全汇总；不是第四场景 |

时光胶囊公共展示是审核人员触发的插入子场景，不改变全场场景或运行状态，不自动轮播、自动公开或由 AI 决定。
它与排练结尾预览组成互斥 presentation；场景变化、暂停或重置会清除活动投影。LIVE 完成会先捕获当前最多 6 条插入胶囊到只读终局回顾，再清除活动投影。晚到者不能补做已经离开的场景或补领旧场景奖励。

## 4. 交付范围

- **Demo 邀请入口**：个性令牌、网页入口二维码和 NFC/二维码同令牌规则；实体写卡、印刷和发放延期。
- **手机 H5**：进入、核验、选色、胶囊决定、个人恒星与星系、节目单、动力值、弹幕、互动任务与个人档案。
- **后台控制台**：共用账号登录、自提权、运行状态、全场场景与节目状态、实时弹幕事后处理、胶囊插入展示、数据监控、应急暂停和确定性重置。
- **舞台大屏**：星星集结、节目热度、合规匿名弹幕、协同点亮进度和结尾匿名聚合。
- **本地运行**：一条命令启动本地持久化服务和三端网页，输出局域网 URL、二维码和 Demo 凭据；正式现场运行后续补充。

默认不包含支付、抽奖、兑奖与领奖核销、公开个人排行榜、人脸识别、四年或永久保存个人档案、真实名单、实体 NFC 写入、邀请函印刷、公网部署、真实 AI 审核或重型 3D 动画。星号只保留未来抽奖扩展方向，不代表抽奖已经进入 G5。

## 5. 单人维护与 AI 协作

项目负责人长期单人维护。以下是职责边界，不代表固定有五名成员；同一人可以承担多项职责：

| 职责 | 主要内容 |
|---|---|
| 产品与验收 | 需求、优先级、Issue、取舍和最终人类验收 |
| 前端 | 手机、后台、大屏页面、可访问性和浏览器兼容 |
| 后端与运行 | 数据库、接口、实时同步、迁移、重置和故障恢复 |
| 视觉与动效 | 轨道信号场、组件、动画分层和 reduced-motion |
| 测试 | 自动化、负载、真机和三端全流程证据 |

AI 可协助梳理需求、生成原型或代码、编写测试和维护文档，但必须遵守：

- 产品取舍、公开内容、数据导出和上线操作由人类负责人批准。
- AI 只使用合成或已匿名化数据，不接收真实姓名、真实学号、真实入口令牌、原始时光胶囊或弹幕。
- AI 产出必须由项目负责人复核，不得把建议写成学院正式决定。
- 影响实现或验收的决定先写入 `DECISIONS.md`，再同步本文与 `REQUIREMENTS.md`，最后修改实现与测试。

正式活动当天仍需明确现场主控、公开内容处置、人工协助和数据删除复核责任；具体人数和人选延期到彩排前确认。

## 6. 已知约束

- NFC 和二维码必须落到同一个稳定入口，且手机端状态一致。
- 现场大屏只能接收聚合数据、公开星号/星色、规则通过且仍公开的弹幕，以及后台人工选中的时光胶囊；不得读取完整姓名、完整学号、令牌或未选中的胶囊正文。
- 三个全场场景的关键切换由后台触发；参与者入场状态独立推进。Demo v0 保证无动效时的静态信息降级，正式可播放兜底素材后续确认。
- 后台采用共用账号，任何登录会话可自行提权；该方案不能提供真实个人归因，是项目负责人明确接受的风险。未登录访问仍必须拒绝。
- Demo v0 使用本地局域网和合成数据；离线时阻止业务写入，重连后拉取服务端快照，不在客户端排队补写。
- 实体明信片、NFC、采购、样品测试、写入和到货验收均为正式版延期事项，不阻塞 Demo v0。
- “时光胶囊”目前是叙事表达，不等于获准保存数据四年。
